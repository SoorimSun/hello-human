# 콘텐츠 발행 지침

뉴스레터와 분야별 글을 작성하고, 목록과 홈에 반영할 때 따르는 지침입니다. 코드로 표시한 저장소 경로는 프로젝트 루트 기준입니다.

먼저 [README의 공개 자료 기준](../README.md#콘텐츠-올리기-전에-꼭-읽어주세요)을 확인하고, 페이지를 추가할 때는 [공통 화면과 갱신 표시](site-operations.md)도 함께 적용하세요. 새 글 목록은 각 콘텐츠의 목록 페이지에서 관리하며, README나 파일 구성 문서에 개별 글을 계속 추가하지 않습니다.

외부 도메인으로 연결하는 링크에는 `target="_blank" rel="noopener noreferrer"`를 지정해 새 탭으로 엽니다. 사이트 내부의 글·목록·목차 링크는 현재 탭에서 이동합니다.

## 뉴스레터 발행하기

사이트의 `newsletters/`에 정적 HTML로 발행합니다. **매주 화요일 발행**하며 1호 메일 발송 예정일은 2026년 10월 6일입니다. 이메일 발송이나 자동 발행 기능은 포함하지 않습니다.

뉴스레터 메뉴는 홈의 데스크톱·모바일 메뉴와 각 콘텐츠 메뉴의 맨 마지막에 배치했으며, **메뉴와 홈의 소개 영역을 노출하도록 설정했습니다.** 홈의 데스크톱 메뉴는 소개 영역으로, 모바일·각 콘텐츠 메뉴는 뉴스레터 목록으로 연결됩니다. 홈의 최신 호 카드에서는 1호로 이동할 수 있습니다. 1호 파일명은 발행일에 맞춰 `2026-10-06-first-letter.html`로 정했습니다.

**공개 설정:** `assets/style.css`의 뉴스레터 숨김 규칙을 제거했고, 이를 불러오는 HTML 페이지와 공통 레이아웃의 캐시 버전을 `?v=9`로 갱신했습니다. 날짜 조건 없이 노출하며, 배포 시 CSS와 참조 페이지를 함께 반영합니다. 사내메일용 본문은 발송 전에 그때의 현행화된 웹 원고를 바탕으로 별도 준비합니다.

- **1호**의 발행일은 2026년 10월 6일이며 발행 전날인 10월 5일까지의 전체 글을 수록합니다. 현재 작성본에는 10월 5일 새 글 4편을 반영한 전체 기사 27편(일반뉴스 7, 단신 5, 가이드 7, 사례연구 4, 인사이트 4)과 홈에 등록된 회원 작업물 소개 2편을 담았습니다. 발행 직전에 10월 5일까지 추가된 글이 있는지 목록을 다시 대조하고, 새 글이 있으면 수록 목록과 편수를 함께 갱신합니다. 앞서 소개한 정보유출 기사, 코딩 에이전트 실습에서 AI-native SDLC로 이어지는 추천 가이드와 추천 3편은 전체 편수에 포함되며 별도 편수로 세지 않습니다. 작업물 페이지 안의 개별 프로젝트·실험 결과도 해당 소개 페이지를 통해 찾을 수 있습니다.
- **2호부터 매주 화요일**에 발행 직전 월요일까지의 일주일간 글을 소개합니다. 수록 범위는 한국시간 지난주 화요일 00:00 이상, 발행일 화요일 00:00 미만에 처음 발행한 글입니다. 2호는 2026-10-13 발행 예정이며 첫 주간 집계는 2026-10-06~2026-10-12입니다. 이 경계를 이어가면 호 사이에 누락이나 중복이 생기지 않습니다. 발행 시각은 정하지 않았고 자동 예약도 설정하지 않았습니다. 최초 발행일이 없는 작업물은 새 등록 여부와 등록일을 확인하고, 확인되지 않은 날짜를 추정해 넣지 않습니다.
- 기존 글의 수정은 신규 글 수에 넣지 않습니다. 독자가 다시 읽을 만한 큰 수정은 원래 URL과 수정일을 붙여 ‘업데이트한 글’로 별도 소개합니다. 신규 발행이 없으면 ‘이번 주 새 글 없음’으로 표시하고, 지난 글을 새 글처럼 재수록하지 않습니다.
- 날짜는 파일 수정 시간이 아닌 글의 최초 발행일로 판단합니다. `news/`, `guides/`, `insights/`, `case-studies/`의 목록과 홈의 회원 작업물 영역을 모두 확인합니다. 아직 목록에 올라오지 않은 초안·조사 메모·실습용 자산·뉴스레터 자체는 기사 집계에서 제외합니다.

1. 1호를 참고해 `newsletters/YYYY-MM-DD-주제.html`을 만들고 호수·발행일·수록 기간을 바꿉니다. 도입 인사, 먼저 읽을 글 2~3편, 분야별 전체 목록, 해볼 작은 실험의 흐름을 유지하되 추천을 위해 없는 글을 채우지 않습니다.
2. 각 글은 쉬운 제목, 무엇을 다루는지와 왜 읽으면 좋은지 1~2문장, 발행일, 원문 링크로 소개합니다. 추천 글도 전체 목록에 포함하며, 총 편수는 고유 URL로 셉니다. 모든 글은 자바스크립트 없이도 보여야 합니다.
3. 기간에 해당하는 원문 URL 집합과 뉴스레터 전체 목록의 URL 집합을 대조해 누락·중복을 확인합니다. 원문의 주장·의혹·발표·예정 상태를 유지하고 오래된 뉴스를 최신 발표처럼 쓰지 않습니다.
4. `newsletters/index.html`에 최신 호를 맨 위에 추가하고 호수를 갱신합니다. 홈 `#newsletter`의 최신 호 카드도 같은 제목·날짜·편수로 맞춥니다. 기존 호의 수록 목록과 URL은 새 글 발행 때문에 바꾸지 않습니다.
5. `noindex`, 테마·분석·콘텐츠 갱신 스크립트를 유지합니다. 로컬 링크, 전체 편수, 작은 화면과 라이트·다크 모드를 확인하고 `node --test`, `git diff --check`를 실행합니다.

## AI뉴스 발행하기

AI뉴스는 발행 주기를 정하지 않고, 새 소식이 있을 때 정적 HTML 페이지를 추가합니다.

1. `news/2026-09-25-ai-agents.html`을 복사해 `news/YYYY-MM-DD-주제.html`을 만듭니다. 제목·설명·날짜·호수와 기사 내용을 바꾸고, `<meta name="robots" content="noindex, nofollow, noarchive">`를 유지합니다. 목차 링크와 본문 절의 `id`를 맞추고 `article-toc.js`를 유지합니다.
2. 공식 발표와 원문 링크를 기사 안에 넣고, 발표 사실·기업 자체 평가·우리의 해석을 구분합니다. 출시 예정이나 진행 중인 사건은 확인 날짜를 적습니다.
3. `news/index.html`의 단일 목록 `#news-feed .news-issues`에 새 글을 한 번 추가하고, `data-news-kind`를 일반뉴스는 `regular-news`, 속보·단신은 `briefs`로 지정합니다. 날짜 내림차순, 같은 날짜는 속보·단신 먼저로 정렬하고 유형별 편수와 전체 편수를 갱신합니다. 일반뉴스는 `ISSUE`, 속보·단신은 `BRIEF` 번호를 각각 이어갑니다. 홈페이지 `index.html`의 `#ai-news`에서는 새 글이 해당 유형의 최신 글일 때 그 유형의 카드만 갱신합니다.
4. 로컬에서 목록·기사·홈 링크와 모바일 화면을 확인한 뒤 배포합니다. `assets/style.css`, `assets/news.css`, `assets/news-sections.css`를 바꾸면 이를 불러오는 페이지의 `?v=` 값도 올립니다.

## AI 사례연구 발행하기

AI 사례연구는 공개된 AI 결과물과 구현 과정을 살펴보고, 확인 범위와 우리 실험에 가져갈 교훈을 비정기적으로 발행합니다.

1. `case-studies/2026-09-27-tidewater.html`을 참고해 `case-studies/YYYY-MM-DD-주제.html`을 만듭니다. 제목·부제·날짜·사례 번호를 바꾸고 `noindex` 메타 태그를 유지합니다. 목차 링크와 본문 절의 `id`를 맞추고 `article-toc.js`를 유지합니다.
2. 직접 체험한 내용, 공개 코드·문서에서 확인한 사실, 제작자 주장과 우리의 해석을 구분합니다. 성능을 재측정하지 않았다면 제작자 기록임을 적고, 코드·변경 기록은 가능하면 확인 당시 커밋으로 연결합니다.
3. 결과물 사이트와 공개 소스 링크를 넣습니다. 본문에 실제 화면이나 영상을 배치하고 원작·출처·캡처 날짜를 표기합니다. 이미지는 `assets/case-studies/`에 저장하고 해당 폴더의 `README.md`에 출처를 남깁니다.
4. `case-studies/index.html`의 목록 맨 위에 새 글을 추가하고 편수를 갱신합니다. 홈페이지 `index.html`의 `#ai-case-studies` 카드도 최신 글로 바꿉니다.
5. 홈·목록·본문·결과물 링크와 모바일 화면을 확인한 뒤 배포합니다. `assets/case-studies.css`를 바꾸면 이를 불러오는 페이지의 `?v=` 값도 올립니다.

## AI가이드 발행하기

AI가이드는 발행 주기를 정하지 않고, 실제 업무에 적용할 만한 방법이 정리됐을 때 정적 HTML 페이지를 추가합니다.

1. `guides/2026-09-25-llm-selection.html`을 참고해 `guides/YYYY-MM-DD-주제.html`을 만듭니다. 제목·설명·날짜·가이드 번호와 내용을 바꾸고 `noindex` 메타 태그를 유지합니다. 목차 링크와 본문 절의 `id`를 맞추고 `article-toc.js`를 유지합니다.
2. 공개 저장소에 올릴 수 없는 회사명, 내부 시스템 이름·URL, 실제 로그·코드·데이터는 일반화하거나 익명화합니다. 외부 서비스의 기능 설명과 평가 수치는 공식 자료를 확인하고 링크합니다.
3. `guides/index.html`의 목록 맨 위에 새 가이드를 추가하고 개수를 갱신합니다. `index.html`의 `#ai-guides` 카드도 최신 글로 바꿉니다.
4. 로컬에서 목록·본문·홈 링크와 모바일 화면을 확인한 뒤 배포합니다. CSS를 바꾸면 이를 불러오는 페이지의 `?v=` 값도 올립니다.

## 커머스 인사이트 발행하기

커머스 인사이트는 AI를 커머스 제품에 적용할 때의 기회와 설계를 비정기적으로 살펴봅니다.

1. `insights/2026-09-25-agentic-commerce.html`을 참고해 `insights/YYYY-MM-DD-주제.html`을 만듭니다. 제목·부제·날짜·호수와 내용을 바꾸고 `noindex` 메타 태그를 유지합니다. 목차 링크와 본문 절의 `id`를 맞추고 `article-toc.js`를 유지합니다.
2. 발표된 기능과 표준의 설계안, 헬로우 휴먼의 제품 제안을 구분합니다. 기능·수치·규격은 공식 자료를 확인하고 본문 가까이에 링크합니다. 공개 저장소에 올릴 수 없는 회사명, 내부 시스템과 실제 데이터는 일반화합니다.
3. `insights/index.html`의 목록 맨 위에 새 글을 추가하고 개수를 갱신합니다. `index.html`의 `#commerce-insights` 카드도 최신 글로 바꿉니다.
4. 로컬에서 홈·목록·본문 링크와 모바일 화면을 확인한 뒤 배포합니다. CSS를 바꾸면 이를 불러오는 페이지의 `?v=` 값도 올립니다.
