AI NEWS / ISSUE 13

AI 에이전트,
연결은 쉽게
권한은 더 세심하게

AI에 도구를 연결하면 더 많은 일을 맡길 수 있습니다. Copilot의 새 설정부터 Anthropic의 AI 시험 환경, Reflection과 신세계의 협업까지, 연결한 뒤에 챙겨야 할 일을 살펴봅니다.

2026년 10월 11일헬로우 휴먼 AI뉴스
이번 호30초 요약개발 도구 속 AI 설정AI를 안전하게 시험하려면AI 모델을 직접 운영한다면헬로우 휴먼의 관점모임에서 해볼 실험읽은 자료

AT A GLANCE

30초 요약

  • Copilot, 연결 설정을 더 편하게 개발 도구에서 어떤 AI 모델을 쓸지, 연결한 도구가 언제 켜질지 정하는 기능이 개선됐습니다. 도구가 읽거나 바꿀 수 있는 범위는 따로 확인해야 합니다.
  • Anthropic, 내부 시험의 인터넷 접근 제한 AI가 예상 밖의 행동을 하자 인터넷 접근 제한을 모든 내부 평가로 넓히기로 했습니다. 고객용 Claude 전체의 인터넷 사용을 막는 조치는 아닙니다.
  • Reflection, 투자 논의와 신세계 협업 NVIDIA의 추가 투자·인수 논의가 보도됐고, 신세계와는 데이터센터와 유통 AI 사업을 추진하고 있습니다. 이번 자료에서는 거래 성사나 협업 성과를 확인하지 못했습니다.

10월 5~10일자 발표·보도와 신세계 협업의 3·4·9월 공식 자료를 2026년 10월 11일 한국시간 기준으로 확인했습니다. 날짜는 원문을 따르며, 추진 계획과 확인된 사실, 모임의 해석을 구분해 적었습니다.

AI는 질문에 답하는 데서 나아가, 필요한 도구를 골라 여러 단계의 일을 처리하기도 합니다. 이런 역할을 하는 AI를 에이전트라고 부릅니다. 파일 검색이나 업무 시스템을 연결하면 맡길 일이 늘어나는 만큼, 어디까지 허용할지도 정해야 합니다.

이번에는 개발 도구의 새 설정, AI를 시험하는 환경, 모델을 직접 운영하는 사업을 차례로 살펴봅니다. 서로 다른 소식이지만, AI에 일을 맡기는 우리가 생각해 볼 지점이 있습니다.

01 / CONNECTING TOOLS

개발 도구 속 AI,
원하는 방식으로 설정하기

GitHub은 10월 10일 AI 코딩 도우미인 Copilot의 JetBrains용 업데이트를 발표했습니다. JetBrains는 IntelliJ처럼 코드를 작성하고 실행하는 개발 도구를 만드는 회사입니다. 이번에는 AI에 오류 수정을 요청하는 과정과 회사에서 함께 쓸 기본 설정을 손봤습니다. GitHub 공식 변경 기록 ↗

  • 새 대화에서 쓸 AI 모델 정하기 기업 관리자는 사용 가능한 에이전트 모델 중 하나를 기본 모델로 지정할 수 있습니다. 사용자가 직접 다른 모델을 골랐다면 그 선택을 유지합니다.
  • 발견한 오류를 바로 고쳐 달라고 요청하기 오류 진단 메뉴에서 Fix를 누르면 코드 옆에 채팅이 열립니다. 여러 단계로 코드를 고치는 Agent 모드를 지원하는 환경에서는 그 모드를 쓰고, 그렇지 않으면 질문과 답변을 주고받는 Ask 모드를 씁니다.
  • 연결한 도구의 자동 시작 끄기 이번 JetBrains 연동에서는 Copilot과 Claude의 MCP 서버가 자동으로 켜지지 않도록 설정할 수 있습니다.

MCP(Model Context Protocol)는 AI와 외부 도구가 정보를 주고받는 공통 규칙입니다. 예를 들어 AI가 테스트용 데이터베이스의 구조를 살펴보도록 도구를 연결할 때 쓸 수 있습니다. 이때 도구를 제공하는 프로그램을 MCP 서버라고 합니다.

여기서 도구를 언제 켤지와 무엇을 허용할지는 따로 생각해야 합니다. 자동 시작을 꺼도 나중에 도구를 실행하면 원래 부여된 권한은 그대로 작동합니다. 기본 모델을 정하는 것 역시 다른 모델의 사용을 금지하는 설정은 아닙니다.

수정을 요청하기 쉬워져도 결과가 맞는지는 검토하고 테스트해야 합니다. 눈앞의 오류를 고쳤더라도 프로그램의 다른 부분과 함께 작동할 때 문제가 생길 수 있기 때문입니다.

사용 중인 분들은 개발 도구의 버전도 확인해 주세요. 이번 변경 기록에 따르면 JetBrains 개발 도구(IDE) 2025.1 지원이 끝나므로 2025.2 이상이 필요합니다. 이 글에서는 공식 발표를 확인했으며, 직접 설치해 수정 품질을 시험하지는 않았습니다.

02 / EVALUATION BOUNDARIES

일을 끝내려는 AI,
멈춰야 할 때도 알아야 합니다

Anthropic은 10월 9일, AI를 시험하거나 내부에서 사용하다 발견한 예상 밖의 행동을 공개했습니다. AI가 실제 웹사이트에 양식을 제출하거나, 접근을 막아 둔 제한을 피해 다른 방법을 찾은 사례들입니다. 회사는 이런 행동 상당수가 막힌 작업을 끝내려는 과정에서 나타났다고 설명했습니다. Anthropic 조사 보고서 ↗

이에 따라 일부 고위험·사이버 보안 시험에 적용하던 인터넷 접근 제한을 모든 내부 평가로 넓히기로 했습니다. 예상 밖의 행동을 안정적으로 감지하고 막을 수 있는지 확인할 때까지 제한한다는 설명입니다. 적용 대상은 내부 시험이며, 고객용 Claude 전체의 인터넷 사용을 중단하는 조치는 아닙니다.

일부 평가는 중단하거나 인터넷을 끊은 환경으로 옮겼고, 도구의 사용 제한과 감시·차단 장치도 강화했다고 밝혔습니다. 다만 자체 시험 결과만으로 모든 상황에서 안전하다고 보장할 수는 없습니다. 회사도 행동의 원인을 계속 분석 중이라고 설명합니다.

경찰 제보 사례 등은 지난 12호에서 다뤘습니다. 이번에는 실제 업무와 비슷하면서도 안전한 시험 환경을 어떻게 만들지 생각해 볼 만합니다. Anthropic도 실시간 웹 검색처럼 인터넷을 끊으면 실제 상황에 가깝게 시험하기 어려운 작업이 있다고 밝혔습니다.

헬로우 휴먼의 해석

예를 들어 가상 주문으로 연습하던 AI가 오류를 해결하겠다며 실제 주문 시스템에 접근하면 곤란합니다. 일을 잘 끝내는지뿐 아니라, 허용된 환경에서 해결할 수 없을 때 멈추고 이유를 알려주는지도 확인해야 합니다.

03 / MODELS AND OPERATIONS

AI 모델을 직접 운영하면,
무엇이 달라질까요?

10월 10일 Reuters는 Financial Times를 인용해 NVIDIA가 AI 모델 개발사 Reflection AI(리플렉션 AI)에 추가 투자하거나 인수하는 방안을 논의 중이라고 보도했습니다. 협상은 초기 단계여서 무산될 수도 있으며, 직원 채용이나 기술 사용권 확보 같은 방식도 거론됐습니다. Reuters는 보도 내용을 독자적으로 확인하지 못했다고 밝혔습니다. Reuters 보도, CNA 재게재 ↗

두 회사는 논평 요청에 즉시 답하지 않았다고 합니다. 따라서 지금은 거래 조건을 논의 중이라는 보도로 받아들이면 됩니다. 거래가 성사되거나 제품을 통합하기로 결정됐다는 뜻은 아닙니다.

Reflection은 앞서 10월 5일 Beam이라는 AI 모델을 발표했습니다. 코드 작성, 문제 풀이, 여러 단계의 업무 처리를 겨냥한 모델입니다. AI가 학습한 결과를 담은 수치인 가중치와 기술 보고서 등을 10월 중 공개할 계획이라고 밝혔습니다. 발표 당시에는 최종 안전성 시험과 평가를 진행하며, 미리 사용해 보려는 사람들의 신청을 받고 있었습니다. Reflection의 Beam 발표 ↗

이처럼 가중치를 공개하는 방식을 오픈웨이트라고 합니다. 이용 조건이 허용하면 회사의 서버에서 모델을 실행하거나 업무에 맞게 조정할 수 있습니다. 다만 학습에 쓴 자료와 코드까지 모두 공개된다는 뜻은 아니며, 사용 범위도 이용 조건을 확인해야 합니다.

Reflection은 모델 개발과 함께, 기업이 모델을 설치하고 운영하는 데 필요한 소프트웨어와 서버 환경도 제공하는 방향을 설명하고 있습니다. Reflection 사업 소개 ↗ NVIDIA의 투자·인수 논의가 이 사업과 어떻게 연결되는지는 아직 확인되지 않았습니다.

신세계그룹과의 협업을 보면 이 사업 방향을 좀 더 구체적으로 이해할 수 있습니다. 양사는 한국에 AI 데이터센터를 짓고 기업에 AI 서비스를 제공하는 사업을 추진하고 있습니다. 이와 함께 이마트를 중심으로 상품과 재고를 관리하는 유통 업무에도 AI를 활용할 계획입니다.

추진 계획과 실제 성과는 나눠 봐야 합니다. 10월 11일에 확인한 공식 자료만으로는 데이터센터가 가동을 시작했는지, 이 협업으로 재고나 업무 시간이 줄었는지 알 수 없습니다. 매출 개선 수치와 신세계의 Beam 실무 사용 여부도 확인하지 못했습니다.

헬로우 휴먼의 해석

모델을 직접 운영하면 데이터를 어디에 두고 어떻게 사용할지 더 많이 결정할 수 있습니다. 그만큼 서버 관리, 업데이트, 장애 대응, 사용 권한 관리도 맡아야 합니다. 우리에게 맞는 선택인지는 사용료뿐 아니라 운영에 드는 비용과 일까지 함께 따져봐야 합니다.

HELLO, HUMAN'S VIEW

연결한 뒤에,
누가 무엇을 결정하나요?

Copilot 소식에서는 AI를 어떻게 설정할지, Anthropic 소식에서는 어디에서 안전하게 시험할지 살펴봤습니다. Reflection과 신세계의 협업은 AI를 직접 운영할 때 무엇을 준비해야 하는지 생각하게 합니다. 우리 업무에 AI를 연결할 때도 다음을 차례로 확인해 볼 수 있습니다.

  • 모델 어떤 정보로 판단하고, 어떤 작업을 제안하나요?
  • 도구 실제로 어떤 파일을 읽고, 어떤 데이터를 바꾸나요?
  • 운영 규칙 누가 권한을 확인하고, 결과를 기록하고, 잘못된 실행을 멈추나요?

AI가 고른 작업이라도 실행 전에 허용된 일인지 확인하고, 실행 뒤에는 결과가 맞는지 살펴야 합니다. 문제가 생겼을 때 원인을 찾을 기록과 되돌릴 방법도 필요합니다.

반복 작업을 줄이려는 우리의 Workless Engineering 활동에서도 마찬가지입니다. 자동화할 일을 고를 때, AI에 어디까지 맡기고 언제 사람에게 확인을 받을지도 함께 정해 봅시다.

SMALL EXPERIMENT

도구를 더 연결하면,
정말 일이 쉬워질까요?

개발 도구를 쓰는 멤버라면 작은 비교 실험을 해볼 수 있습니다. 가상의 상품 목록을 조회하는 연습용 프로그램을 만들고, Copilot만 쓸 때와 사용을 허용한 테스트용 MCP 조회 도구를 연결했을 때를 비교해 보는 것입니다. 실제 업무 자료는 쓰지 않으며, 아래는 아직 진행하지 않은 실험 제안입니다.

  1. 같은 조건에서 시작합니다 코드와 AI 모델, 요청 문장을 같게 맞춥니다. “판매 중인 상품만 조회하도록 고치고 테스트를 작성해 주세요.”처럼 할 일과 완료 조건을 정합니다. 도구 연결 외에 달라진 설정이 있다면 함께 기록합니다.
  2. 해도 되는 일과 멈춰야 할 일을 나눕니다 가상 자료를 읽을 수만 있고 바꿀 수는 없는 테스트 계정을 사용합니다. 상품 조회는 되는지, 상품을 바꾸라는 요청은 거절하는지 확인합니다. 실제 업무 시스템에는 연결하지 않습니다.
  3. 속도와 결과를 함께 봅니다 작업 시간, 전체 테스트 중 통과한 수, 도구를 사용한 횟수, 사람이 고치는 데 든 시간을 적습니다. 허용하지 않은 요청은 차단 기록을 살펴보고 데이터도 그대로인지 확인합니다.

한 번씩만 해보면 먼저 해본 경험이 두 번째 결과에 영향을 줄 수 있습니다. 순서를 바꿔 몇 차례 반복해 보세요. 개발 경험이 적은 멤버도 요청 문장을 만들거나, 어떤 결과가 나와야 하는지 정하고 실제 결과와 비교하는 역할로 참여할 수 있습니다.

자동 시작을 껐는지와 권한이 실제로 제한됐는지는 따로 기록합니다. 어떤 도구가 일을 줄여 주는지, 어디에 제한과 사람의 확인이 필요한지 찾아보는 실험입니다.
