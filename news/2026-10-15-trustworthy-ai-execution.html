01 / GITHUB HYDRAFUSION

한 모델이 작성하고,
다른 모델이 검토합니다

GitHub은 여러 모델을 조합해 작업하는 HydraFusion을 개선하고, 복잡한 작업을 위한 Max 옵션을 추가했습니다. 두 옵션 모두 이용자의 피드백을 받으며 시험하는 연구 프리뷰 단계입니다.

HydraFusion은 작업에 따라 한 모델을 쓰거나, 여러 모델에 작성과 검토를 나눠 맡깁니다. 이렇게 모델의 역할과 작업 순서를 조정하는 시스템을 모델 오케스트레이터라고 합니다. 이용자는 중간 단계를 직접 연결할 필요 없이 최종 답변을 받습니다.

사용할 수 있는 모델에는 Claude Opus 5.5, GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna 등이 포함됩니다. 매번 모두를 쓰는 것은 아니며, 작업 방식과 이용 조건에 따라 선택이 달라집니다. GitHub의 업데이트 발표 ↗

이번 Critique 개선의 핵심은 검토 모델이 실제 파일과 작업 환경을 도구로 직접 살펴본다는 점입니다. 코드를 작성한 모델의 요약에 주로 기대던 검토를 보완한 것입니다. 여러 검토 모델을 동시에 쓰는 방식도 도입했습니다.

여러 파일을 함께 고치는 작업이라면, 작성 모델이 놓친 파일 사이의 관계를 다른 모델이 찾아볼 수 있습니다. Cascade에는 초안을 평가한 뒤 필요한 경우에만 수정을 요청하는 단계가 추가됐습니다.

다만 모델이 여럿이어도 같은 오류를 놓칠 수 있습니다. 모델의 검토 의견과 실제 테스트 결과를 함께 봐야 하는 이유입니다.

Max는 깊이 있는 검토에 초점을 맞춥니다

일반 HydraFusion은 속도·비용·결과 품질의 균형을 고려합니다. Max는 더 어려운 작업을 깊이 분석하고 꼼꼼하게 검토하는 데 초점을 맞췄습니다.

추가 검토에는 시간과 비용이 들 수 있습니다. HydraFusion 자체의 별도 사용료는 없지만, 실제로 사용한 모델마다 표준 요금이 붙습니다. 단순한 수정인지, 여러 파일에 영향을 주는 복잡한 변경인지에 따라 추가 검토의 가치를 따져볼 필요가 있습니다. 이용 요금 설명 ↗

어디에서 쓰고, 무엇을 주의해야 하나요?

두 옵션 모두 VS Code·GitHub Copilot 앱·명령줄 도구인 Copilot CLI에서 제공합니다. 대상 구독은 Copilot Pro·Pro+·Business·Enterprise입니다. 시험 기능을 켜야 하며, 조직에서 허용한 모델만 사용할 수 있습니다. 이번 발표에는 JetBrains 지원이 명시되지 않았습니다.

GitHub은 실제 운영 업무에 쓰도록 제공하는 기능이 아니며, 서비스 수준 보장(SLA)도 없다고 안내합니다. 또 초안을 버려도 그 과정에서 수정한 파일이 자동으로 원상복구되지는 않습니다. 작업을 마치면 답변과 함께 파일의 변경 내역도 확인해야 합니다. 연구 프리뷰의 제약 ↗

02 / GITHUB ACTIONS LOCKFILE

검토할 때와 실행할 때,
같은 코드인가요?

GitHub Actions는 코드를 실행 가능한 프로그램으로 만들고, 시험하고, 배포하는 작업을 자동화하는 도구입니다. 개발 과정에서 이런 작업을 이어서 자동 실행하는 체계를 CI/CD라고 부릅니다.

작업 순서를 적은 설정을 워크플로라고 합니다. 여기에는 다른 사람이 만든 도구인 Action을 연결할 수 있습니다. 예를 들어 v4라는 버전 이름으로 도구를 불러오더라도, 나중에는 같은 이름이 다른 코드를 가리킬 수 있습니다. 우리 설정을 고치지 않았어도 다음 실행에서 다른 코드가 쓰일 수 있는 것입니다.

GitHub이 공개 시험을 시작한 Workflow Lockfile은 사용할 코드의 버전을 별도 파일에 기록합니다. 특정 시점의 코드 상태를 기록한 커밋을 고정해, 같은 버전 이름이 다른 코드를 가리키더라도 기록해 둔 코드를 실행하게 합니다. 외부 도구를 통해 들어오는 위험을 줄이는 공급망 보안 기능입니다. 공개 프리뷰 발표 ↗

AI가 배포 설정을 작성하더라도 확인할 점은 같습니다. 작업이 성공했는지와 함께, 어떤 코드를 실행했는지도 봐야 합니다. Lockfile은 그 버전을 확인하고 관리하는 데 도움을 줍니다. 고정할 코드가 안전한지, 필요한 만큼의 권한만 줬는지는 별도로 검토해야 합니다.

개발자가 알아둘 적용 범위와 지원 조건

파일은 .github/workflows/actions.lock에 둡니다. GitHub의 명령줄 도구에 설치하는 확장 기능 gh actions-lock으로 생성·관리하고, 워크플로별로 하나씩 적용할 수 있습니다. 버전 업데이트를 제안하는 Dependabot은 이미 적용된 워크플로의 Action을 갱신할 때 Lockfile도 함께 갱신합니다.

직접 연결한 Action뿐 아니라 그 Action이 사용하는 다른 도구도 고정할 수 있습니다. 다른 저장소에 있는 워크플로를 통째로 불러올 때는 범위가 나뉩니다. 불러오는 워크플로의 버전은 우리 Lockfile에, 그 안에서 사용하는 도구들의 버전은 원래 저장소의 Lockfile에 기록합니다. 파일 하나가 모든 저장소의 실행 버전을 고정하지는 않습니다. 공식 문서의 적용 범위 ↗

공개 프리뷰 대상은 Free·Team·Enterprise Cloud입니다. 데이터를 지정한 지역에 보관하는 Enterprise Cloud의 데이터 레지던시 환경도 포함됩니다. 10월 14일 발표문의 지원 구독 정정을 반영했습니다.

03 / NVIDIA · UK RESEARCH

안전성을 반복해서 시험할
컴퓨팅 자원을 지원합니다

NVIDIA는 영국의 에이전트 안전성·보안 연구에 5년간 2억5천만 달러 상당의 컴퓨팅 자원을 지원하겠다고 발표했습니다. 컴퓨팅 자원은 대규모 AI 실험을 돌리는 데 필요한 서버 등의 계산 자원을 뜻합니다.

에이전트는 파일을 수정하거나 도구를 호출하며 작업하는 AI입니다. 예를 들어 파일을 수정하는 에이전트라면, 접근 권한이 없는 파일을 바꾸려 할 때 실제로 차단되는지 시험해야 합니다. 모델과 실행 환경을 바꿔가며 이런 시험을 반복하려면 많은 계산 자원이 필요합니다.

자원은 영국에 시설을 둔 NVIDIA의 클라우드 협력사를 통해 제공합니다. 지원 대상은 영국 연구계 전반이며, 일부는 Oxford가 이끄는 BOLD, UCL이 이끄는 SOFAIR, Imperial College London의 연구에 쓰일 계획입니다. 에이전트와 공개 모델의 보안, 같은 조건으로 반복할 수 있는 실험, 로봇 안전성 등을 연구합니다.

잘못된 판단이 실제 행동으로 이어지지 않게

발표에는 OpenShell과 시스템 구성안인 Sentry를 활용하는 연구도 포함됩니다. OpenShell은 에이전트가 파일과 네트워크에 접근할 수 있는 범위를 통제하는 소프트웨어입니다. NVIDIA는 에이전트가 스스로 규칙을 지키는 데만 기대지 않고, 바깥의 실행 환경에서 접근을 제한하는 방식이라고 설명합니다. OpenShell 공식 구조 설명 ↗

이번 발표는 안전성을 더 연구하기 위한 지원 계획입니다. 우리 업무에서도 AI가 잘못된 행동을 선택했을 때 실제 실행을 막을 수 있는지 확인할 필요가 있습니다. 좋은 답변을 내놓는 능력과 허용된 범위에서만 행동하는 능력은 각각 시험해야 합니다.

OUR VIEW · 헬로우 휴먼의 해석

사람이 다시 고치는 일까지
줄어들어야 합니다

네 소식은 모델의 역할 분담, 실행할 코드의 관리, 안전성 시험, 전문 연구 도구라는 서로 다른 문제를 다룹니다. 모임에서는 이를 AI에게 일을 맡기기 전에 무엇을 준비해야 하는가라는 질문으로 연결해볼 수 있습니다.

가령 쿠폰 계산 코드를 바꾼다고 해봅시다. 다른 모델은 업무 규칙이 빠지지 않았는지 검토하고, 자동 테스트는 할인 금액이 예상대로 나오는지 확인합니다. Lockfile은 빌드에 쓰는 외부 도구의 버전을 고정합니다. 담당자는 이런 결과와 실제 변경 내역을 보고 배포 여부를 판단합니다.

이처럼 확인할 일을 나누면 사람이 집중해야 할 부분이 더 분명해질 수 있습니다. 다만 검토 단계만 늘려서는 도움이 되지 않습니다. 검토에 드는 시간과 비용을 감안해도, 사람이 오류를 찾고 다시 고치는 부담이 줄어드는지 봐야 합니다. Workless Engineering에서 확인하려는 변화도 여기에 있습니다.

판단·금액·핵심 이유가 모두 맞은 주문을 셌습니다. E의 두 금액은 각각 쿠폰 대상일 때와 아닐 때의 결제액입니다. 구매 이력이 확인되지 않아 ‘확인 필요’와 ‘미정’ 판정은 유지했습니다.

실행 전에 정한 기준으로 비교했으며, 수정본에서 새 오류는 발견하지 못했습니다. 첫 초안을 그대로 사용한 한 번의 관찰로, 같은 모델의 재검토와 비교한 실험은 아닙니다.

따라 하는 방법 · 세 번만 요청하세요

사용할 수 있는 서로 다른 모델 두 개를 고릅니다. 각 단계의 복사 버튼으로 요청문을 옮기고, 정답은 모델에게 보내지 않습니다.

  1. 작성. 첫 모델의 새 대화에 아래 요청을 보내고, 첫 답을 ‘초안’으로 저장합니다.

    정책·주문·작성 요청

    [가상 쇼핑몰의 첫 구매 쿠폰 정책]
    모든 주문은 행사 기간 안에 앱에서 진행합니다. 아래 규칙만 사용하세요.

    R1. 과거 구매 이력이 없는 회원이 대상입니다. 과거 주문이 전부 ‘결제취소’ 또는 ‘전체 반품 완료’라면 구매 이력이 없는 것으로 봅니다. ‘부분 반품’ 주문은 구매 이력에 남습니다.
    R2. 최소 구매 금액은 ‘일반 상품 합계 - 일반 상품에 붙은 즉시할인’으로 계산합니다. 행사 상품과 배송비는 이 기준에 포함하지 않습니다. 적립금을 쓰더라도 최소 구매 금액의 기준은 줄어들지 않습니다.
    R3. 회원 조건을 충족하고 기준 금액이 5만 원 이상이면 해당 일반 상품 금액의 20%를 할인하며, 이번 쿠폰의 할인액은 최대 1만 원입니다. 행사 상품은 이번 쿠폰으로 할인하지 않습니다.
    R4. 다른 쿠폰과 이번 쿠폰을 함께 쓸 수 없습니다. 이미 선택된 다른 쿠폰은 유지하고, 임의로 빼거나 바꾸지 마세요. 상품 즉시할인은 다른 쿠폰이 아니며 함께 적용됩니다. 적립금은 쿠폰 할인 후 결제액에서 차감합니다.
    R5. 제공된 정보로 판정을 확정할 수 없을 때만 ‘확인 필요’로 표시합니다. 확인되지 않은 정보를 임의로 가정하지 마세요.

    [공통 금액 조건]
    아래 일반 상품 금액은 즉시할인 전 금액입니다. 행사 상품 금액에는 추가 상품 할인이 없습니다. 배송비는 주문마다 3,000원이며 무료배송은 없습니다. 적힌 것 외의 상품·할인·적립금은 없습니다. 최종 결제액에는 일반 상품과 행사 상품, 배송비를 모두 포함하고, 적용 가능한 할인과 사용할 적립금을 차감합니다.

    [판단할 주문 8건]
    A: 과거 주문은 결제취소 1건뿐. 일반 54,000원 / 행사 10,000원 / 즉시할인 5,000원 / 다른 쿠폰 없음 / 적립금 0원.
    B: 과거 주문은 전체 반품 완료 1건뿐. 일반 60,000원 / 행사 0원 / 즉시할인 0원 / 다른 쿠폰 없음 / 적립금 15,000원.
    C: 과거 주문은 부분 반품 1건. 일반 80,000원 / 행사 0원 / 즉시할인 0원 / 다른 쿠폰 없음 / 적립금 0원.
    D: 과거 주문 없음. 일반 40,000원 / 행사 30,000원 / 즉시할인 0원 / 다른 쿠폰 없음 / 적립금 0원.
    E: 과거 구매 이력 미확인. 일반 70,000원 / 행사 0원 / 즉시할인 0원 / 다른 쿠폰 없음 / 적립금 5,000원.
    F: 과거 구매 이력 미확인. 일반 55,000원 / 행사 0원 / 즉시할인 6,000원 / 다른 쿠폰 없음 / 적립금 0원.
    G: 과거 주문 없음. 일반 75,000원 / 행사 0원 / 즉시할인 0원 / 다른 쿠폰 5,000원 할인 선택됨 / 적립금 0원.
    H: 과거 주문은 결제취소 1건과 전체 반품 완료 1건뿐. 일반 55,000원 / 행사 15,000원 / 즉시할인 5,000원 / 다른 쿠폰 없음 / 적립금 10,000원.

    [작성 요청]
    각 주문을 판단해 ‘주문 / 이번 쿠폰 적용: 가능·불가·확인 필요 / 최소 구매 판단용 금액 / 이번 쿠폰 할인액 / 최종 결제액 / 핵심 이유와 규칙 번호’ 표로 작성해주세요. 확정할 수 없는 금액은 ‘미정’으로 적으세요. ‘확인 필요’인 주문에는 꼭 확인해야 할 정보도 적어주세요. 계산은 원 단위로 표시하고, 정책에 없는 조건은 추가하지 마세요.

  2. 검토. 다른 모델의 새 대화에 1단계의 전체 요청과 초안을 붙여 넣습니다. 아래 검토 요청도 덧붙여 한 번에 보냅니다.

    검토 요청

    정책과 주문 자료를 근거로 다른 모델의 표를 검토해주세요. 각 주문의 쿠폰 적용 판단, 판단용 금액, 이번 쿠폰 할인액, 최종 결제액, 핵심 이유가 서로 맞는지 독립적으로 확인해주세요.
    문제가 있다면 ‘주문 / 원래 답의 해당 내용 / 적용해야 할 규칙 / 올바른 판단과 금액 / 수정 이유’로 정리해주세요. 정보 부족과 적용 불가를 구분하고, 근거 없는 가정을 하지 마세요. 틀린 부분이 없으면 없다고 말해주세요. 말투 변경은 오류 수정에 포함하지 말고, 아직 전체 표를 다시 작성하지는 마세요.

  3. 수정. 초안을 만든 대화로 돌아가 검토 응답 전체와 아래 수정 요청을 함께 보냅니다. 받은 답은 ‘수정본’으로 저장합니다.

    수정 요청

    이 검토 의견을 원래 정책과 주문 자료에 대조해주세요. 근거가 있는 의견만 반영해 처음 요청한 열 구성으로 주문 8건의 최종 표를 작성해주세요. 이미 정확한 값은 유지하고 새로운 조건을 가정하지 마세요. 표 아래에 실제로 바꾼 주문과 변경 전후 값·이유를 적고, 반영하지 않은 검토 의견이 있다면 이유도 적어주세요. 수정할 부분이 없으면 기존 표를 유지해도 됩니다.

마지막으로 초안과 수정본을 아래 정답에 대조해, 맞은 주문 수와 실제로 바뀐 내용을 비교합니다.

주문별 정답과 비교 기준 보기

적용 판단·판단용 금액·이번 쿠폰 할인액·최종 결제액·핵심 이유가 모두 맞으면 주문당 1점, 총 8점입니다. 초안과 수정본에 같은 기준을 적용합니다. 금액이 맞아도 설명의 계산 단계가 틀렸다면 그 주문은 보완이 필요합니다. 말투만 바꾼 것은 점수에 반영하지 않습니다.

A · 불가
판단용 49,000원 / 이번 쿠폰 0원 / 결제 62,000원.
취소된 주문은 구매 이력에서 제외되지만, 즉시할인 후 금액이 5만 원 미만입니다. 행사 상품 10,000원과 배송비는 결제액에 포함합니다.
B · 가능
판단용 60,000원 / 이번 쿠폰 10,000원 / 결제 38,000원.
전체 반품 완료 주문은 이력에서 제외합니다. 적립금은 최소 구매 기준을 줄이지 않습니다. 60,000 + 3,000 − 10,000 − 15,000원입니다.
C · 불가
판단용 80,000원 / 이번 쿠폰 0원 / 결제 83,000원.
부분 반품 주문은 구매 이력에 남아 첫 구매 조건을 충족하지 못합니다.
D · 불가
판단용 40,000원 / 이번 쿠폰 0원 / 결제 73,000원.
행사 상품 30,000원은 최소 구매 기준에는 포함하지 않지만 실제 결제액에는 포함합니다.
E · 확인 필요
판단용 70,000원 / 이번 쿠폰·결제액 미정.
과거 주문 이력과 취소·반품 상태를 확인해야 합니다. 자격을 충족하면 쿠폰 10,000원·결제 58,000원, 아니면 쿠폰 0원·결제 68,000원입니다. 두 결제액 모두 적립금 5,000원을 뺀 뒤의 금액입니다.
F · 불가
판단용 49,000원 / 이번 쿠폰 0원 / 결제 52,000원.
구매 이력을 모르더라도 최소 구매 금액을 충족하지 못하므로 적용 불가로 확정할 수 있습니다. ‘확인 필요’로 미루지 않습니다.
G · 불가
판단용 75,000원 / 이번 쿠폰 0원 / 결제 73,000원.
이미 선택된 다른 쿠폰을 유지합니다. 이번 쿠폰은 중복으로 쓸 수 없고, 다른 쿠폰 5,000원은 결제액에서 차감합니다.
H · 가능
판단용 50,000원 / 이번 쿠폰 10,000원 / 결제 48,000원.
취소·전체 반품 주문은 모두 이력에서 제외합니다. 즉시할인 후 정확히 5만 원으로 조건을 충족합니다. 결제액은 50,000 + 15,000 + 3,000 − 10,000 − 10,000원입니다.
