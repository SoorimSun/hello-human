EXHIBIT 01

Workless Engineering

Workless Engineering의 목표는 단순한 자동화가 아닙니다.

사람이 수행하던 업무를 분석하고,

  1. 01Human Driven
  2. 02AI Assisted
  3. 03AI Delegated
  4. 04Human on Exception

방향으로 시스템을 재설계해보는 것입니다.

AI에게 모든 판단을 넘기자는 것도 아닙니다.

  • RuleRule로 해결할 일은 Rule로,
  • SoftwareSoftware로 해결할 일은 Software로,
  • AIAI가 필요한 곳에는 AI를 사용하고,
  • Human사람이 꼭 필요한 지점만 남기는 것이 목표입니다.

EXHIBIT 02

이런 것들을 실험합니다

업무를 Workflow로 바꾸기

사람이 하던 일을 다음과 같이 분해해봅니다.

  1. Trigger
  2. Context
  3. Decision
  4. Action
  5. Validation
  6. Exception

그리고 각 단계에서 질문합니다.

  • 자동화할 수 있는가?
  • 기존 코드나 API로 해결할 수 있는가?
  • LLM의 판단이 필요한가?
  • Agent가 Tool을 호출하게 할 수 있는가?
  • 사람이 승인해야 하는 지점은 어디인가?
  • 실패하면 어떻게 복구할 것인가?
HUMAN INSTRUCTION BOARD

AI Native Engineering Workflow

우리가 실제로 하고 있는 일도 실험 대상입니다. 예를 들면,

  • 요구사항 분석
  • 영향도 분석
  • Legacy Code 탐색
  • API / DB 구조 분석
  • 테스트 생성 및 실행
  • 장애 로그 분석
  • 코드 리뷰
  • 반복적인 데이터 추출
  • 기술 문서 작성
  • Release Note 작성

다음과 같은 Workflow도 만들어볼 수 있습니다.

중요한 것은 특정 AI 제품이나 프레임워크를 배우는 것이 아닙니다.

어떤 업무 구조가 AI와 Software에 위임될 수 있는지를 직접 설계하고 검증하는 것입니다.

EXHIBIT 03

운영 방식

매주 모여 공부하는 스터디보다는 2주에 한 번, 실제 실험을 중심으로 운영하려고 합니다.

한 번의 사이클은 대략 다음과 같습니다.

TIME CARDSTEP 1

모임

  • 없애고 싶은 업무 공유
  • Workflow 분석
  • Architecture / 구현 아이디어 논의
  • 이전 실험 결과 Demo
TIME CARDSTEP 2

다음 2주

  • 작은 PoC 구현
  • AI / Coding Agent / Workflow 적용
  • 실패 사례 기록
  • 실제 업무 적용 가능성 확인

↻ 그리고 다음 모임에서 결과를 공유합니다.

완성된 제품을 만들어야 하는 것은 아닙니다.

작게 만들고, 실행해보고, 실패해보는 것을 중요하게 생각합니다.
