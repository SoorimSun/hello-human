- SSM 상태 저장 도식은 같은 16토큰 구간의 쓰기 주기를 비교하는 설명용이다. L=16, 저장된 체크포인트와 빈 입력 버퍼에서 시작해 기존 전체 상태 쓰기 16회와 ReplaySSM 체크포인트 갱신 1회를 나란히 표시했다. 매 단계의 읽기·출력 계산·입력 기록은 계속된다고 명시했다. 속도나 전체 메모리 입출력의 16배 차이로 해석하지 않는다.
- 도식의 후속 문구 수정에서는 내부 상태를 ‘계산용 기록’, 입력 버퍼 기록을 ‘작은 메모’로 풀어 썼다. 한 칸이 답변 조각(토큰) 하나를 만드는 단계라고 먼저 설명하고, 범례를 비교 행 앞으로 옮겼다. 작은 메모를 남기는 칸에는 점을 표시해 작업 중단으로 보이지 않도록 했다. 체크포인트·버퍼·L=16·시작 조건은 펼쳐보기에서 설명하며, 매 단계의 읽기·계산·입력 기록과 저장 횟수·실제 속도의 구분은 유지한다.
- 다른 시각화도 같은 기준으로 문구를 다듬었다. 외부 평가 그래프에는 점수 단위를 붙이고, 지표 버전과 모델별 영문 설정명은 바로 아래 펼쳐보기로 옮겼다. Maia는 ‘같은 전력으로 처리하는 토큰 수’와 ‘장비 한 묶음(랙)이 처리하는 토큰 수’로 기준을 풀어 썼다. ReplaySSM의 속도 비교는 ‘내부 계산 일부’와 ‘답변을 이어 만드는 과정 전체’로 나누고, 배치 256은 동시에 만드는 답변 수로 설명했다. 원래의 커널·디코딩 용어와 모델·장비·FP32·L=16 조건은 펼쳐보기에 보존했다. 요약·목차에도 같은 쉬운 표현을 쓰고, 모임 실험은 ‘검수’를 ‘확인’으로 바꾸며 막대의 빗금 의미를 설명했다. 수치와 근거를 새로 조사한 것이 아니라 기존 내용의 표현을 다듬은 수정이다.
- 본문과 도식을 이어 읽으며 중복 문구와 문단 순서를 정리했다. 도입부의 세 소식 재요약을 줄이고, Artificial Analysis 그래프와 Meta의 SWE-Marathon이 별도 평가임을 명시했다. Maia의 설계 설명은 수치 도식 앞으로 옮기고, 도식 뒤에는 처리량과 요청 대기 시간의 차이가 이어지도록 했다. ReplaySSM은 저장 원리에서 속도 측정으로 연결하고, 일반 디코딩과 추측 디코딩의 실험 조건을 구분했다. 업무 전체 시간에 대한 설명은 본문에 모았으며, 배치 1을 ‘혼자 쓰는 AI’와 바로 연결하지 않고 동시 생성 수의 차이로 설명했다. 모임 관점에서 이전 결과 재사용 실험으로 넘어가는 문장을 보완했다. 기존 수치·조건·출처·발행일은 유지한 문장 편집이다.
- ReplaySSM 성능 수치 앞에 배치 256·4개 모델·H100/B300 조건을 표시하고, 배치 1에서 속도 개선이 없었다는 결과를 별도 강조했다. 수치 범위는 모델별 결과의 최솟값~최댓값이다.
