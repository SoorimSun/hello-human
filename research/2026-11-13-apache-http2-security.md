# Apache HTTP Server 2.4.71 단신 확인 기록

- 확인일·발행일: 2026-11-13, 한국시간.
- 대상: `news/2026-11-13-apache-http2-security.html`, BRIEF 15.
- 사용자 제공 원고를 공식 공지와 대조해 로컬 사이트에 반영. 푸시 금지 요청을 따른다.

## 편집 범위와 한계

- 초안의 제목과 핵심 구성, httpd와 Tomcat 구분, 운영 점검 세 가지를 유지했다.
- [KISA 한국어 공지](https://krcert.or.kr/kr/bbs/view.do?bbsId=B0000133&categoryCode=&menuNo=205020&nttId=72304&pageIndex=1&searchCnd=&searchWrd=)는 처음 직접 열기에서 접근 오류가 났으나 검색 결과를 통해 다시 열어 2026-11-12자 본문을 확인했다. 제품명, CVE 3건, 영향 범위와 해결 버전이 Apache와 일치한다. 한국어 확인 자료로 기사에 연결했다. 이 공지에 백포트 설명이 있는 것은 아니므로 해당 설명에는 Red Hat 정책 원문을 별도로 연결했다.
- 취약점·공격·패치 효과를 직접 재현하지 않았고 실제 운영 서버를 점검하지 않았다. 운영 관점은 ‘헬로우 휴먼의 시선’으로 구분했다.
- 원문에 없는 공격 확산·피해 사례나 AI의 구체적인 발견 과정을 덧붙이지 않았다.
- 이미지로 입증할 별도 제품 동작이 없는 보안 단신이므로 취약점 비교표를 사용했다. 작은 화면에서 표 내부만 가로 스크롤하며 본문을 밀어내지 않도록 구성했다.
- 기존 단신 한 열 레이아웃과 공통 테마·갱신 표시를 재사용했다. 목록은 총 61편(일반뉴스 46, 단신 15), 같은 날 일반뉴스보다 앞에 배치하고 홈 최신 단신을 교체했다.

## 검증

- `node --test`: 기존 테스트 71개 통과, 실패 0. 이후 변경은 제목 구절 묶음·CSS와 출처 링크에 한정하며 브라우저에서 최종본을 다시 확인했다.
- `git diff --check`: 오류 없음. 새 파일 3개도 별도 후행 공백 검사를 통과했다.
- 홈·목록·본문의 참조 173개를 검사했다. 로컬 대상과 해시 대상 존재, 중복 ID 없음, noindex, 외부 링크의 새 탭·보안 속성을 확인했다.
- 뉴스 목록 61개 고유 URL, 일반뉴스 46·단신 15, 날짜 내림차순과 같은 날짜의 단신 우선 배치를 확인했다. 본문·홈·목록의 날짜와 단신 번호를 맞췄다.
- 로컬 브라우저에서 큰 화면과 작은 화면, 라이트·다크 모드를 확인했다. 작은 화면의 제목은 구절 단위로 줄바꿈하고 문서 전체에 가로 넘침이 없었다. 비교표의 독립 가로 스크롤과 키보드 오른쪽 이동을 확인했다.
- 기사 → 목록 이동, 단신 필터 선택 시 15편 노출, 읽은 뒤 목록 새로고침에서 불필요한 New·Updated가 붙지 않는 것, 홈 최신 단신 → 본문 이동을 확인했다. 최종 기사 탭의 오류·경고 로그는 없었다.
- 확인은 localhost 정적 서버에서 수행했다. 커밋·푸시·배포는 수행하지 않았다.

## 2026-11-13 재검토

- 사용자 요청에 따라 사실과 문장을 다시 검토했다. Apache·Red Hat CVE·Red Hat 보안 회보·백포트 정책·KISA 본문을 다시 열었다. 공개일, 세 CVE의 번호·등급·영향 버전, HTTP/2 활성 조건, 발견자와 보고일은 기존 기사와 일치했다.
- RHEL 8 이하 비영향 안내는 Red Hat이 제공한 패키지 기준임을 명확히 했다. 운영체제 이름만으로 별도 설치한 모듈까지 안전하다고 오해하지 않도록 범위를 좁혔다. RHEL 9·10은 Important여도 영향을 받으므로 수정 패키지를 적용해야 한다는 설명을 덧붙였다.
- Apache 원문에 있는 별도 GitHub `mod_h2` 영향 범위 2.0.8~2.0.42를 보완했다. [mod_h2 릴리스 목록](https://github.com/icing/mod_h2/releases)도 확인했으며, 저장소가 아카이브돼 있고 최신 표시는 영향 범위에 포함되는 2.0.42였다. 확인하지 않은 수정 릴리스 번호를 추정하거나 ‘GitHub 최신 버전이면 해결’이라고 안내하지 않았다.
- 패키지 설치 환경은 `httpd`뿐 아니라 따로 제공되는 HTTP/2 모듈의 수정 패키지도 확인하도록 했다. 임시 완화 후 재시작 대상은 운영체제 전체가 아니라 `httpd`임을 분명히 했다.
- ‘업스트림’과 ‘공유 자원의 동기화’는 각각 Apache 배포본, 동시 요청 처리 중 다른 작업의 메모리를 잘못 바꾸는 문제로 풀었다. 영향 버전과 활성 조건을 한 문장으로 정리하고, 설치 방식·백포트·배포판 예시는 짧은 문단으로 나눴다.
- 발견자 절 제목을 ‘Anthropic과 Google이 보고한 취약점’으로 바꿨다. 확인하지 않은 AI의 단독 발견 과정은 추가하지 않았다. ‘우리 서버의 조치로 이어가기’ 같은 추상적인 표현은 실제 확인할 항목으로 바꿨다.
- 기사의 제목·URL·단신 번호·발행일과 목록 요약은 여전히 본문에 맞아 유지했다. 이번 재검토의 수정 대상은 기사와 이 확인 기록이다.
- 재검토 후 `node --test --test-reporter=dot` 통과, `git diff --check` 오류 없음. 홈·목록·본문의 참조 175개, 중복 ID, noindex, 외부 링크 속성, 새 문구와 버전 범위를 정적으로 확인했다.
- 최종 기사 본문을 로컬 브라우저에서 다시 읽고 큰 화면·작은 화면의 문단과 줄바꿈을 확인했다. 문서 전체의 가로 넘침이 없고 브라우저 오류·경고 로그도 없었다. 실제 서버 취약점 재현이나 패치 적용 검증은 수행하지 않았다. 커밋·푸시·배포도 수행하지 않았다.

## 공식 로고 썸네일 추가

- 사용자 제안에 따라 Apache 공식 로고 자료실의 HTTP Server 프로젝트 PNG를 내려받았다. 원본은 보존하고 흰 배경과 여백을 둔 1200 × 630 썸네일을 HTML 렌더링으로 만들었다.
- 본문 상단·뉴스 목록·공유 메타데이터에 반영했다. 본문 로고는 프로젝트 홈페이지로 연결하고 제공처와 상표권자를 캡션에 적었다. 이전의 ‘이미지 없이 비교표 사용’ 판단은 이 사용자 요청으로 변경됐다.
- 출처·원본 규격·제작 방법은 `assets/news/apache-http2-media.md`에 기록했다. 기사 제목·사실관계·날짜·단신 번호는 유지했다.
- 검증: 원본 PNG 1200 × 458, 썸네일 JPEG 1200 × 630 및 HTML 크기 속성 일치, 본문·목록·렌더링 원본의 로컬 경로, Open Graph·Twitter 이미지 URL 일치, 기사 CSS 캐시 버전 2를 확인했다. 기존 테스트 71개와 `git diff --check`가 통과했다.
- 브라우저에서 목록 썸네일과 본문 로고 로딩, 모바일의 가로 넘침 없음, 다크 모드에서 흰 배경을 통한 대비, 공식 출처 캡션을 확인했다. 원격 공유 카드의 실제 표시·캐시는 확인하지 않았고 커밋·푸시·배포는 하지 않았다.

## 커밋·푸시 승인

- 위 작성·검토 단계 이후 사용자가 커밋과 푸시를 명시적으로 요청했다. 초기의 푸시 금지 요청은 이 승인으로 변경됐다.
- 커밋 직전 기존 테스트 71개를 다시 실행해 통과했고, 원격 `main`과 로컬 기준 커밋이 일치함을 확인했다. 기사·홈·목록·스타일·공식 로고 원본·썸네일·렌더링 HTML·출처 및 검증 기록을 함께 반영한다.
