Caddie 원문은 웹 조회 도구에서 접근 오류가 나서 앱 내 브라우저로 직접 열었다. 제목·날짜·15개 항목·본문·말미의 측정 범위 고지를 확인했다. Anthropic과 GitHub는 실제 제공되는 한국어 공식 페이지를 확인해 사용했다. Git worktree 문서는 한국어 번역이 목록에 없어 영문 공식 문서를 연결했다.

## 편집 판단

- 동시 구현 두 건과 일주일 도입 일정은 시작을 위한 제안이며 필수 기준이나 측정된 최적값이 아니다.
- Caddie의 자동 병합 제안을 모든 유지보수에 적용하지 않는다. 실제 변경 영향, 필수 검사, 복구 방법에 따라 팀이 결정하도록 했다.
- 쿠폰 자격은 서버가 판정한다. 화면의 사유 표시 기능과 기존 적용 버튼·적용 요청·할인 계산 계약을 분리했다.
- 초안의 ‘버튼 비활성화’ 요구가 새 자격 규칙처럼 읽히지 않도록 기존 서버 판정에 따른 동작이라는 가정을 명시했다. 조회 실패 시 기존 적용 정책이 불분명하면 확인하도록 했다.
- 조회 실패를 사용 불가와 구분하고, 현재 요청 실패 후 과거 성공 응답이 도착하는 사례를 표와 순서 도식에 반영했다.
- 모의 응답 검증, 실제 시험 API 연동, 코드 검토와 실행 확인을 구분했다. 예시를 실제 서비스 실행 기록으로 표현하지 않았다.
- worktree 명령은 독자가 사용할 예시이며 실행하지 않았다. 미커밋 변경이 복제되지 않는 점, 같은 기준 커밋, 외부 실행 자원 격리 한계를 덧붙였다.
- 기존 공통 CSS·JS를 재사용하고 새로운 의존성을 추가하지 않았다. 목차, 표의 키보드 스크롤, 텍스트 요청문과 네 개의 시각 자료로 구성했다. 전용 CSS는 바로가기 제목의 상단 여백, 요청문 줄바꿈, 표의 열 너비와 시각 자료의 반응형 배치를 보완한다.
- 홈 최신 가이드와 가이드 목록을 함께 갱신했다. 기존 뉴스레터의 수록 목록은 변경하지 않았다.

## 검증

- `node --test`: 기존 테스트 71개 통과, 실패 0. 새 업무 로직은 추가하지 않았다.
- `git diff --check`: 통과. 새 HTML·CSS·조사 기록의 공백과 금지 문자도 별도로 검사했다.
- HTML 파서로 본문·목록·홈의 태그 닫힘, 중복 ID, 내부 파일과 앵커, 외부 링크의 새 탭·rel 속성, noindex와 공통 스크립트 참조를 확인했다.
- 목록은 고유 가이드 12개이며 새 글이 첫 번째다. 본문 H1·title·OG·목록·홈의 제목과 2026-11-05 날짜, GUIDE 12 번호가 일치한다.
- 앱 내 브라우저에서 320/390/768/1440px × 라이트·다크 8가지 조합으로 본문을 확인했다. 문서 가로 넘침은 없었다. 모바일 표는 영역 안에서만 가로 스크롤된다.
- 모바일 제목에서 줄바꿈을 숨길 때 두 단어가 붙는 문제를 수정했다. 요청문은 좁은 화면에서 줄을 접어 표시하되 복사되는 텍스트의 원래 개행을 유지한다.
- 요청문 바로가기 제목이 고정 메뉴에 일부 가려져 전용 CSS로 여백을 보완했다. 수정 후 제목 상단 179.94px, 메뉴 하단 84.75px로 가려지지 않는 것을 확인했다.
- 목차의 현재 절 표시, 쿠폰 표의 키보드 가로 스크롤(ArrowRight로 scrollLeft 40), 테마 전환과 새로고침 유지, 목록·홈에서 본문으로 이동을 확인했다. 모바일 목록·홈에도 문서 가로 넘침이 없었다.
- 데스크톱 첫 화면, 모바일 다크 모드, 모바일 요청문과 목록 화면을 직접 확인했다. 마지막 본문 방문에서 브라우저 콘솔 오류 0건.
- 일반 실행 환경의 로컬 HTTP 접근은 권한 오류가 발생했다. 승인된 로컬 전용 서버를 사용해 브라우저 검증을 완료했으며, 실패한 HTTP 검사를 성공으로 기록하지 않았다.
- 쿠폰 서비스나 문서에 실린 worktree 명령은 실행하지 않았다. 위 결과는 가이드 웹페이지와 저장소의 기존 테스트에 대한 검증이다.
- 최초 작성과 편집 검토 단계에서는 커밋·푸시·배포하지 않고 로컬 변경사항으로 남겼다.

## 문장과 중복 표현 검토 · 2026-11-05

- 전체 본문·표·요청문을 읽고 번역투, 주어와 서술어의 호응, 같은 문단 안의 반복 설명을 다듬었다.
- ‘개발자의 주의력을 쓴다’, ‘검증을 세 층으로 나눈다’, ‘비어 있는 이름’, ‘사람에게 돌아온다’ 등을 구체적인 행동으로 풀어 썼다.
- ‘합성 응답/모의 응답’은 ‘모의 응답’, ‘확인 실패/조회 실패’는 ‘조회 실패’로 통일했다. ‘쿠폰 자격’은 ‘쿠폰 사용 가능 여부’, 버튼의 ‘자격 조건’은 ‘활성 조건’으로 명확히 했다.
- 원문 도표의 한계, 서버 판정을 따르는 이유, AI 리뷰를 다시 검토해야 한다는 설명을 간결하게 묶었다. 독립적으로 복사해 쓰는 요청문의 필수 조건은 유지했다.
- ‘이전 요청이 도착’은 ‘이전 요청의 응답이 도착’으로, ‘재시도하면 정상 복귀’는 ‘재시도가 성공하면 결과 표시’로 고쳐 동작 조건을 분명히 했다.
- 제목·발행일·번호·출처 링크·목차 ID와 9개 절·8개 요청문 및 명령 블록을 유지했다. 새 사실이나 외부 출처는 추가하지 않았다.
- 수정 전후의 링크·자산 경로·ID·날짜 속성 일치를 확인했다. HTML 구조, 링크 39개, ID 13개, 용어 통일과 공백 검사 및 `git diff --check`를 통과했다. 기존 미리보기를 새로고침해 수정 문장과 화면 너비 내 표시를 확인했다. 이번 검토에서도 커밋·푸시·배포하지 않았다.

## 반복 실수의 재사용 지침 반영과 표 너비 · 2026-11-05

- 사용자에게 전달된 게임 기획 분야의 경험을 커머스 개발팀의 운영 제안으로 바꾸어 8절에 추가했다. ‘같은 원인의 실수가 두 번 나오면 당일 회고에서 규칙·스킬로 옮긴다’는 제안이며, 보편적 기준이나 측정된 효과로 표현하지 않았다.
- 쿠폰의 과거 응답, 결제 시간 초과 뒤 재시도, 부분 취소의 할인·배송비 배분을 가상 사례로 정리했다. 결제·환불의 실제 동작은 기존 API 계약과 확정된 정책을 따르도록 했다.
- 시작 때 자동으로 읽히는 핵심 지침에 작업별 스킬의 적용 조건과 경로를 연결하는 방법, 시작 지침 예시, 이전 대화 없는 새 세션에서 적용 여부를 확인하는 절차를 추가했다. 본문의 예시 경로는 실제 저장소에 생성한 파일이 아니다.
- https://code.claude.com/docs/ko/memory 를 다시 열어 상위 지침의 시작 시 로드, 하위 지침의 파일 접근 시 로드, 스킬의 호출 또는 관련성에 따른 로드를 확인했다. 스킬을 저장했다고 전체 내용이 매 세션 자동 로드된다고 표현하지 않았다.
- 회귀 테스트, 담당자·확인 날짜, 정책 변경 시 갱신을 기존 스킬 양식과 연결했다. 1절 재사용 행과 9절 마지막 날의 활동도 같은 방향으로 맞췄다.
- 표 9개에 열 비율을 각각 지정했다. 쿠폰 결과 열 64%, 도입 일정의 활동 열 50% 등 설명 길이에 맞춰 배분했고, 표 종류별 최소 너비는 520~640px로 조정했다. 데스크톱 본문 폭 650px 안에 모두 들어간다. 전용 CSS 참조는 v2로 갱신했다.
- HTML 파서로 태그 닫힘, 중복 ID, 로컬 파일·앵커, 표 열 비율의 합계 100%, 행별 열 수, 키보드 접근 가능한 표 영역을 확인했다. 표 9개와 요청문·명령 블록 9개를 확인했고 공백 검사 및 `git diff --check`를 통과했다.
- 브라우저에서 320/390/768/1440px를 확인했다. 문서 가로 넘침과 셀 내부 텍스트 넘침은 0건이었다. 1440px에서는 모든 표가 가로 스크롤 없이 표시되고, 작은 화면에서는 표 영역만 스크롤된다.
- 320px 다크 모드에서 새 사례 표를 직접 확인하고 ArrowRight 입력으로 표의 scrollLeft가 40px 이동하는 것을 확인했다. 종료 전 라이트 모드와 기본 화면 크기로 복원했다. 최종 페이지 콘솔 오류는 0건이었다.
- 이번 변경은 본문과 전용 스타일에 한정된다. 실제 커머스 서비스를 실행하거나 스킬·에이전트 설정을 변경하지 않았고, 커밋·푸시·배포하지 않았다.

## 가이드 중심으로 도입부 재편집 · 2026-11-05

- 사용자의 ‘가이드이므로 원글을 과하게 강조할 필요가 없다’는 의견을 반영했다. 도입부와 OG 설명에서 원글 소개를 덜고 독자가 따라갈 작업 흐름과 양식을 안내하도록 바꿨다.
- 1절을 ‘작업을 맡기기 전에 팀의 기준을 정합니다’로 고쳤다. 원문 번호와 비교표를 작업 선정·완료 판단·진행 권한·병렬 작업·지식 재사용의 운영 기준 및 기록 항목으로 대체했다. 목차도 ‘팀의 운영 기준’으로 맞췄다.
- 최소 5개 에이전트와 원문 도표의 측정 범위를 설명하던 단락을 삭제했다. 본문에 해당 수치나 실측 주장이 남지 않았으므로 부연 설명도 제거했다. Caddie 출처는 하단 참고 자료에 한 번 남겼으며, 앞의 조사 기록은 초기 편집 과정의 이력이다.
- 1절 표의 열 비율은 22/46/32%로 조정했다. 8절의 커머스 사례와 시작 지침 예시, 나머지 표의 너비는 유지했다.
- HTML 구조·내부 링크·앵커·열 너비 합계를 확인했고 `git diff --check`를 통과했다. 9개 절·9개 표·9개 요청문 및 명령 블록을 유지했다. 미리보기를 새로고침해 새 제목과 목차, 표 열 너비 143/299/208px 및 문서 가로 넘침 없음을 확인했다. 커밋·푸시하지 않았다.

## 멤버들이 따라 하기 위한 시각 자료 · 2026-11-05

- 사용자의 이해·실행을 돕는 시각화 요청을 기존 가이드에 반영했다. 별도 서비스나 이미지 의존성 없이 본문 안의 HTML·CSS 도식으로 구성했다.
- 도입부의 간단한 순서도를 ‘맡기기 → 만들기 → 확인하기 → 남기기’ 역할 지도로 개편했다. 단계마다 사람과 에이전트의 일, 남길 결과를 함께 보여 주고 작업 지시문·쿠폰 예시·완료 보고·규칙 기록으로 연결했다.
- 3절에 막연한 쿠폰 요청과 목표·범위·완료 기준·확인 방법을 넣은 요청을 비교하는 시각 자료를 추가했다. 전체 요청문의 API 계약·검증 명령·진행 권한을 생략해도 된다는 뜻이 되지 않도록 본문 양식으로 연결했다.
- 8절에 반복한 실수를 핵심 규칙과 작업별 스킬로 나누고, 시작 지침에서 연결해 새 세션의 구현·검증에 적용하는 흐름을 추가했다. 기존 로드 조건 설명과 실제 적용 여부 확인을 유지했다.
- 시각 자료 바로가기 ID는 `workflow-map`, `request-example`, `learning-loop`다. 기존 쿠폰 지연 응답 도식을 포함해 총 4개이며, 9개 절·9개 표·9개 요청문 및 명령 블록은 유지했다. CSS 캐시 버전은 v3이다.
- 최종 HTML 구조·고유 ID 17개·로컬 링크·앵커·자산 경로와 CSS 괄호·공백을 검사했다. `git diff --check`를 통과했다. JavaScript와 기존 업무 로직은 수정하지 않았다.
- 320/390/768/1440px에서 문서와 시각 자료 영역의 가로 넘침이 없었다. 좁은 화면에서는 역할·규칙과 스킬·새 세션 단계가 세로로 배치된다. 데스크톱에서 목록 사이의 화살표는 의도적으로 항목 간 여백에 표시된다.
- 4개 단계 링크가 올바른 앵커로 이동하고 Enter 키로도 작업 지시문으로 이동하는 것을 확인했다. 모바일 링크 높이는 모두 44px였다. 데스크톱 3개 시각 자료와 320px 다크 모드 요청문·재사용 흐름을 직접 확인했다.
- 최종 콘솔 오류는 0건이었다. 기본 화면 크기·라이트 모드로 복원하고 사용자 미리보기를 역할 지도에 열어 두었다. 커밋·푸시하지 않았다.

## 게시 전 최종 확인 · 2026-11-05

- 시각화 반영 후 사용자가 푸시를 요청했다. 가이드 본문, 전용 CSS, 이 조사 기록, 가이드 목록과 홈의 5개 파일을 커밋·푸시 대상으로 확인했다.
- 최종 작업 상태에서 `node --test --test-reporter=spec`를 다시 실행했다. 테스트 71개 통과, 실패·건너뜀 0개였다. 이는 저장소의 기존 기능 테스트이며 실제 쿠폰·결제 서비스를 검증한 결과가 아니다.
- `git fetch origin` 후 로컬 `main`과 `origin/main` 사이에 선행·후행 커밋이 없음을 확인했다.
