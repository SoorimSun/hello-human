# 커머스 AI, 반복 업무의 전문가로 키우기

- 확인일·발행일: 2026-10-22 (한국시간)
- 결과물: `insights/2026-10-22-shopify-task-experts.html`, COMMERCE INSIGHT 07
- 업무 질문: 커머스 팀은 반복 작업을 어디까지 AI에 맡기고, 담당자의 수정 경험으로 품질과 전체 처리비용을 어떻게 개선할 것인가?
- 편집 방향: 공개 사례 → 성과의 범위 → 개선 경로 → 배송 문의 도우미와 비교 실험. 특정 모델 도입이나 자체 GPU 운영을 전제하지 않는다.
- 공개 범위: 개인 대화 링크·사내 정보·실제 고객 자료를 수록하지 않았다. 배송 문의와 처리 흐름은 가상이다.

## 추가 도표·관련 자료 재검토 (2026-10-22)

기술 블로그 두 편, 네 논문의 초록·학회 정보, 모델 카드, Sidekick 도움말, DSPy·Megatron Bridge·AIPerf·vLLM·TensorRT-LLM 공식 문서를 다시 열어 대조했다. 도표의 실제 파일과 캡션·대체 텍스트도 함께 읽었다.

| 확인 대상 | 판단과 반영 |
| --- | --- |
| 품질·응답 시간·비용 도표 | 37.7→61.5→74.5, 비교 기준 73, 중앙값·p99, 비용 약 90% 감소가 원본과 일치한다. 수치는 유지하며 품질 점수·응답 시간·전체 사업비의 구분을 유지했다. |
| AIPerf 재생 범위 | 10월 원문의 Optimize inference는 고객 원문 대신 합성 텍스트로 트래픽 패턴을 재현한다고 설명한다. 이를 본문에 명시하고, 모델 요청의 응답 시간과 전체 업무 완료 시간을 구분했다. |

| Gist tokens | NeurIPS 2023 논문은 압축하도록 모델을 학습한다. Shopify의 Compress the prompt 절은 모델 가중치를 고정하고 gist 토큰 임베딩을 학습한다고 설명한다. 두 방식을 구체적으로 구분했다. |
| 제품·도구 | 공개 Nemotron 가중치와 Shopify가 추가 학습한 모델을 구분했다. DSPy의 GEPA, 모델 형식 변환·학습, 부하 시험, 추론 서비스 실행의 역할을 쉬운 말로 정리했다. |

이는 자료의 주장과 편집 내용의 일치 여부를 확인한 작업이다. 공급사 성능을 독립 재현하거나 모델·도구를 설치·실행하지 않았으며, 커밋·푸시·배포하지 않았다.

재검토 후 검증: HTML 구조·목차·링크·자산·공개 범위 검사와 `git diff --check` 통과. 새 제목의 H1·문서 제목·OG·목록·홈 일치, 사례연구 제목 유지, 도표 네 파일의 해시·크기 속성 일치를 확인했다. 브라우저에서 1280px 제목·홈 연결, 390px 도표, 320px 다크 모드 논문 카드를 확인했고 가로 넘침과 콘솔 오류·경고가 없었다. 글 방문 후 목록 새로고침에서 New/Updated가 다시 붙지 않았다. 이번 문구 수정에서는 JS를 바꾸지 않아 아래의 기존 71개 테스트를 반복 실행하지 않았다.

## 확인한 1차 자료

### 1. Shopify의 업무 전문 모델

- URL: https://shopify.engineering/open-model-task-experts
- 발표일: 2026-10-21. 확인일: 2026-10-22.
- 대조 위치: 도입부, `Results on GraphQL`과 원본 그래프 설명.
- 본문 표에 사용할 값: 품질 73/74.5점, 응답 중앙값 6.50/0.87초, 추론 서비스 비용 약 90% 감소. 초기 37.7점, 교정 61,000개, 여섯 루프.
- 원본 도표에서 추가 확인: 첫 회차 61.5점, 회차별 신규 교정 사례 13k·13k·4k·9k·7k·15k. 중간 회차의 점수는 그림에서 추정하지 않았다.
- 응답 시간 도표: Nemotron 중앙값 0.87초·p99 2.51초, 추가 학습한 Qwen3.5-9B 0.97초·5.50초, 범용 API 6.50초·20.3초. 비용 비교 범위는 일주일의 운영 GraphQL 트래픽으로 표시돼 있다.
- 실패 교정 도식: 2026년 6~9월의 야간 실행 86회, 교정 대화 59,535건, 시도한 실패 중 69% 교정, 평균 점수 4.1→6(6점 만점). 학습 도표의 61,000건·74.5점과 서로 다른 집계·척도다.
- 한계: 자체 보고·특정 업무·트래픽 재생. 정확도나 총사업비로 치환하지 않는다. 비교 대상 범용 모델의 이름·오차 범위 미공개. 8월의 다른 절감률, 별도 업무의 하드웨어 성과와 합치지 않는다. 재채점에서 힌트를 숨기는 것과 힌트 없이 재실행해 성공하는 것은 구분한다.

### 2. Sidekick의 개선 과정

- URL: https://shopify.engineering/sidekicks-continual-learning-loop
- 발표일: 2026-08-05. 확인일: 2026-10-22.
- 대조 위치: `Define quality`, `Calibrate your judge`, `Improve the frontier baseline`, `From discrete artifacts to continuous parameter updates`.
- 사용할 표현: 사람의 기준으로 평가기를 보정하고 지침·도구부터 개선한다. 교정 사례의 지도 미세조정과 평가 보상을 이용한 강화학습을 설명한다.
- 한계: 이 글은 학습 과정의 근거다. 10월 Nemotron 실험의 모든 학습 설정이 같았다고 단정하지 않는다. 평가기는 대리 지표이며 실제 성과와의 정렬 검증이 필요하다.

## 편집 판단과 시각 자료

- 사례 사실, 공급사 성과, 헬로우 휴먼의 적용 제안, 가상 화면을 본문에서 구분했다.
- 사용자의 원본 이미지·도표 배치 요청에 따라 Shopify의 네 도표를 관련 해설에 인용했다. 각 그림에 제공자·원문 링크·한국어 캡션·대체 텍스트를 붙이고, 클릭하면 원본을 크게 볼 수 있게 했다.
- 공개 재배포 라이선스나 별도 이용 허락은 확인하지 못했다. 출처 표기를 자유 재사용 허락으로 해석하지 않는다. 이번 결과는 검토용 로컬 변경이며 공개 배포하지 않았다.
- 역할 도식·실패 분류 흐름·배송 문의 처리 흐름은 HTML/CSS로 작성한 설명이다. 실제 UI·실제 학습 결과처럼 표시하지 않는다.
- 성능 그래프를 새로 그리거나 값을 추정하지 않았다. Shopify 원본 그래프와 공식 보고값의 표를 함께 제시하고, 자체 제안은 흐름과 비용식으로 구분했다.
- 본문에 사내 구현체나 고객 식별자를 넣지 않는다. Java/Spring은 일반적인 기존 업무 시스템의 예시다.
- 금액·권한·상태 변경의 검증은 서버 책임으로, 의도 해석과 근거 정리는 모델 책임으로 구분했다.
- 학습/시험 간 동일 주문·유사 문의 중복 방지, 복합 의도 누락과 잘못된 확답의 별도 집계, 실패 비용을 포함한 성공 건당 비용은 우리 실험 설계다.
- 공통 CSS·JS는 변경하지 않았다. 개별 글 목록은 목록 페이지에서 관리하라는 README 지침에 따라 README에 기사 목록을 추가하지 않았다.

## 역할별 시각 구성 개편

- 6장의 가상 검토 화면과 중복 설명을 AI → 서버 → 조회 결과별 분기 → 담당자 검토 → 수정 경험 기록의 처리 흐름으로 교체했다. 조회 성공도 사실의 완전성을 보장하지 않으며, 실패·정보 부족은 확인 필요로 전달한다. 두 분기는 모두 담당자 검토에 도달한다.
- 7장의 논문 카드 네 개와 도구 표를 지침 개선·모델 학습·입력 압축·실행 및 측정의 역할 지도로 통합했다. 논문·공개 모델·개발 도구·판매자용 제품을 표시하고, 필수 도입 순서나 연동 검증 결과로 보이지 않도록 설명했다.
- 기존에 확인한 공식 출처와 핵심 제한을 유지했다. GEPA·ACE의 지침 개선과 가중치 학습, Gist 원논문과 Shopify의 적용 방식, 공개 모델과 Shopify의 추가 학습 결과물, 부하 시험과 답변 품질 평가를 구분했다.
- 2·3장의 원본 도표 네 점은 그대로 두고 캡션을 번호·짧은 소제목·설명으로 나눴다. 중앙값·p99, 회차별 추가량, 실패 교정률의 분모를 유지했다. 중복되던 교정률 설명은 본문 한 곳에 모았다.
- HTML 태그·ID·목차·상대 경로·외부 링크·메타데이터 자동 검사와 공백 검사를 다시 통과했다. 이 편집은 기사 HTML과 전용 CSS에 한정하며 기존 JavaScript 테스트는 재실행하지 않았다.
- 브라우저에서 데스크톱 1280px, 모바일 390px·320px의 변경 영역을 확인했다. 원본 이미지 네 점 정상 로딩, 페이지·도식·캡션 가로 넘침 없음, 라이트·다크 화면 표시 정상, 콘솔 경고·오류 없음.
- 로컬 검토용 변경으로 유지했으며 커밋·푸시·배포하지 않았다.
