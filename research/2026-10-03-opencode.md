# OpenCode 입문 가이드 근거 조사

- 확인일: **2026-10-03, Asia/Seoul**.
- 범위: NEON ATLAS 야간 아트 페스티벌 단일 HTML의 생성·수정 능력을 모델별로 비교하는 한국어 입문 가이드.
- 방법: OpenCode 공식 문서·공식 저장소·로컬 런타임 및 제공자 공식 문서만 근거로 사용. 설치, 로그인, 모델 호출, 성능 측정은 실행하지 않았다.
- 아래의 **확인**은 문서/소스 확인을 뜻한다. **제안**은 이 가이드의 실험 설계이며 제품 보장이나 측정 결과가 아니다.

## 1. 설치: 홈과 문서의 경로 차이

**확인:** 공식 홈은 `curl -fsSL https://opencode.ai/v2/install | bash`, 기존 Intro 설치 문서는 `curl -fsSL https://opencode.ai/install | bash`를 안내한다. 둘을 같은 스크립트의 별칭으로 설명하면 부정확하다. v2 스크립트는 OpenCode 업데이트 메타데이터와 npm의 `@opencode/cli-*` 계열을 이용하고, 기존 스크립트는 GitHub release 바이너리를 이용한다. 설치 채널과 `opencode --version`을 비교 기록에 남긴다. [홈](https://opencode.ai/) · [v2 설치 스크립트](https://opencode.ai/v2/install) · [기존 설치 스크립트](https://opencode.ai/install)

**확인:** [한국어 Intro](https://opencode.ai/docs/ko/)의 설치 안내는 다음과 같다.

| 환경 | 공식 문서의 명령/경로 |
|---|---|
| Windows 네이티브, Node.js 설치 후 | `npm install -g opencode-ai` |
| Windows 대안 | `choco install opencode` 또는 `scoop install opencode` |
| macOS | `brew install anomalyco/tap/opencode` 또는 위 npm 명령 |
| WSL 터미널 / Linux | `curl -fsSL https://opencode.ai/install \| bash` 또는 위 npm 명령 |

표의 `\|`는 Markdown 표 구분을 피하기 위한 표기다. 복사 가능한 실제 명령은 다음이다.

```sh
npm install -g opencode-ai
opencode --version
```

```sh
curl -fsSL https://opencode.ai/install | bash
```

OpenCode는 Windows에서 직접 실행할 수 있으며 공식 문서는 WSL을 권장한다. WSL을 쓴다면 설치·실행·설정은 WSL 환경에서 맞춘다. 문서는 원활한 성능을 위해 WSL 파일시스템의 프로젝트 폴더도 제안한다. [Windows/WSL 공식 문서](https://opencode.ai/docs/windows-wsl/)

**불확실성:** `/docs/install`은 이번 조회에서 정상 문서로 확인되지 않았다. HTTP 404로 단정하지 않고, 가이드에는 검증된 [Intro 설치 섹션](https://opencode.ai/docs/#install)을 연결한다. 홈 v2와 기존 문서의 채널 차이 때문에 모든 배포판의 화면이 같다고 보장하지 않는다.

## 2. 무료 첫 실행과 기본 명령

**확인:** 기존 provider 소스는 OpenCode 인증키가 없으면 입력비용이 0인 모델을 남기고 공개 키로 자동 로드한다. v2 provider 소스도 키가 없을 때 공개 키를 지정하고 유료 입력비용 모델을 비활성화한다. 따라서 **무료 내장 경로의 첫 실습에 `/connect`나 결제 등록을 필수로 넣지 않는다.** [기존 provider 소스, 203–223행](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts#L203-L223) · [v2 provider 소스, 165–177행](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/plugin/provider/opencode.ts#L165-L177)

가이드에 사용할 순서:

```text
터미널: 실습 폴더에서 opencode 실행
OpenCode 안: /models
OpenCode 제공 목록에서 현재 무료로 표시된 모델 선택
짧은 인사 또는 지정된 실습 프롬프트 입력
```

**실무상 한계:** 이는 공개 무료 접근의 구현 확인이며 특정 시간·계정·지역에서의 성공, 처리량, 무제한 사용을 검증한 것이 아니다. 인증된 유료 API 연결은 별도 선택 단계다. 무료 목록이 없거나 요청이 실패하면 버전·공식 모델 목록·오류를 확인한다. 유료 모델로 자동 대체하는 실습 지시는 넣지 않는다.

| TUI 명령 | 확인한 의미 |
|---|---|
| `/connect` | 공급자 인증 연결 |
| `/models` | 사용 가능한 모델 조회/선택 |
| `/new` (`/clear`) | 새 세션 시작 |
| `/compact` (`/summarize`) | 현재 대화 압축; 새 비교용 빈 대화가 아님 |
| `/init` | `AGENTS.md` 생성/갱신 안내 |
| `/sessions` | 기존 세션 조회/전환 |
| `/undo`, `/redo` | 메시지 및 파일 변경의 되돌리기/재적용; Git 필요 |

[한국어 TUI](https://opencode.ai/docs/ko/tui/)

**소스 확인:** `/new`는 TUI에서 홈 화면으로 이동하고 대화상자를 정리한다. 해당 핸들러에는 파일 삭제/되돌리기 동작이 없다. 따라서 생성 파일은 남으며, 이전 세션 삭제도 의미하지 않는다. 모델 비교 시 새 세션과 별개로 동일한 초기 파일을 준비해야 한다. [TUI 구현, 561–574행](https://github.com/anomalyco/opencode/blob/dev/packages/tui/src/app.tsx#L561-L574)

## 3. Plan, Build, 도구 권한

**확인:** 기본 primary agent는 Build와 Plan이며 Tab으로 전환한다. Build는 도구를 사용하는 구현용, Plan은 계획·분석용이다. 상세 Agents 문서는 Plan의 파일 수정과 bash 기본값을 `ask`로 설명한다. Intro의 간단한 “수정 비활성화” 설명만 보고 Plan을 완전한 읽기 전용 샌드박스라고 단정하지 않는다. [한국어 Agents](https://opencode.ai/docs/ko/agents/)

권한값은 `allow`, `ask`, `deny`다. `edit`는 write/patch 등 파일 변경을 포함한다. 대부분의 기본 권한은 allow이므로 “실행 전에 항상 물어본다”는 설명은 틀릴 수 있다. 입문 실습에서는 아래처럼 명시적 확인을 요청할 수 있다. [한국어 권한](https://opencode.ai/docs/ko/permissions/)

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",
    "bash": "ask",
    "external_directory": "ask"
  }
}
```

**제안:** 단일 HTML 실습에서는 첫 파일 쓰기와 브라우저 확인에 필요한 동작을 승인하되 요청 범위를 읽는다. 도구 호출 자체가 실패하면 디자인 품질과 분리해 기록한다.

## 4. Zen 무료·스텔스 모델: 기준일 스냅샷

아래 정보는 [공식 한국어 Zen 문서](https://opencode.ai/docs/ko/zen/)의 가격·기간·개인정보 항목을 확인했다. 무료가 영구적이라는 의미는 아니다.

| 가이드 예시 | 모델 ID | 공식 설명 |
|---|---|---|
| Big Pickle | `big-pickle` | 한정 무료 stealth; 수집 데이터의 모델 개선 사용 가능 |
| Space Bunny Free | `space-bunny-free` | 한정 무료 stealth; 미보관·학습 미사용 명시 |
| Fledge Alpha Free | `fledge-alpha-free` | 한정 무료; 모델 개선 사용 가능; stealth 표기는 확인하지 못함 |

동일 가격표의 기타 무료 ID: `longcat-2.5-preview-free`, `mimo-v2.6-flash-free`, `mimo-v2.5-free`, `ling-3.1-flash-free`, `ling-3.0-flash-fin-free`, `nemotron-3-ultra-free`, `nemotron-3.5-lightning-free`, `muse-spark-1.3-contributor-free`, `jev-1.13-free`.

Jev는 구조화 판단 API이므로 HTML 생성 후보로 섞지 않는다. Nemotron 무료 엔드포인트는 평가 용도·데이터 조건이 있고, Muse contributor는 학습 이용 조건이 있다. 유료 Zen은 종량제이며 자동충전 설정도 있으므로 유료 연결 단계에서 별도 확인한다.

**해석:** stealth는 정식 정체를 추정해 붙이는 근거가 아니다. 공식 문서가 공개하지 않은 회사·기반 모델·버전을 단정하지 않는다. 프라이버시 기능으로 설명하지도 않는다. 이 세 예시는 인기 순위나 성능 순위가 아니다.

**불확실성:** 제공 기간은 변경 가능하다. 지역별 세부 가용성·한도는 이 문서만으로 확인되지 않았다. 현행 목록은 [Zen 모델 목록 API](https://opencode.ai/zen/v1/models)와 사용 중인 `/models`에서 재확인하는 구조로 안내한다. 이번 조사는 모델 목록 API의 실제 응답이나 실습 요청을 실행하지 않았다.

## 5. 중국계 모델 연결: 모델과 공급자를 구분

**확인:** OpenCode 공식 공급자 문서는 DeepSeek, Moonshot AI, MiniMax, Z.AI를 지원한다. `/connect`에서 해당 공급자와 API키를 연결한 뒤 `/models`로 선택한다. Z.AI 일반 API와 **Z.AI Coding Plan**은 선택 경로를 구분한다. [한국어 공급자 문서](https://opencode.ai/docs/ko/providers/) · [영문 공급자 문서](https://opencode.ai/docs/providers/)

| 모델 계열 | 입문 가이드에서 연결할 경로 |
|---|---|
| DeepSeek | DeepSeek API 계정 → `/connect`에서 DeepSeek → `/models` |
| GLM | Z.AI API 또는 계약한 Coding Plan 경로 → `/models` |
| Kimi | Moonshot AI API → `/connect`에서 Moonshot AI → `/models` |
| MiniMax | MiniMax 공급자/API 연결 → `/models` |
| Qwen | Alibaba Cloud Model Studio의 현재 OpenCode 설정 안내 또는 로컬 공개 가중치 |

Qwen의 “무료 채팅”과 API 사용권을 같다고 안내하지 않는다. Alibaba 공식 OpenCode 문서는 종량제·Coding Plan·Token Plan별 endpoint/인증 설정을 구분하며 종량제 endpoint는 지역과 Workspace ID에 의존한다. 최신 예제에는 `qwen3.8-max`/`qwen3.8-flash` 등이 있지만, 계약별 모델 목록이 다르므로 가이드에서 하나의 모델을 모든 계정에 보장하지 않는다. [Alibaba Cloud OpenCode 공식 통합 문서](https://www.alibabacloud.com/help/en/model-studio/opencode)

**제안:** `/models`에 표시되는 전체 `provider/model-id`를 그대로 기록한다. 같은 계열 이름이라도 Zen, 원제공자 API, 제3자 호스팅, 로컬 가중치는 별도 실험으로 취급한다. 중국계 모델이라는 분류만으로 추론 서버 위치를 단정하지 않는다.

## 6. 로컬 연결과 검증 가능한 설정 예제

**확인:** OpenCode 공식 공급자 문서는 Ollama의 `http://localhost:11434/v1`, LM Studio의 `http://127.0.0.1:1234/v1`을 `@ai-sdk/openai-compatible`로 연결한다. [공급자 문서](https://opencode.ai/docs/providers/)

**스키마 대조:** `model`, `small_model`, `enabled_providers`, 사용자 정의 `provider.local`, `npm`, `options.baseURL`, 모델별 `tool_call`, `limit.context`, `limit.output`는 현행 공식 스키마에 있는 필드다. 아래는 문서·스키마에 맞춘 예제이며 OpenCode 실행 테스트를 한 설정은 아니다. [공식 스키마](https://opencode.ai/config.json)

Ollama에 `qwen3.5`라는 정확한 모델 ID가 존재하고, 해당 모델을 실제로 65,536 컨텍스트로 실행한다는 전제의 예제:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "enabled_providers": ["local"],
  "model": "local/qwen3.5",
  "small_model": "local/qwen3.5",
  "provider": {
    "local": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Local lab",
      "options": {
        "baseURL": "http://localhost:11434/v1"
      },
      "models": {
        "qwen3.5": {
          "name": "Qwen local experiment",
          "tool_call": true,
          "limit": { "context": 65536, "output": 8192 }
        }
      }
    }
  }
}
```

`qwen3.5`는 Ollama의 공식 OpenCode 연결 예제에 사용된 ID다. 설치 태그가 다르면 `models`의 키와 `model`/`small_model`의 모델 ID 부분을 모두 실제 값으로 변경한다. [Ollama OpenCode 통합](https://docs.ollama.com/integrations/opencode)

LM Studio에서는 endpoint를 `http://127.0.0.1:1234/v1`로 바꾸고, 다음처럼 **서버가 돌려준 실제 모델 ID**를 사용한다. 꺾쇠 placeholder 그대로는 실행용 모델이 아니다.

```text
baseURL: http://127.0.0.1:1234/v1
models의 키: <GET /v1/models에서 확인한 실제 ID>
model: local/<동일한 실제 ID>
small_model: local/<동일한 실제 ID>
```

LM Studio는 `/v1/models`와 `/v1/chat/completions`를 제공하며 모델 identifier를 요청에 넣도록 안내한다. [OpenAI 호환 API](https://lmstudio.ai/docs/developer/openai-compat)

`enabled_providers`는 공급자 allowlist이고 `small_model`은 제목 생성 등 보조 작업에 사용할 모델이다. 둘을 로컬로 맞추되 설정 파일은 병합되므로 전역·프로젝트의 에이전트별 모델 지정도 확인한다. 이 설정을 완전한 오프라인 모드로 설명하지 않는다. [OpenCode 설정 문서](https://opencode.ai/docs/config/)

**추가 소스 확인:** 기존 런타임에서 새 사용자 정의 모델의 `limit`를 생략하면 context/output은 0으로 초기화된다. output 0은 실제 0토큰 요청이 아니라 기본 출력 한도(현재 소스 32,000)로 대체되지만, context 0은 자동 overflow/압축 판정을 비활성화한다. 따라서 장문 HTML 생성·수정 실습에서는 서버에 실제 로딩한 context와 지원되는 출력 한도를 명시한다. 예제의 65,536/8,192가 모든 모델의 권장값이라는 뜻은 아니다. [사용자 정의 모델 기본값](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts#L1512-L1516) · [출력 한도 대체](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts#L1385-L1387) · [압축 판정](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/overflow.ts#L18-L30)

### 컨텍스트·도구 호출의 함정

- **컨텍스트:** OpenCode 공급자 문서의 16k–32k는 Ollama 도구 호출 문제 해결 힌트다. 더 최근의 Ollama 통합 문서는 OpenCode에 64k 이상을 요구한다고 명시한다. 실습은 64k 이상이 가능한 모델·메모리로 구성하고 서버의 실제 context와 `limit.context`를 일치시킨다. 숫자를 JSON에 적는 것만으로 서버의 메모리 할당이 커지지는 않는다. [Ollama 통합](https://docs.ollama.com/integrations/opencode) · [Ollama 컨텍스트](https://docs.ollama.com/context-length)
- **자원:** context가 커지면 메모리가 더 필요하다. `ollama ps`는 실행 중 모델의 CONTEXT와 CPU/GPU 배치를 확인하는 공식 경로다. [Ollama 컨텍스트](https://docs.ollama.com/context-length)
- **도구 호출:** `tool_call: true`는 호환성을 선언하는 설정이다. 모델에 없던 기능을 만들어 주지 않는다. LM Studio는 모델 템플릿과 런타임 파싱의 조합에 따라 Native/Default tool use를 구분하며 결과가 모델별로 다르다고 설명한다. 파일 읽기·쓰기 도구를 작은 실습으로 먼저 확인한다. [LM Studio 도구 사용](https://lmstudio.ai/docs/developer/openai-compat/tools)
- **로컬의 범위:** 추론 연결 주소가 로컬이라는 뜻이다. 모델 다운로드·업데이트·플러그인·웹 도구·Ollama Cloud 등은 별도 동작이다. 로컬 모델과 클라우드 모델을 혼동하지 않는다. [Ollama OpenCode 통합](https://docs.ollama.com/integrations/opencode)

## 7. 비교 실습에 남길 기록: 제안

다음 항목은 공정한 비교를 위한 가이드 설계 제안이다. 아직 모델별 실험 결과는 없다.

| 기록 | 이유 / 확인 경로 |
|---|---|
| 날짜·시간, OpenCode 버전·설치 채널 | 배포판·모델 목록 변경을 추적 |
| provider와 정확한 model ID | 모델 계열 이름과 실제 호스팅 경로를 분리 |
| 모델 variant / reasoning 설정 | 같은 모델의 추론 설정 차이를 분리 |
| 로컬 런타임 버전, 모델 파일/태그/digest | 재현에 필요한 모델 아티팩트 식별 |
| 양자화, context 실제값, 출력 한도 | 로컬 자원·성능 조건 기록 |
| 하드웨어, CPU/GPU 배치 | 로컬 속도 차이 설명 |
| 동일 프롬프트, 동일 초기 파일, 세션 여부 | 이전 생성물·대화의 영향 통제 |
| 생성/수정 각각 시간, 오류, 도구 호출 실패 | HTML 품질과 연결 실패를 분리 |
| 데스크톱/모바일 결과, 접근성, 수정 회귀 | 시각적 화려함과 기능 유지 모두 평가 |
| 토큰·비용·무료 조건(확인 가능한 경우) | 단가 추측 대신 실제 조건 기록 |

OpenCode는 provider/model 형식 및 모델별 variant를 지원한다. `/thinking`은 표시 토글이고 실제 reasoning 설정 전환과 다르다. [한국어 모델 문서](https://opencode.ai/docs/ko/models/) · [한국어 TUI](https://opencode.ai/docs/ko/tui/)

LM Studio의 `/api/v1/models`는 quantization, 로딩된 context, 모델 최대 context, tool-use capability, 선택한 variant 등의 메타데이터를 제공한다. 최대 context와 현재 로딩 context를 별개로 기록한다. [LM Studio 모델 메타데이터](https://lmstudio.ai/docs/developer/rest/list)

**확정 실습 설계:** Round 1은 각 모델마다 동일한 요구사항과 지침만 둔 새 프로젝트·새 세션에서 시작한다. Round 2는 같은 모델·같은 세션에서 각자가 만든 Round 1 결과에 동일한 변경 요청을 적용한다. 이 방식은 제작부터 자기 결과 수정까지 이어지는 종합 실습이며, 모델마다 수정 대상 HTML과 이전 대화가 다르다. 수정 능력만 별도로 비교하려면 대안 실험으로 동일한 원본 HTML 사본·새 세션·동일한 변경 요청을 사용하고 종합 실습 결과와 구분한다. 스텔스 모델의 내부 버전처럼 공개되지 않은 값은 `미공개`로 기록한다. 승자·점수·속도는 직접 측정하기 전에는 채우지 않는다.
