## 실험 제안의 구체화 · 2026-10-18

‘실험이 직관적이지 않다’는 사용자 피드백에 따라, 가상 상품 30개·테스트 조회 서비스·HTTP 403을 준비하는 제안을 채팅창에서 따라 할 수 있는 가상 텀블러 비교로 바꿨다. 첫 요청문과 상품 표, 후속 요청문, 기대 답변, 세 가지 확인 기준을 모두 본문에 제공한다.

- 가상 예산은 배송비 포함 20,000원이다. A는 16,000 + 3,000 = 19,000원, B는 상품가 14,000원만 확인되고 배송비·재고 미확인, C는 15,000 + 2,000 = 17,000원이다.
- C의 상품가만 19,000원으로 변경하면 총액은 21,000원이다. 조건이 확인된 상품 중 첫 추천은 C, 변경 후 추천은 A가 되는 예시다.
- 가격·상품·답변은 모두 편집부가 만든 가상 예시다. 외부 상품 사실이나 실제 AI 실행 결과로 제시하지 않는다. 웹 차단 인식·Shop MCP 통합·실제 결제 능력을 검증하는 실험으로 확대 해석하지 않는다.
- 확인할 항목을 변경 반영·미확인 정보 구분·총액과 이유 설명으로 줄였다. 복잡한 성공률·시간 지표는 제거했다.

## Shop MCP 실제 실행과 기사 반영 · 2026-10-18 11:46~11:49 KST

사용자가 후속 요청에서 실제 상품 검색부터 체크아웃 생성까지 실행하고 결과를 기사에 반영하라고 명시했다. 결제·푸시 금지 조건을 유지했다. 위의 ‘미실행’ 기록은 이전 편집 단계에 관한 것이며, 이번 단계에서는 실제 공식 서버를 호출했다.

### 방법과 범위

- `https://mcp.shop.com/`에 HTTP POST JSON-RPC 호출. 공식 [Shop 스킬](https://mcp.shop.com/skill.md)과 [거래 참고 문서](https://mcp.shop.com/references/transactions.md), 실제 `tools/list` 입력 스키마를 읽은 뒤 진행했다.
- MCP 헤더·메타 버전 `2026-07-28`, 응답 UCP 버전 `2026-08-25`. Authorization·쿠키·Shop 로그인·구매자 개인정보·결제수단을 사용하지 않았다.
- 검색 입력: `catalog.query: 텀블러`, `context: {address_country: KR, currency: KRW}`, `filters: {ships_to: {country: KR}, available: true}`, `pagination.limit: 3`.
- 검색 후보 중 첫 번째 텀블러를 실행용으로 선택했다. 사용자의 취향이나 최저가 추천을 검증한 것이 아니다. 판매자 한 곳, 옵션 하나, 수량 1개만 생성했다.
- `get_product`는 처음 `selected[].value`를 보내 HTTP 400 / JSON-RPC -32602 / `label` 누락 오류를 받았다. `selected[].label`로 수정해 성공했다. 이 읽기 요청 수정은 체크아웃 재생성이 아니다.
- `create_checkout`에 공개 variant ID·판매자 도메인·수량·KR/KRW context와 UUID 멱등성 키를 전달했다. 생성 1회와 해당 ID의 조회 1회만 수행했다. 장바구니 생성·체크아웃 수정·결제 완료·다른 판매자 재시도는 수행하지 않았다.
- 체크아웃 ID·진행 URL은 생성과 조회를 실행하는 같은 프로세스의 메모리에서만 취급했다. 원문 응답을 저장하거나 출력하지 않고, 필드를 허용 목록으로 골라 접근 키 없는 요약만 확인했다. 이 기록은 원시 로그가 아닌 공개 가능한 관찰 메모다.

1. KRW 요청에도 USD가 반환된 후보가 있었다. 응답 통화를 확인해야 한다는 사례이며 모든 상품이 KRW를 무시한다는 뜻은 아니다.

4. 한 시점·한 판매자·한 체크아웃의 관찰이다. 전체 판매자 지원률, 재현 가능한 고정 상품 순위, 성능 벤치마크로 확장하지 않는다.

## 실제 요청·응답 발췌 추가 · 2026-10-18

사용자의 요청에 따라 `#shop-mcp-examples` 접기 영역 안에 네 도구의 요청·응답 JSON 예시를 추가했다. 11:46~11:49의 기존 호출과 당시 확인한 응답을 근거로 했으며, 예시를 만들기 위해 외부 API를 다시 호출하거나 체크아웃을 추가 생성하지 않았다.

- 요청은 JSON-RPC `params.name`·`params.arguments`, 응답은 `result.isError`와 `result.structuredContent`의 선택 필드를 발췌했다. 전체 원문 로그·완전한 실행용 요청이 아니라는 점과 공통 외피·메타데이터의 생략을 명시했다.
- 검색 응답은 3개 중 2개를 선택해 KRW 요청과 USD 응답의 차이를 보여준다. 상세 조회는 `selected[].label`로 수정해 성공한 실제 요청을 사용했다.
- 생성·재조회는 당시 출력한 허용 필드 요약에서 확인한 원래 필드 경로와 값으로 구성했다. 출력하지 않은 checkout ID는 복구하거나 추정하지 않고 `[CHECKOUT_ID_REMOVED]`로 통일했다. 진행 URL·접근 키·인증·쿠키·구매자·결제 데이터는 포함하지 않았다. 공개 상품·옵션 ID와 판매자 도메인은 유지했다.
- 생성 당시 메모리에서 만든 UUID 멱등성 키는 `[IDEMPOTENCY_KEY_REMOVED]`로 치환했다. 자리표시자는 실제 값이나 실행 가능한 입력이 아니라고 안내했다.
- 배송비·세금이나 주문 객체를 `0`·`null`로 만들어 넣지 않았다. 생략된 필드와 실제 부재를 구분하고, 두 `totals` 항목과 거래 상태·네 메시지 코드는 관찰값 그대로 유지했다.
- 네 단계는 각각 독립적인 하위 접기 영역으로 제공한다. 별도 JavaScript 없이 기본 `details`·`summary`를 사용하고 코드의 모바일 줄바꿈·키보드 초점을 지원했다. 기사 전용 CSS 참조를 `v=5`로 변경했다.

검증: 요청·응답 JSON 발췌 8개를 모두 파싱하고 도구 이름, 옵션 ID, 치환된 ID·멱등성 키, USD·KRW, 체크아웃 상태·메시지 수를 관찰 기록과 대조했다. 코드 예시에 진행 URL·토큰·구매자·결제 데이터 필드가 없는지 검사했다. HTML ID 16개·로컬 참조·태그 짝 확인, 기존 테스트 7개 통과. 데스크톱 1280px와 모바일 390px 라이트·다크 화면에서 코드 표시·가로 넘침 없음, 바깥 접기 영역과 네 단계의 Enter 조작을 확인했다. 브라우저 오류 0개. 테마·임시 화면 크기를 복원하고 미리보기에는 조회 예시를 펼쳐 두었다. 외부 API 추가 호출·결제·커밋·푸시 없음.

## 요청·응답 사이의 식별자 연결도 · 2026-10-18

사용자가 상품 ID·판매자·체크아웃 ID의 연결을 한눈에 보도록 요청해, 코드 예시 바로 위에 HTML/CSS 연결도를 추가했다. 요청 경로는 `params.arguments`, 응답 경로는 `result.structuredContent` 기준이다. 기존 실제 호출에서 확인한 값만 재구성했으며 새로운 API 호출은 없다.

마지막으로 선택한 `bash` 또는 `powershell`을 `hello-human:shop-curl-shell`이라는 브라우저 저장소 키에 기록하고, 페이지 초기화 때 읽어 모든 cURL 예시에 적용한다. 두 값 이외의 저장값은 기본 Bash/zsh로 처리한다. 저장소 읽기·쓰기가 실패해도 페이지 내 전환·복사 동작은 유지한다. 저장 대상은 셸 이름뿐이며 요청 본문이나 식별자는 저장하지 않는다. 기사 설명을 갱신하고 스크립트 참조를 `v=6`으로 변경했다.

## 예시 펼침 상태 유지와 문장 마무리 · 2026-10-18

전체 요청·응답 영역, 도구별 JSON, 도구별 cURL, 비교 단계별 JSON·cURL의 펼침 상태를 같은 브라우저에서 복원하도록 했다. 접힌 부모 영역 안에서도 자식 예시의 상태를 별도로 보존한다. 비교 영역은 마지막 선택 단계를 함께 기억하므로 연결도로 돌아간 뒤 새로고침해도 다시 표시된다. `hello-human:shop-example-disclosures`에는 허용된 화면 항목의 불리언 값과 비교 단계 이름만 저장하며, 요청·응답 내용이나 거래 식별자는 저장하지 않는다. 잘못된 저장값은 제외하고 저장소 오류가 있어도 화면 조작은 유지한다.

새로고침은 직전의 접힘 상태를 존중하고, 사용자가 직접 누른 다음 요청 링크는 해당 예시를 연다. 같은 링크를 다시 눌러도 접어 둔 요청이 열리도록 처리했다. 스크립트 참조는 `v=7`이다.

본문과 도식 설명, 사용 안내의 문장을 전반적으로 다듬었다. 뉴스 요약의 공급사 평가·보도 구분을 명확히 하고, 긴 기술 설명을 짧게 나눴다. 전체 문서 교체 절차와 통신·거래 상태의 차이를 자연스러운 문장으로 풀고, 실제 실험에서는 반환 금액과 최종 결제액의 구분을 유지했다. 제목·발행일·호수·사실관계·출처 링크·코드 예시는 유지했다. 새로운 사실 조사나 API 실행으로 최신화한 수정은 아니다.
