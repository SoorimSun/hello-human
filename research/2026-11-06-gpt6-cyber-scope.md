## 조사 범위와 편집 판단

- 각 공식 발표·보고서와 관련 도움말의 실제 본문을 읽었다. 검색 요약만으로 사실을 확정하지 않았다. METR, Anthropic, Box 일부 URL은 웹 도구에서 오류가 났지만 일반 브라우저 User-Agent의 읽기 전용 HTTP 요청으로 본문을 확보했다. OpenAI 영문 본문과 시스템 카드는 웹 도구와 브라우저로 읽었다.
- OpenAI 한국어 후보 URL은 웹 도구에서 캐시 미스, 직접 요청에서는 403이었다. 유효한 번역 내용을 확인하지 못했으므로 영어 링크를 사용한다.
- 공식 발표 날짜에 맞춰 ‘최근 24시간’ 대신 11월 5일 발표와 11월 6일 확인일을 적었다. 실제 최초 게시 시각은 확정하지 않았다.
- Firefox 81건은 발표사 집계와 Mozilla의 관련 수정 확인을 구분했다. Linux 연구는 38호와 겹쳐 수치를 다시 전개하지 않았다.
- 초안의 사전식 RAG·토큰·Plaid·DLP 정의와 반복되는 ‘~라는 뜻은 아닙니다’를 줄이고 판단에 필요한 조건을 수치·화면 가까이에 모았다.
- 새로운 비용 예시는 추가하지 않았다. 실험의 비용은 향후 실제 측정할 지표이며 지금 계산한 값이 없다.

## 실험 설계와 최근 글 대조

- 35호: 장애 알림의 참여 판단·재개·중복 보고서. 36호: 승인 후 견적 변경과 재승인. 37호: 개발 도구 비교. 38호: 검사 결과와 현재 커밋 일치. 이번에는 문서 접근 권한과 도구 실행 권한을 나눠 확인한다.
- 초안의 쿠폰·부분반품·정산 전반 대신 협력사 서류 검토로 범위를 좁혔다. 문서 검색부터 상태 변경까지 한 사례로 연결한다.
- 가상 문서 30개 = 일반 정책 12 + 제출 서류 12 + 관리자 전용 6. 조정용 요청 6개와 최종 24개 분리. 최종 24 = 정상 8 + 권한 초과 8 + 문서 내 지시 8. 권한 초과는 관리자 문서 4, 승인 요청 4.
- A 수작업, B 에이전트+권한별 검색, C B+실행 전 검사. B와 C에 동일 모델·검색·지침·한도. 검색 필터 제거 비교는 별도이며 실행 통제 효과와 섞지 않는다. B의 변경도 모의 저장소에서만 발생한다.
- ‘검사기가 잘 막았다’와 ‘모델이 금지 호출을 제안하지 않았다’를 구분한다. 금지 호출 시도가 0이면 차단율 미산출. 정책 서버 장애는 고정 호출로 주입하고 보류를 기대한다.
- 사람 비교는 첫 실행만 사용하고 세 검토자가 A/B/C를 각각 8건씩 맡도록 24개 요청을 교차 배정한다. 한 검토자는 동일 요청을 다른 방식으로 다시 보지 않는다. 사람 시간은 전체 투입을 올바른 완료 건수로 나누며 완료 0건이면 미산출이다.
- 모델·정책 검사기·실제 업무 서비스 통합은 구현하지 않았다. 기사 안의 도식과 상황별 재생은 미리 작성한 기대 흐름이며 성능·권한 검증을 실행한 증거가 아니다.
