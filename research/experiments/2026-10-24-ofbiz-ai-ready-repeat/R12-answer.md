수량 선택 순서는 **명시한 `cancelQuantity` → 해당 키의 `itemQtyMap` 값 → 계산된 잔여 항목 수량**입니다.

1. **둘 다 들어오면 `cancelQuantity`가 우선입니다.** `cancelQuantity == null`일 때만 맵을 조회하므로, 0을 포함해 null이 아닌 값이면 맵 값으로 덮어쓰지 않습니다. (`OrderServices.java` 2006, 2012~2016행)

2. **맵의 키는 `orderItemSeqId + ":" + shipGroupSeqId`입니다.** 예를 들어 `"00001:00002"`이며, 값은 문자열로 읽어 `new BigDecimal(...)`로 변환합니다. 맵이 비어 있지 않고 해당 키의 값도 비어 있지 않아야 선택합니다. 서비스 정의에는 `cancelQuantity`가 `BigDecimal`, `itemQtyMap`이 `Map`, 문자열 입력 접두사가 `iqm_`로 선언돼 있습니다. (`services.xml` 284~287행, `OrderServices.java` 2012~2016행)

3. **직접 수량이 없고 맵에 해당 키가 없거나 값이 비어 있으면**, `cancelQuantity`는 null로 남아 `itemQuantity`를 사용합니다. 이는 `OrderItem.quantity − 기존 취소 수량 − 기입고 수량(구매 주문) 또는 기출고 수량(그 외)`입니다. 배송 그룹 연결의 잔여 수량을 기본값으로 고르는 것은 아닙니다. 선택 수량이 배송 그룹 잔여 수량을 초과하면 자동으로 줄이지 않고 오류를 반환합니다. (2071~2104, 2213~2215행)

맵 조회는 배송 그룹 연결을 순회하기 **전에 한 번** 수행하므로, 각 연결의 식별자로 맵을 다시 조회하지 않습니다. (2013~2019, 2051행)

추가 확인할 내용은 `iqm_00001:00002` 같은 요청 필드가 실제 맵으로 변환되는 프레임워크 처리와 위 분기의 실행 결과입니다. 제공된 테스트는 주문 생성 검사이며, 수량 우선순위·키 누락 동작의 실행 검증 근거는 없습니다.
