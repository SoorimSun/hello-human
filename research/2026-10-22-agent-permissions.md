## 후속 확인과 편집

- 다음 모임 재사용 후속 요청으로 취소 결과 아래에 ‘남은 생수 전부 재사용 가능·불가’와 다음 필요량 0·10·20·40병 선택을 추가했다. 이 두 설정은 예시 재실행 없이 예상 비교를 바로 바꾸며, 기존 주문·취소 상태·환불·수수료·예산·이력을 변경하지 않는다. 같은 용량·옵션의 남은 생수를 먼저 쓰고 부족분을 상자 단위로 올려 구매한다고 가정한다. 다음 상자 가격도 24,000원이며, 늦는 기존 배송은 다음 모임 전에는 도착하고 그 사이 다른 곳에서 생수를 쓰지 않는 조건이다.
- 각 권한 방식의 유지·취소별로 이번 지출, 다음 모임에서 쓸 남은 물, 다음 구매량·비용, 두 모임 합계, 다음 모임 뒤 재사용 가능한 여분을 비교한다. 환불 12,000원·수수료 3,000원, 이번 새 두 상자 완료, 다음 20병 필요 조건에서 재사용 가능이면 유지 72,000원·취소 87,000원, 재사용 불가이면 유지 96,000원·취소 87,000원이다. 현재 비용만 보면 취소가 저렴해도 다음 구매를 포함하면 유지가 저렴해지는 경우를 명시한다. 다음 0병이면 여분에 현금 가치를 임의로 붙이지 않아 이번 지출만 비교하고, 10병이면 새 한 상자의 여분 10병을 표시한다.
- 재사용 불가 물량은 다음 필요량과 ‘다음 뒤 여분’에서 제외하지만 자동 폐기하지 않는다. 보관·사용 가능한 상태는 편집자의 실험 가정이며 실제 품질 판단이 아니다. 가격 변동·별도 배송비·보관 비용은 계산하지 않고 미래 구매도 실행하지 않는다. 이번 모임 준비가 아직 부족하면 부족분 구매비가 합계에 빠져 있음을 표시하고 유지·취소 우열 판단을 보류한다. 과거 주문의 취소를 되돌리거나 다음 필요량을 이번 중복 구매 목표에 합치지 않는다.
- 취소 수수료·부분 환불 후속 요청으로 기존 취소 예시를 확장했다. 취소 가능 여부와 별도로 환불액 24,000원·12,000원·0원, 수수료 0원·3,000원·12,000원·15,000원을 선택한다. 환불액은 수수료 차감 전 금액으로 정의하고 총지출 = 새 구매 비용 + 기존 결제 − 환불 + 수수료로 계산해 이중 차감을 막는다. 부분 환불도 기존 20병 주문 전체 취소이며, 취소 불가·미시도에는 환불·수수료를 반영하지 않는다. 실제 고객사 정책이 아닌 가상 조건이다.
- 취소 전에도 현재 새 주문을 동일하게 둔 유지·취소 예상 결과를 각 권한 방식의 비교표로 보여준다. 예상 비교는 주문·환불·수수료·이력을 변경하지 않고, 취소 버튼 실행 뒤에만 현재 결과가 바뀐다. 새 두 상자 완료 조건에서 유지는 총 72,000원·모임 뒤 20병, 전액 환불·수수료 3,000원은 51,000원·0병, 50% 환불·수수료 3,000원은 63,000원·0병, 50% 환불·수수료 15,000원은 75,000원·0병이다. 환불액과 수수료가 같으면 총지출은 같다. 남는 생수의 향후 사용 가치나 보관 부담은 금액으로 가정하지 않아 취소가 항상 낫다고 단정하지 않는다.
- 환불·수수료 선택은 예시 재실행 때 적용하며 실행 중인 기존 조건은 결과에 따로 표시한다. 환불액은 기존 결제액을 넘지 않는 정수, 수수료는 0~200,000원의 정수만 모델에서 허용한다. 기존 전액 환불·수수료 0원은 기본값으로 유지한다. 반복 취소의 중복 환불·수수료, 다른 구성으로의 금액 전파, 기존 주문 정산으로 새 구매 예산이 바뀌는 동작을 막았다.
- 늦는 기존 주문의 취소 비교를 일곱 번째 반복 예시로 추가했다. 총 40병 필요·집 재고 0·기존 20병은 모임 뒤 도착·기존 결제 24,000원을 고정하고, 취소 가능·불가 조건을 고른 다음 별도 버튼으로 가상 취소를 시도한다. 가능 선택만으로 취소되지 않으며, 성공하면 전액 환불·수수료 없음으로 계산한다. 실제 고객사 정책이 아닌 편집자의 가정이다. 공통 권한과 개별 권한 모두에 같은 고객의 취소 선택을 적용한다.
- 새 주문 두 상자가 완료됐을 때 새 구매 비용은 취소 여부와 관계없이 48,000원이다. 기존 주문 유지·취소 불가는 총지출 72,000원·모임 뒤 20병, 취소 성공은 환불 24,000원을 반영해 총지출 48,000원·잔여 0병이다. 새 구매 비용·기존 결제·환불·총지출·남는 수량을 따로 표시한다. 기존 환불로 새 구매 예산이 늘지는 않는다. 승인 대기·생략·차단은 구매 완료나 비용에 포함하지 않으며, 늦게 오는 물량으로 모임 당시의 부족분을 상쇄하지 않는다. 모임 중 필요량까지 소비하고 취소하지 않은 늦은 배송은 이후 모두 도착한다는 가정이다.
- 취소된 기존 배송은 가용 물량에서 제외하고 원래 주문 정보와 과거 판단 이력은 유지한다. 반복 취소는 추가 환불을 만들지 않으며, 기존 주문의 수량·도착 시점은 취소 예시 동안 고정한다. 다른 예시를 다시 실행하면 취소 이력과 조건이 초기화되고 개별 배송 입력도 다시 열린다. 취소 조건·결과는 같은 용량·옵션에만 적용한다. 일반 배송 예시는 기존대로 도착 시점을 바꿀 수 있다.
- 배송 중인 생수 후속 요청으로 여섯 번째 반복 예시와 개별 요청의 기존 배송 수량·도착 시점 입력을 추가했다. 총 40병 필요·집 재고 0·배송 중 20병에서 모임 시작 전 도착 예정이면 추가 한 상자, 모임 후 도착 예정 또는 시점 미확인이면 두 상자가 필요한 가상 규칙이다. 0·10·20·40병으로 배송 물량도 바꿀 수 있고, 개별 입력은 0~200병을 지원한다. 시간 미확인은 보수적으로 제외하는 편집자의 실험 규칙이며 실제 쇼핑몰 정책이 아니다.
- 집에 있는 재고·모임 전 도착 예정·늦거나 시점 미확인인 배송·이번 실험의 새 주문·승인 대기를 구분했다. 집 재고와 모임 전 배송 예정만 먼저 필요량에서 빼고, 부족분을 상자 단위로 올려 새 구매 목표를 계산한다. 배송은 동일 용량·옵션별로 보관하며 입력 원본과 반환값 변경이 내부 수량을 바꾸지 않는다. 승인 시 최신 배송 시점을 재검사하고, 재시도와 이전 이력은 당시 판단을 보존한다. 도착 예정은 수령 완료·도착 보장이 아니며, 모임 후 도착분을 제외해도 주문이 취소되지는 않는다. 이번 실험의 새 주문은 모임 전에 도착한다고 가정하고, 기존 주문 금액은 새 주문의 가상 지출·예산 합계에 넣지 않는 범위를 화면에 밝혔다.
- 집에 남은 생수를 포함하는 후속 요청으로 다섯 번째 반복 예시를 추가했다. 총 40병이 필요한 상태에서 500mL·일반 뚜껑 생수가 0·10·20·40병 남은 경우를 비교한다. ‘필요 수량까지 고려’는 총 필요 병 수에서 집에 있던 병 수를 뺀 뒤 상자 단위로 올려 새 구매 목표를 계산한다. 10병이면 부족분 30병 때문에 두 상자, 20병이면 한 상자, 40병 이상이면 새 구매 0상자다. 묶음 판매로 생기는 여분을 불필요한 추가 상자와 구분했다.
- 개별 요청에는 남은 생수 0~200병 입력과 현재 필요량 계산을 추가했다. 재고는 같은 용량·옵션별로 분리하며, 실험 시작 전 보유량과 이번 실험의 완료 주문을 따로 합산해 이중 계산을 막는다. 주문 완료·승인 대기·앞으로 구매 완료해야 할 부족분을 공통 권한과 개별 권한별로 표시한다. 입력은 즉시 반영하되 완료 주문은 취소하지 않으며, 승인 때 최신 재고와 권한·예산을 다시 확인한다. 요청 재시도는 기존 판단을 반환하고 이력에는 판단 당시 재고를 남긴다. 실물 재고·소비·배송을 자동 연동한 기능이 아닌 가상 실험이다.
- 인원 증가 후속 요청으로 네 번째 반복 예시와 ‘필요 수량까지 고려’ 기준을 추가했다. 20명에게 1인당 생수 1병을 준비해 A가 500mL × 20병·일반 뚜껑 1상자를 구매한 뒤, 40명으로 늘어 목표를 1→2상자로 바꾸고 B가 같은 구성을 추가 요청한다. 기존 구성 비교는 B도 대기시키지만 수량 기준은 필요한 두 번째 상자를 허용한다. 이후 B가 같은 구성을 새 요청으로 추가해 세 번째 상자의 목표 초과를 비교할 수 있다.

- 승인 대기 주문은 승인 시점에 연결 상태·구매 권한·누적 예산을 다시 검사한다. 같은 요청 번호와 내용은 기존 결과를 반환하고, 같은 번호의 다른 내용은 변경 전에 거부한다. 서로 다른 요청이 같은 상품을 사는 중복 수요는 별개이며, 공동 장바구니·중복 알림을 다음 실험 아이디어로 제시한다. 새로고침·초기화 시 기록은 사라지고 네트워크 주문은 없다.
- 동적 결과에 따라 역할별 권한 템플릿·승인함·개별 중지·통합 예산·중복 구매 알림을 제안한다. 정해 둔 규칙의 시연이며 실제 사용성·구매 감소 효과를 측정한 결과는 아니다. 단계별 관찰 안내와 JavaScript 없이 읽을 수 있는 정적 예상 결과 표도 남겼다.
- 발송 직전 변경 안내를 ‘기존 승인 범위 안’과 ‘재승인 필요’로 나눴다. 오탈자 교정도 허용받았고 의미·금액·수신자가 그대로인 경우와, 승인받지 않은 수신자·내부 원가표를 추가해 공유 범위를 넓힌 경우를 대비했다. D2의 범위 내 후속 행동과 범위 밖 새 판단 원칙을 적용한 편집 예시다. 정확한 최종본에 대한 승인만으로 모든 교정이 자동 허용된다는 주장은 피했으며 기존 맞춤 규칙·안전 요건 설명은 유지했다.
- 발송 직전 수신자·첨부 변경 예시를 같은 회의 자료 상자에 추가했다. D2는 구체적 지시가 정한 범위의 후속 행동을 포괄할 수 있지만 범위 밖 행동에는 새 판단이 필요하다고 설명한다. 이를 승인받은 고객 외 수신자 추가·내부 원가표 첨부라는 편집 예시에 적용해, 기존 허용 범위를 벗어나면 발송을 멈추고 변경된 대상·내용의 승인을 다시 확인해야 한다고 썼다. 모든 사소한 변경에 무조건 재승인을 요구하거나 재승인만으로 기본 안전 요건을 우회할 수 있다고 쓰지 않았다. 도표 캡션에 D2를 연결했으며 실제 동작 보장이나 발송 시험 결과가 아니다.
- Dots 발송 예시를 ‘추가 승인 없이’와 ‘승인 대기’ 두 문장으로 구체화했다. 최종본·수신자를 지정한 발송 지시가 자동 검토에서 규칙·기본 안전 요건에 맞는 경우와, 동일 자료에 ‘고객 메일은 발송 전 확인’ 규칙을 적용한 경우를 비교한다. D1의 액세스·권한 및 자동 검토 설명을 재확인했으며, 명시적 지시만으로 모든 승인이 생략된다고 쓰지 않았다.
- 회의 자료 예시에 수신자를 지정한 이메일 발송 요청을 추가했다. A1의 메시지 발송 전 내용 제시·사용자 승인 대기와 D1의 사용자 지시·맞춤 규칙·기본 안전 요건에 따른 자동 검토를 다시 확인했다. 두 카드에 ‘자료 수정 → 고객에게 발송’을 같은 순서로 표시했다. Dots의 ‘고객 메일은 승인 후’ 규칙은 편집자가 정한 예이며, 모든 이메일이 승인 없이 발송되거나 맞춤 규칙으로 안전 요건을 해제할 수 있다고 서술하지 않았다. 실제 메일은 발송하지 않았다.
- 비교표 바로 아래에 동일한 회의 자료 수정 업무의 가상 예시를 추가했다. 월요일의 ‘한 장·비용 우선’ 조건을 화요일 새 견적 반영 요청에도 이어 쓰는 상황이다. Duet은 같은 지속 대화, Dots는 ChatGPT에서 Slack의 같은 dot으로 이어지는 작업이라는 A1·D1의 설명을 적용했다. 자료·앱 접근 허용을 전제로 하고 실제 실행·기억 정확도 검증이 아님을 명시했다. 기존 반응형 예시 스타일을 재사용하고 절 마지막의 중복 회의 예시는 실험 관점으로 줄였다.
- 맥락 기억과 업무 연속성에 대한 후속 요청으로 비교표에 두 행을 더해 본문 6행으로 확장했다. A1의 기존 Claude 메모리·스킬·연결 앱, 하나의 지속 대화, 장기 작업·완료·검토 알림과 D1의 대화·피드백에 따른 선호·판단·결과 기준 파악, 채널 간 맥락 유지, 여러 프로젝트 병행을 대조했다. 제품이 설명하는 사용 방식을 비교했으며 모든 대화를 영구 저장한다거나 기억 구조·보존 기간이 같다는 주장은 하지 않는다.
- 후속 요청으로 Duet의 맥락 유지 설명 바로 뒤에 4행 비교표를 추가했다. 공통 기반은 두 제품 열을 합쳐 한 번만 설명하고, 대화 채널·컴퓨터 접근·실행 승인을 세 가지 차이로 제시했다. 표 아래에 확인일과 양사 원문 링크를 붙였으며 전용 CSS만 조정했다.
- 사용자 요청에 따라 Duet 절의 소제목과 도입을 ‘맥락을 유지하며 일을 이어가는 개인 업무 에이전트’ 중심으로 수정했다. 30초 요약·부제·모임 관점도 맞췄다. 메모리·스킬·연결 앱, 이어지는 대화, 기기가 꺼진 동안의 작업, 완료·검토 알림을 연결해 설명하고 Dots 공식 발표와 기존 가이드 링크를 추가했다. 앱 이미지는 일을 수행하는 도구를 설명하는 역할로 제목을 조정했다. 회의 준비 예시는 가상 실험 제안으로 표시했으며, 기존 프리뷰 대상·확인 주기·승인·사용 한도는 유지했다.
- 10월 22일 확인 시 Walmart·Claude Duet·Google Cloud의 후속 제공 상태와 OpenAI 보고서 갱신을 공식 도메인 중심으로 검색했다. 확인한 원문·제품 페이지·보고서 목록에서 위 제공 상태를 바꾸는 공식 후속 발표는 찾지 못했다. 모든 후속 자료가 없음을 보장하지 않는다.

초기 작성에서는 HTML 도식과 공식 페이지 링크만 사용했다. 이후 사용자의 공식 이미지 배치 요청에 따라 Walmart의 구매 이력·프로필 소개 이미지(1920 × 1080)를 원본 그대로 로컬 검토본에 추가했다. 출시 예정 기능의 소개 자료와 직접 사용 화면을 구분했다. 원본 URL·위치·이용 조건은 `assets/news/agent-permissions-media.md`에 기록했다. 공개 재배포 허가는 확인하지 못했으며 원격 게시하지 않았다.

다른 발표의 이미지도 추가해 달라는 후속 요청으로 Anthropic의 Claude Duet 연결 앱 안내, Cohere Rerank 5의 네 벤치마크 비교 그래프, Google Cloud의 협력 대표 이미지를 추가했다. 각 공식 페이지와 이미지 내용을 확인했으며, 기능 소개·공급사 자체 평가·협력 홍보 자료를 구분했다. 1Password 로그인은 출시 예정이라는 조건, Cohere 그래프의 지표·데이터셋 묶음·독립 검증 아님, Google Cloud의 비공개 프리뷰 상태를 캡션에 반영했다. OpenAI 사고 보고서에서는 사용할 별도 공식 이미지를 찾지 못해 기존 타임라인을 유지했다. 세 파일의 원본 URL·규격·배치·이용 확인 상태는 동일 미디어 기록에 추가했다.

## 저장소 적용 범위

기사·전용 CSS·검증 기록을 추가하고 뉴스 목록과 홈의 최신 일반뉴스 카드만 갱신했다. 현재 README·발행 지침은 개별 글을 README에 추가하지 않도록 하므로 README는 유지했다. 공통 CSS·JS는 변경하지 않았으며 커밋·푸시·배포는 수행하지 않는다.

클릭형 실험에는 `assets/agent-shopping-model.js`, `assets/agent-shopping-experiment.js`, `tests/agent-shopping-model.test.js`를 추가했다. 기사 전용 CSS와 실험 절만 확장했고, 초기 화면은 기존 콘텐츠 갱신 스냅샷 뒤인 DOMContentLoaded에 구성한다.

## 기본 결과의 핵심 차이 강조
