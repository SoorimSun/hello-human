## 확인 범위와 제외

- OpenAI 한국어 후보 페이지는 접근되지 않았고 관련 한국어 검색에서 유효한 번역을 확보하지 못해 실제 확인한 영문 원문을 사용했다.
- Open WebUI 릴리스는 확인 시 Latest로 표시됐다. 상세 보안 권고의 공개 상태는 별도 검증하지 않았으므로 CVE 공개 예정 문구를 본문에 복제하지 않았다.
- 독립적인 제조 비용 절감·실도로 안전성 개선 수치는 확보하지 못했다. 공급사 발표를 독립 측정으로 표현하지 않았다.
- OpenAI 영상은 실제 페이지에서 해당 위치로 이동해 확인했지만 Vimeo iframe의 재생 주소가 비어 있어 재생되지 않았다. 원문에 영상이 없다고 단정하지 않는다.
- Mazda 영상은 재게재·재사용 금지 문구가 있어 임베드·다운로드하지 않았다.
- 바이두 기술 설명은 출처가 바이두인 발표문 전재를 근거로 했다. Reuters는 공개 사건과 10만 km 주장의 보조 대조 자료다.

- 최근 글 대조: 11월 3일은 견적 변경·위임 취소·주문 원장 검증, 11월 2일은 채널 참여 판단·작업 복구, 10월 30일은 재시도와 늦게 도착한 비용 집계였다.

- 8개 결함은 서로 독립된 시작 코드로 준비한다. 연습 2건과 최종 8건을 분리하고 동일 요청·모델·설정·실행 환경을 유지한다. 각 방식 3회, 전체 48회라는 제안이다.

- 비교의 완전한 통제에는 한계가 있다. 같은 모델에 도구를 연결하면 도구 설명·메시지 형식도 달라진다. 특정 브랜드의 우열이나 운영 신뢰도로 일반화하지 않는다.
- A에도 같은 소스 파일·오류 재현 정보를 제공하고 모델 수정안을 그대로 적용한다. 사람의 직접 코드 수정은 자동 수정 성공에서 제외한다. 요청 전달부터 검사 종료까지 15분은 이 가상 과제에 제안한 동일 상한이며 제품의 제한이나 측정값이 아니다.
- 결과물은 버전이 있는 입력·시작 코드·요청문·검사기·변경 내역·실패 기록. 비용의 실제 단가와 금액은 제시하지 않았으므로 이번 기사에 가격·환율 추정을 추가하지 않았다.

## 최초 작성 시 검증 기록

- `node --test`: 기존 테스트 71개 통과, 실패 0. 새 실행 로직은 추가하지 않았다.
- `git diff --check`: 오류 없음. 기존 파일의 LF→CRLF 변환 안내는 있으나 공백 오류는 없다.
- HTML 검사: id 11개 중복 없음, 목차와 상대 링크·자산 경로 존재, 외부 링크의 새 탭·보안 속성, noindex, 엠대시 미사용 확인.
- 기사·목록·홈의 제목, ISSUE 37, 2026-11-04, URL 일치. 전체 50편·일반뉴스 37편·단신 13편, 새 기사 링크 한 번만 등록.
- 브라우저: 기본 데스크톱 1280px, 모바일 390px·320px 확인. 320px에서 회사명만 한 줄로 남는 현상을 발견해 전용 CSS의 좁은 화면 글자 크기를 조정하고 다시 확인했다.
- 라이트·다크 화면, 모바일 도식의 세로 순서, 실험 표, 가로 넘침 없음 확인. 이미지 3개는 각 절로 이동해 기사 내 로딩을 확인했다.
- 목차 클릭과 Enter 이동, 일반뉴스·단신 필터의 37·13편, 필터의 ArrowRight 이동 확인. 기사 열기→목록 복귀→새로고침 뒤 새 기사에 불필요한 Updated가 붙지 않았다.
- 홈의 최신 일반뉴스가 새 기사로 연결되고 기존 단신 링크는 유지됨을 확인했다. 마지막에는 기사 미리보기를 열고 임시 화면 크기 설정을 해제했다.
- 설명도·표·실험은 HTML에 정적으로 포함돼 있다. 자바스크립트를 실제로 끈 브라우저 세션과 인쇄 미리보기는 별도 확인하지 않았다.

- 사용자가 CSV 한 줄에 여러 오류를 담은 도입 예시가 직관적이지 않다고 지적했다. 도입을 ‘재고 0인 품절 상품과 재고 미입력 상품을 모두 오류로 처리하는 버그’ 하나로 좁혔다.
- 업로드할 상품표 두 행, 현재 오류, 수정 후 기대 결과를 HTML 표·카드로 제시하고 모델에 전달할 수정 요청을 바로 뒤에 붙였다. 가상 예시임을 표시했다.
- 앞자리 0·따옴표 안 쉼표 등 기존 8개 검증 과제와 48회 비교 설계는 유지했다. 파일 처리 규칙은 펼쳐 읽을 수 있도록 옮겨 구체적인 상황에서 세부 조건으로 이어지게 했다. 새 동작 스크립트는 추가하지 않았다.
- 검증: 기존 테스트 71개와 `git diff --check` 통과. id·목차·상대 경로·접근성 참조·CSS 버전 확인. 브라우저에서 상품표·오류·기대 결과를 대조하고, 데스크톱과 좁은 모바일의 가로 넘침 없음, 라이트·다크 대비, Enter·Space로 규칙 펼치기·접기를 확인했다. 테마와 임시 화면 크기를 복원하고 수정한 실험 절을 열어두었다. 변경분은 커밋·푸시하지 않았다.

## 실험 절 전체 재구성

- 사용자가 예시뿐 아니라 실험 과정과 내용 자체가 직관적이지 않다고 다시 지적했다. 기존 8개 결함·48회 평가, 세부 파일 형식 규칙, 여러 실행 상한을 제거하고 동일한 버그 한 건을 두 방식으로 고치는 입문 실험으로 범위를 바꿨다.
- 준비할 앱은 상품표를 받아 가져온 상품·오류 목록을 보여주는 로컬 실습 화면이다. 재고 0과 빈칸을 모두 미입력으로 처리하는 버그를 넣은 폴더 두 사본과 같은 상품표를 준비한다. 실제 운영 서비스에는 연결하지 않는다.
- 진행 순서는 ① 같은 시작 상태 준비 ② 동일한 요청으로 A는 채팅 수정안을 사람이 반영·검사하고 B는 에이전트가 직접 수정·검사 ③ 사람이 같은 파일과 재고 3인 컵 추가 파일로 최종 확인 ④ 수정 결과·사람의 중간 작업·최종 검토 시간을 기록하는 네 단계다.
- 모델·추론 설정, 새 대화, 같은 소스·입력, 방식별 15분, 해결안 공유 금지, 사람의 직접 수정 기록은 남겼다. 15분은 이 제안의 상한이며 제품 사양이나 측정값이 아니다. 한 번의 결과로 효율 우열을 일반화하는 평가가 아니라 진행 방식과 남는 일을 이해하는 실험으로 설명한다.
- 표의 ‘완료 / 미완료’, ‘직접 기록’은 기입 항목이며 실험 결과가 아니다. 실제 앱 구현·모델 호출·측정은 수행하지 않았다. 앞선 48회 설계와 이해도 개선 기록은 편집 이력으로 보존했다.
- 검증: `node --test` 71개와 `git diff --check` 통과. 링크·목차·id·접근성 참조·CSS 버전 및 폐기한 48회 설계의 본문 잔재 없음을 확인했다. 브라우저에서 네 단계 본문, A/B 순서 각 3단계, 데스크톱·모바일 배치, 기록표, 라이트·다크 대비와 가로 넘침 없음을 확인했다. 기존 접이식 규칙은 제거했고 모든 핵심 내용은 정적 HTML로 읽힌다. 후속 변경분은 커밋·푸시하지 않았다.

## 소식과 실험의 연결 명시

- 사용자가 네 소식 중 어느 내용과 관련된 실험인지 알기 어렵다고 지적했다. 직접 연결할 소식을 02 Open WebUI로 특정하고, 소식 끝의 실험 링크·목차·실험 제목·도입·A/B 환경을 함께 수정했다.
- 공식 웹 개발·파일 브라우저 문서를 다시 열어 파일 수정→서버 실행→Browser 탭 확인과 Files 탭의 역할을 대조했다. 버전 간 성능 비교가 아닌, 같은 Open WebUI 0.13에서 실행 도구 없이 채팅만 쓰는 A와 Open Terminal을 연결한 B의 작업 흐름 비교다. B의 Chrome 브라우저 조작 조건을 준비 단계에 포함했다.
- 상품표 오류는 파일 수정·검사 실행·화면 확인이 모두 필요한 작은 과제로 고른 가상 버그다. Open WebUI에서 실제로 발견한 제품 오류가 아니다. OpenAI의 제조 성과, Copilot·Air의 구독·격리, Apollo World의 주행 검증은 이번 실험의 확인 범위에 넣지 않는다.
- 연결 기능은 공식 문서에 근거하지만 실제 제품 설치·설정·실험은 수행하지 않았다. 작업 방식이 달라지면 도구 설명과 관측 형식도 달라지므로 하나의 변수만 완전히 분리한 성능 평가로 해석하지 않는다.
- 검증: 테스트 71개와 `git diff --check`, id·목차·상대 경로·외부 링크 속성 검사를 통과했다. 02절의 새 링크와 목차에서 Enter로 실험 절 이동을 확인했고, 데스크톱·모바일에서 소식 번호·새 제목·연결 이유가 보이며 가로 넘침이 없음을 확인했다. 후속 수정은 커밋·푸시하지 않았다.

## 후속 변경 최종 검토

- 사용자가 누적된 수정사항의 재검토와 로컬 커밋을 요청했다. 바이두 이미지·캡션·미디어 출처, Open WebUI 연결 실험의 범위와 네 단계, 관련 CSS와 조사 기록을 검토했다. 푸시·배포는 요청 범위에서 제외된다.
- 실험의 수정·중간 검사에 15분을 배정하고 마지막 사람 검토는 별도로 기록하도록 경계를 명확히 했다. 같은 라이브러리 버전·실행·검사 명령을 쓰도록 보완하고, 사람이 직접 고친 코드는 결과표에서도 확인할 수 있게 추가했다.
