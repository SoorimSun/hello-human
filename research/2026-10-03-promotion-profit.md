# 커머스 인사이트 3 · 판촉·가격 AI 근거 검증

검증일: 2026-10-03 (Asia/Seoul). 범위: RELEX, Mathem, Talon.One. 공식 제품 문서·발표·고객 사례를 우선했다. 제품 설명은 제공사의 주장으로 구분했으며, 독립적인 효과 검증으로 간주하지 않는다. 외부 미디어는 다운로드하지 않고 공식 원격 URL을 확인했다.

## 기사에 반영할 핵심 수정

- Mathem의 **21%p는 ‘이익이 난 프로모션의 비중’ 증가**다. 회사 전체 수익성이나 이익률이 21%p 상승했다는 뜻이 아니다.
- Mathem은 2022년 가을 도입한 통합 판촉계획 사례다. 2026년 RELEX 생성형 AI 에이전트의 실적으로 연결하면 안 된다.
- Talon.One MCP는 현재 문서상 **Closed beta / 읽기 전용**이다. 캠페인 수정·자동 발행을 현재 기능처럼 쓰면 안 된다.
- Talon.One Predict 기존 공식 제품 URL은 검증 시 `/product`로 리다이렉트되었다. 검색 색인에는 종전 설명이 남아 있지만 현재 제공 범위를 입증하지 못한다. 기사 중심 사례는 현재 확인되는 **Experiments**로 업데이트한다. 리다이렉트만으로 Predict 단종을 단정하지 않는다.

## 2. Mathem: 숫자와 분모를 정확히

RELEX가 공개한 고객 사례는 다음을 보고한다.

- 상업팀의 프로모션 기획 시간: **20% 감소**.
- 이익이 난 프로모션의 비중: **21%p 증가**. 원문은 상대 증가율 **56%**를 함께 표기한다.
- 공급망 계획자의 판촉 계획 시간 감소 55%는 별도 지표다. 상업팀의 20%와 섞지 않는다.
- Mathem은 2020년 예측·보충계획에 RELEX를 쓰기 시작했고, 2022년 가을 판촉계획을 도입했다. 도입 후 6개월 안의 결과라고 설명한다.

기사 권장 문장: “RELEX가 공개한 Mathem 사례에서는 상업팀의 판촉 기획 시간이 20% 줄었고, 이익이 난 판촉의 비중은 21%포인트 높아졌다. 다만 이는 2022년 도입한 통합 판촉계획의 공급사 공개 사례이며, 최근 AI 에이전트만의 효과는 아니다.” 고객사의 현재 규모·직원 수는 사례 작성 당시 수치일 수 있어 인용하지 않는다. [Mathem 공식 고객 사례](https://www.relexsolutions.com/resources/case-mathem/)

## 3. Talon.One: Predict보다 현재 Experiments를 중심에

### Experiments의 현재 확인 가능한 기능

2026-05-27 발표에서 모든 고객 대상 제공을 명시했다. 한 캠페인 안에 두 효과를 만들어 비교하며, 할인율과 정액할인·포인트·무혜택 대조군 등을 비교할 수 있다. 고객 프로필 ID에 따라 같은 고객이 같은 조건을 보게 한다. 승자를 독립 캠페인으로 만들 때는 **비활성 상태로 생성한 뒤 담당자가 검토하고 활성화**한다. [Experiments 공식 발표](https://www.talon.one/blog/introducing-experiments)

현재 문서는 두 변형을 비교하는 A/B 테스트로 정의한다. 익명 고객 세션은 제외되고 고객 프로필에 연결된 세션만 추적한다. 실험을 일반 방문자 전체의 전환 개선 측정으로 과장하면 안 된다. [현재 Experiments 개요](https://docs.talon.one/docs/product/campaigns/experiments/overview)

결과 화면에는 할인 전후 평균 주문금액, 평균 주문수량, 주문수, 할인 전 매출, 할인 총액, 쿠폰 사용수 등이 있다. AI는 평균 지표와 신뢰도 점수만 받아 승자·지표 간 상충·불확실성을 요약하며 개별 주문액과 개인식별정보는 받지 않는다고 설명한다. 평균 지표의 신뢰도는 Welch 양측 t-test로 계산한다. **90%는 Talon.One이 권장하는 제품 기준**이므로 모든 사업 실험의 보편적 합격선처럼 쓰지 않는다. [결과 관리 문서](https://docs.talon.one/docs/product/campaigns/experiments/manage-experiments)

해석: 결과표의 ‘할인 후 매출’은 원가·배송비·반품비 등을 차감한 공헌이익과 다르다. 이익을 목표로 삼는 기사는 비용과 반품을 별도로 연결해야 한다고 설명하는 편이 타당하다. 이는 위 지표 정의에서 도출한 작성자의 해석이다.

### Predict 최신화 주의

검색 색인에 남은 종전 공식 설명은 구매성향 예측, Next Best Offer, A/B 실험을 소개한다. 그러나 검증 시 직접 접속한 [Predict URL](https://www.talon.one/product/predict)은 [현재 제품 개요](https://www.talon.one/product)로 이동했고, 현재 제품 개요에는 Predict 항목이 없었다. 현재 정식 제공·정확도 90%·ROI 3배 등을 기사 근거로 사용하지 않는 것을 권한다. 제공 종료인지 재편인지 공개 자료만으로 확인되지 않았다.

## 6. Jev와 문맥 선별의 적용 범위

- [TypeSafe 소개](https://docs.typesafe.ai/introduction)는 상태와 유형이 정해진 질문을 받아 구조화된 판단을 반환한다고 설명한다. [Primitives 문서](https://docs.typesafe.ai/primitives)의 Choice·Score·Noul은 각각 선택지·척도·참 여부 판단이다. 기사에서는 프로모션 요청 유형, 메모 관련성, 발급·활성화 요청 여부의 작은 판단으로 적용한다.
- [Jev 1.13 한계 문서](https://docs.typesafe.ai/model-jaggedness/jev-1.13)를 직접 열어 확인한 갱신일은 **2026-10-02**. 검색 색인과 일부 미러에 남은 9월 17일보다 최신이다. 정확한 수치 계산과 날짜 비교는 코드로 수행하도록 권고하며, Choice 선택지 순서에 따른 편향도 명시한다.
- [Growth-Kinetics/jev-context](https://github.com/Growth-Kinetics/jev-context)는 제작자의 공개 README에서 Pi 에이전트의 스킬·도구 선별과 문맥 가지치기를 설명한다. 커머스 서비스나 실적 검증 자료가 아니다. 기사에서는 설계 원리만 참고하며 성능 수치를 가져오지 않는다.
- 관련성 점수는 할인 성공 확률이 아니다. 원가·예산·기간·승인 상태는 모델의 선별 대상에서 제외하고 필수 데이터로 검증해야 한다는 부분은 작성자의 제품 제안이다.

## 7. 손익 예시와 실험 설계

- 모든 가격·비용·판매량은 원문을 발전시킨 가상 예시다. 실제 고객·주문·사내 시스템 정보는 사용하지 않았다.
- 79,000원 기준가, 53,000원 개당 변동비, 판매자 전액 할인 부담. 추가 할인 없음 100개는 2,600,000원, 5,000원 할인 140개는 2,940,000원, 10,000원 할인 180개는 2,880,000원.
- 10,000원 할인 184개는 2,944,000원으로 5,000원 할인 140개보다 4,000원 많다. 예측 오차에 따라 순위가 바뀔 수 있음을 설명하며 실제 수요 예측은 수행하지 않는다.
- 계산기는 두 할인안의 판매량을 독립적으로 60~240개 사이에서 바꾼다. 가격 변경에 대한 수요 반응을 학습하거나 추정하는 도구가 아니다. 추가 할인 없음은 100개 고정. 기본 값·키보드 조작·무할인 우위·초기화를 브라우저에서 검증한다.
- 할인 후 매출에서 변동비를 뺐으면 할인액을 중복 차감하지 않는다. 비용 분담이 있으면 고객 결제금액과 판매자 정산 수입을 구분해야 한다. 세금·반품·보관비·재고 한도는 계산기에서 제외했다고 명시했다.
- [RELEX promotional pricing](https://www.relexsolutions.com/resources/promotional-pricing/)의 TrueLift 설명은 대체구매, 선구매, 연관 판매, 공급사 지원금을 구분한다. 해당 구분만 인용하고 효과 추정 정확도를 독립 검증한 것처럼 쓰지 않는다.
- 고객당 공헌이익을 비교하는 무작위 배정 실험, 처음 배정된 고객 전체 포함, 관찰 기간·중단 기준·불확실성 검토는 이 글의 제안이다. Talon.One의 세션 중심 지표가 이 평가 전체를 자동 제공한다고 서술하지 않는다.

## Jev 가이드 적용 보완 (2026-10-03)

- 사용자 요청에 따라 `guides/2026-09-30-jev-decisions.html`의 작은 판단, 세 질문 유형, 분기, 한국어 평가, 모델 교체, 총비용 관점을 본문 03·06절에 반영했다. 가이드 원문 자체는 수정하지 않았다.
- 공통 입력에 담당자 요청과 과거 행사 메모를 넣고 Choice·Score·Noul을 독립 평가하는 그림을 추가했다. 그림은 질문 설계와 사람이 정한 기대 판단이며 실제 API 응답·성능 측정이 아니다.
- 같은 요청의 질문은 다른 답을 자동 이어받지 않는다는 [Primitives 공식 설명](https://docs.typesafe.ai/primitives)을 다시 확인했다. Score의 중간값은 자체 정의 척도상의 위치이며, Noul은 ‘예’의 확률이다. 어느 값도 공헌이익 예측이나 발급 권한을 대체하지 않는다.
- [Confidence 공식 설명](https://docs.typesafe.ai/confidence)을 확인했다. Choice·Score의 분포 집중도 지표를 선택지 확률 또는 업무 정답률로 해석하지 않는다. 고정 임계값을 권장하지 않고 현지 평가로 자동 검토 범위를 정하도록 했다.
- 비교 검토·담당자 검토·판단 실패 흐름, 누락을 `noul = 0`으로 대체하지 않기, 재시도 한도, 필수 조건·권한의 코드 검증을 연결했다.
- 한국어 부정·복합 요청·금액 정정·문맥 생략 4개 사례와 기대 처리를 추가했다. 같은 데이터의 세 방식 비교, 수정용/최종 평가 데이터 분리, 같은 오분류 허용 수준에서의 자동 작성 비율, 모델·질문 변경 시 재평가, 검토서 완료까지의 총비용은 가이드를 프로모션 업무에 적용한 설계 제안이다.
- 보완 후 기사 내 로컬 링크·자산·앵커 38개와 고유 ID 25개, ARIA 참조를 검사해 오류가 없음을 확인했다. 데스크톱 1140px와 모바일 390px에서 새 그림과 평가표를 확인했다. 모바일의 판단 카드는 한 열로 표시되고 표는 자체 가로 스크롤을 사용하며, 페이지 전체 가로 넘침은 없다. CSS는 v2로 갱신했다. 계산기 동작은 수정하지 않았다.
