- 글: [ArtCraft, 에이전트와 함께 만드는 창작 도구](../case-studies/2026-11-17-artcraft.html)

- 중심 질문: 사람과 에이전트가 같은 편집 기능을 쓰고, 결과를 검사하며, 개발 자동화의 실행 범위를 통제하려면 어떤 구조가 필요한가.
- 사용자 제공 원고의 제품 구분·논지·설명 순서를 유지했다. 공식 화면을 추가 대조하고, 커머스 적용안을 입력·결과·실패 조건이 있는 미실행 실험으로 구체화했다.
- PhotoCraft 확인 커밋: `957b10cccbb4bcd402394d250e52a9b9e1b63d74`.
- AutoCraft 확인 커밋: `0bcc1f8d681609233d2f6f0d1f4e359e994079e0`.
- 공식 웹 페이지는 확인일의 상태, 위 두 저장소의 코드·문서는 고정 커밋 상태를 다룬다. 보조 저장소 README는 확인일 기본 브랜치의 제품 설명이다.
- 코드 실행·설치·호환성 및 성능 측정·운영 감사는 하지 않았다. 공개 자료의 설명과 정적 코드 확인을 분리해 서술했다. 개발 버전과 배포 버전이 같다고 가정하지 않았다.

## 사실·주장·해석·제안의 구분

- 직접 확인: 위 문서·코드와 이미지 파일의 존재 및 내용.
- 제작자 설명: 제품 지향점, 빌드 제공, Launcher 동작, 저장된 시험·평가 기록. CPU/GPU 비교와 엔진 재렌더링은 시험 코드도 직접 읽었으며 실행 결과는 확인하지 않았다.
- 작성자 해석: 공통 엔진은 화면과 에이전트의 기능 재사용을 돕고, 공통 라이브러리는 여러 제품의 반복 유지보수를 줄이려는 선택이라는 해석.
- 미실행 제안: 이미지 20장 × 3규격 = 최대 60파일을 대상으로 한 수동·명령·에이전트 처리 비교. 완료 수는 검수 통과 결과로 집계하도록 제안.
- 실측하지 않은 비용·시간·효율 향상 수치는 추가하지 않았다. 이번 글의 적용안은 비용 산정 예시가 아니다.
- 직접 하지 않은 일: 앱 설치·실행, PSD 시험, GPU 성능 비교, AutoCraft 운영·병합, 외부 저장소 변경, Git 커밋·푸시·배포.

## 사이트 반영

- 새 본문, 전용 CSS, 이미지 2개, 미디어 출처, 이 조사 기록.
- 사례연구 목록 총 10편, 최신 사례 10으로 등록.
- 홈의 사례연구 카드만 갱신. 공통 CSS·JS와 다른 콘텐츠 카드는 변경하지 않음.
- 전용 JavaScript나 API 호출 없음. 도식은 정적 HTML/CSS.
- 루트 README는 개별 글을 추가하지 않는 현행 저장소 지침을 따름.

## 검증 기록

- `node --test`: 기존 테스트 71개 통과, 실패·생략 0개. 콘텐츠 갱신·읽음 상태 관련 시험을 포함한다. 이 결과는 PhotoCraft나 AutoCraft의 제품 시험 결과가 아니다.
- `git diff --check`: 통과. 새 본문의 태그 중첩, 중복 ID, 목차 앵커, 본문·홈·목록의 상대 링크 및 자산 존재, noindex, theme.js 순서, 이미지 alt·크기 속성을 별도 정적 검사했다.
- 목록 카드 10개, 새 글 1회 등록, 홈 연결 1회, 사례연구 10과 날짜 일치를 확인했다.
- 새 본문·전용 CSS·조사 기록에서 개인 대화 URL, 개인 로컬 경로, TODO/TBD, 엠대시가 검출되지 않았다.
- loopback 전용 로컬 서버에서 본문·목록·홈을 확인했다. 루트 경로와 `/hello-human/` 하위 경로 모두 확인했다. 서버는 공개 페이지·자산만 제공하고 숨김 경로와 개발 자료를 허용하지 않도록 구성했다.
- 브라우저 기본 CSS 뷰포트 폭 914px, 모바일 폭 390px·320px에서 확인했다. 세 폭 모두 페이지 전체 가로 넘침이 없었다. 데스크톱과 모바일 각각 라이트·다크 상태를 확인했다.
- 390px의 엔진 도식은 한 열로 배치된다. 320px 표는 본문을 밀어내지 않고 내부에서 스크롤된다. 포커스 테두리와 오른쪽 화살표 키에 의한 표의 가로 이동을 확인했다.
- 공식 이미지 2개가 원본 크기(2400×1500, 1148×1425)로 로딩됨을 브라우저에서 확인했다. 두 번째 이미지는 지연 로딩이므로 해당 절로 이동한 뒤 확인했다. 본문·홈·목록의 이미지와 캡션을 시각 확인했다.
- 목차의 엔진·AutoCraft 절 이동, 본문→목록 복귀, 목록 새로고침을 확인했다. 읽은 글에 New/Updated가 남지 않았다. 프로젝트 하위 경로에서도 홈 카드의 Enter 키 활성화→본문→목록 복귀가 정상 동작했다.
- 홈 카드의 자동 마우스 클릭은 브라우저 도구의 노드 위치 오류로 완료하지 못했다. 같은 카드의 키보드 Enter 이동은 성공했다. 마우스 클릭을 검증했다고 쓰지 않는다.
- 검토 시 본문 브라우저 오류 로그는 비어 있었다. 임시 뷰포트 설정은 해제하고 본문 미리보기 탭을 남겼다.
- 새 JavaScript·API 호출·영상은 없다. 앱 실행·호환성·성능·운영 시험은 미실행이며, 커머스 실험 역시 제안 상태다.
- 커밋·푸시·배포는 하지 않았다.

## 원고 재검토 (2026-11-17)

- 공식 홈·PhotoCraft·Studio 소개와 고정 커밋의 근거를 다시 대조했다. 제품군의 개발 단계, 배치 실행의 부분 성공, 평가 기준일과 높은 시스템 부하, 모의 대시보드, 미실행 커머스 제안이라는 구분을 유지했다.
- `craft-psd`의 파일 보존과 PhotoCraft 앱의 재저장을 더 분명히 구분했다. README는 앱이 이미지·레이어·합성 정보를 다시 쓰므로 원본과 바이트 단위로 같지 않다고 설명한다.
- GPU 비교 시험과 엔진의 Photoshop 재렌더링 시험을 직접 읽고 본문에 고정 커밋 링크를 추가했다. GPU 시험은 허용 오차 내 결과를 비교하며, GPU를 구할 수 없는 환경에서는 설정에 따라 생략하거나 실패한다. 파일 첫 주석의 2/255와 실제 `TOL` 상수의 1/255 + 부동소수점 여유가 달라 본문에는 임계 수치를 인용하지 않았다.
- 엔진 재렌더링 시험은 캐시를 사용한 I/O 시험과 달리 스마트 오브젝트와 글자를 자체 엔진으로 다시 그린다. 글자 비교에는 시험용 폰트 설치가 필요하다는 조건을 반영했다. 시험 코드의 존재를 통과 결과로 표현하지 않았다.
- AutoCraft의 이름 지정 검사 예외를 구체화했다. 진행 중 검사와 실패 검사 예외가 있으며, 실패 예외로 필수 검사 실패에 따른 GitHub의 병합 차단을 우회하지 않는다.
- 제품 역할표 뒤의 반복 설명, 추상적인 연결 문장, 같은 주의사항의 중복, 이미지 확대 안내를 줄였다. 미디어 보존 방식·재사용 조건 미확인 상태는 이 조사 기록에 남겼다.
- 수정 후 본문·홈·목록의 HTML 중첩, 중복 ID, 상대 링크, 본문 목차, 이미지 속성, robots, theme.js 순서, 새 근거 링크를 정적 검사했다. 새 본문 공백 검사와 `git diff --check`도 통과했다.
- 로컬 미리보기에서 수정한 호환성·AutoCraft 본문을 읽고 데스크톱 호환성 카드와 모바일 검사 카드를 시각 확인했다. CSS 뷰포트 1257px·390px에서 페이지 가로 넘침이 없었고, 모바일 호환성 카드 내부에도 가로 넘침이 없었다. 브라우저 오류 로그는 비어 있었다. 임시 뷰포트 설정을 해제했다.
- 이번 재검토는 본문과 조사 기록만 수정했다. 기존 JavaScript 테스트는 다시 실행하지 않았다. PhotoCraft·AutoCraft 설치·실행이나 제품 시험도 수행하지 않았다. 커밋·푸시·배포하지 않았다.
