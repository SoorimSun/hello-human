## 편집 판단

- 제목은 ‘AI 네이티브 실무 가이드, 반복 업무 하나부터 바꾸기’. H1, title, OG, 목록, 홈을 맞춘다.
- 원문 읽기는 사용자가 지정한 Google Drive 뷰어로 연결하고, 판본 이력은 저자의 공식 저장소로 연결한다. 원문 그림·표·페이지를 재편집하거나 저장소에 복제하지 않는다. 본문 실습 자료·작업지·도식은 헬로우 휴먼이 구성했다.
- 상품 사례는 공급사 명세서에 **판매 구성 1개**를 명시한다. 제품 사양과 판매 묶음을 혼동하지 않도록 한다.
- 기대 답안에는 용량·수량 불일치, 보온 근거 부족, 세척법 누락의 네 문제와 정상인 색상을 포함한다. ‘근거 없음’과 ‘성능 없음’을 구별한다.
- 한 사례의 통과를 운영 가능 판정으로 쓰지 않는다. 5~10건은 입문 연습 제안일 뿐 통계적 신뢰도나 최소 운영 표본 기준이 아니다.
- 추가 연습 5건은 정상·용량 오류·필수 정보 누락·성능 근거 부족·기준 문서 충돌을 포함한다. 정답을 AI 입력과 분리하고, 수정에 쓰지 않은 사례로 확인하도록 한다.
- 18분 → 14분, 4분 절약은 가상 계산이다. 이 작업이나 실제 AI 모델의 실행 시간을 측정한 기록이 아니다.
- 사람이 검토할 시간과 재시도 비용도 포함한다. 완료 0건의 나눗셈, 같은 업무 재시도의 중복 집계를 피하도록 안내한다.
- 모든 직무가 읽을 수 있도록 본문 실습은 상품정보 검수로 통일하고, 개발·QA·운영·PM 적용 예시를 연결한다.
- 개념의 근거는 저자의 원문과 공식 기술 문서로 확인한다. 커뮤니티 논의는 출처로 인용하지 않는다.

## 검증 상태

원문 확인과 기대 답안 대조를 마쳤다. 특정 외부 모델에 이 프롬프트를 실행해 성능을 측정한 것은 아니다.

- `node --test --test-reporter=dot` 통과, `git diff --check` 통과.
- 본문·목록·홈의 HTML 중첩, 고유 ID, 목차 앵커, 로컬 경로, 외부 링크 속성 확인.
- 제목·날짜·GUIDE 10·목록 10편 일치. 대화 전용 인용 토큰, 비공개 대화 링크, 엠대시가 본문에 없는지 확인.
- Edge에서 1440·768·390·320px 가로 넘침 없음. 데스크톱·모바일·다크 모드 화면 캡처 확인.
- 최초 작성 시 요청문 두 개의 클립보드 내용과 TXT 파일을 본문과 대조. Windows 클립보드의 CRLF는 LF로 정규화해 비교. 재검토에서 추가한 공통 요청문은 아래 재검증 기록을 따른다.
- 클립보드 권한이 막히면 본문 선택과 직접 복사·파일 다운로드 안내가 나오는지 확인.
- 기대 결과 펼치기, 기록지 내려받기, 홈 → 본문과 가이드 목록 연결 확인.
- 복사·답안 펼치기 뒤 목록 복귀와 새로고침에서 해당 글에 잘못된 Updated 배지가 붙지 않음.
- 자바스크립트를 꺼도 여섯 장의 본문과 자료를 읽고 기대 답안을 펼칠 수 있음.
- 확인한 페이지에서 로컬 HTTP 오류와 브라우저 실행 오류 없음.
- 사용자 요청에 따라 커밋·푸시·배포하지 않고 로컬 변경으로 남김.

## 초보 독자 관점 재검토 (2026-10-23)

사용자 요청으로 처음 읽는 멤버의 실행 순서와 용어를 다시 검토했다. 실제 멤버 대상 사용성 테스트를 수행한 것은 아니다.

- 시작 단계에 도구 선택·붙여 넣을 위치·완료 후 행동이 부족했다. 새 대화 → 자료 복사 → 붙여 넣어 전송 → 답안 비교·저장의 네 단계로 명시했다. 별도 파일 첨부나 빈칸 입력 없이 첫 실습을 실행하도록 ‘첨부한 자료’를 ‘아래 제공한 가상 자료’로 수정했다.
- AI 네이티브, 요청문, 명세서, QA·PM과 TXT·MD를 첫 사용 지점에서 풀어 썼다. 네 단계 개념, 개발 전용 예시, 시스템 연결 설명은 필요할 때 펼치도록 바꿨다.
- 다른 직무를 위한 실제 요청문이 없어 공통 양식과 회의록 작성 예시를 추가했다. 기록지에도 작성 예시와 추가 사례 교체 순서를 보완했다.
- 검수표 작성 완료와 상품 게시 완료를 구분했다. 답이 기대 결과와 다른 경우의 후속 요청 예시와 저장할 결과물을 추가했다.
- [사용자가 지정한 Google Drive 원문](https://drive.google.com/file/d/1Kve5XiR8kMN260Uc0BW6eeoQi4cJzptA/view)을 비로그인 브라우저에서 열어 407쪽 문서와 114페이지의 ‘AI 네이티브란 무엇인가’를 확인했다. 본문의 원문 링크는 이 읽기 화면으로 통일하고 다운로드 직링크를 제거했다. 읽을 부분 표에는 책 하단 쪽수와 뷰어 입력 번호를 함께 표시했다. 연구 기록의 고정 판본 PDF URL은 근거 추적용으로 유지한다.

### 수정 후 재검증

- 저장소 테스트와 `git diff --check` 통과. HTML 중첩·고유 ID·로컬 경로·목차 앵커·외부 링크 속성을 다시 확인했다.
- 본문의 요청문 세 개와 각 TXT 파일, 로컬 서버가 제공하는 파일 내용이 일치한다. 브라우저에서 세 복사 버튼의 완료 안내를 확인했다. 이번 검토 도구에서는 클립보드 원문을 읽지 못해 실제 붙여 넣은 내용까지 재검증했다고 판단하지 않았다.
- 인앱 브라우저의 320·390·768·1440px 화면 너비에서 가로 넘침이 없었다. 밝은 화면·다크 모드와 접힌 추가 설명, 기대 답안 펼치기를 확인했다. 브라우저 오류·경고 로그는 없었다.
- 본문의 원문 링크 다섯 개가 모두 요청한 Google Drive `/view` 주소를 사용하며, 원문 PDF 다운로드 직링크가 남아 있지 않음을 확인했다.
- 커밋·푸시·배포는 하지 않았다.

## 원문 관점과 자체 실습의 구분 보강 (2026-10-23)

사용자 요청에 따라 원문의 관점을 바탕으로 재구성한 가이드임을 도입부에 명시했다. 반복 업무 실습의 이유와 판단 기준을 이해하도록 업무 적용에 필요한 핵심 개념을 본문에 모았다. 후속 편집에서는 독서 생략을 강조하는 표현을 빼고, 개념의 배경과 다양한 적용 사례를 원문에서도 함께 살펴보도록 권했다.

### 원문 재대조와 반영

| 가이드의 핵심 설명 | v1.0 책 하단 쪽수 | 반영 범위 |
| --- | --- | --- |
| 핵심 가치와 피드백을 통한 개선이 함께 필요함 | 113~114, 127 | AI 기능 수·사용량과 구별. 기록이 쌓이면 저절로 개선된다는 해석 배제 |
| Ready·Enabled·First·Native | 119~127 | 준비·보조·흐름 재설계·핵심 가치 결합으로 풀어 쓰고, 업무별로 적합한 단계가 다름을 설명 |
| 업무 전체의 결과와 완료 건당 비용 | 88~92, 122~126 | 기준선, 검토·수정·실패 비용, 전체 완료 시간을 포함 |
| 질문·검증·책임·복구 역량 | 182~186 | 기대 결과와 확인 방법을 함께 정하고, 원본·계산·테스트로 확인하는 습관 |
| AI 제거 테스트의 네 축 | 146~147 | 고객 가치·운영 부담·복원력·차별화와 학습. AI에 의존하는 것 자체를 성공으로 간주하지 않음 |

- 위 설명은 원문의 개념을 재서술했다. 원문 문단·그림을 전재하거나 저자의 사례를 우리 사례로 바꾸어 소개하지 않는다.
- 핵심 개념은 접힌 설명에서 꺼내 독립 목차로 노출했다. 네 단계 표는 원문의 뜻만 정리하며, 실습의 단계 해석은 별도의 ‘헬로우 휴먼의 적용’ 안내에 넣었다.
- 도입부에 ‘원문 핵심 / 헬로우 휴먼 실습 / 보충 자료’의 출처 구분을 추가했다. 각 실습 장·대표 도식·시간 계산·5일 계획·다운로드 양식에도 자체 구성임을 표시했다.
- 상품 검수는 Ready·Enabled에서 시작하는 연습으로 설명한다. 한 번의 실습 성공을 AI Native 전환의 증거로 표현하지 않는다.
- Anthropic의 평가·워크플로 설명과 MCP 구조 설명은 보충 자료로 명시했다. 참고 자료 목록도 원문과 보충 자료로 나눴다.
- 홈·목록·본문 메타 소개와 내려받는 기록지에도 원문 관점과 자체 적용 예시의 구분을 맞췄다. 요청문 내용과 복사 스크립트는 변경하지 않았다.

### 보강 후 확인

- 저장소 테스트 통과. HTML 중첩·ID·목차·로컬 파일·외부 링크 속성·원문 읽기 주소, 본문과 TXT 요청문 세 개의 일치, 로컬 서버 제공 내용을 확인했다.
- 인앱 브라우저 320·390·768·1440px에서 페이지 가로 넘침이 없었다. 320px에서도 원문 네 단계 표가 가로 스크롤 없이 표시되며 영문 단계 이름이 단어 중간에서 끊기지 않도록 조정했다.
- 도입부의 출처 구분과 핵심 개념이 접히지 않고 읽히는지, 밝은 화면·다크 모드에서 구분 표기가 읽히는지 화면으로 확인했다. 브라우저 오류·경고 로그는 없었다.
- 실제 멤버 대상 이해도 테스트나 모델 성능 실험을 새로 수행한 것은 아니다. 커밋·푸시·배포하지 않았다.

## 최종 발행 전 확인 (2026-10-23)

- 사용자가 전체 검토 후 문제가 없으면 푸시하도록 명시적으로 승인했다. 앞선 푸시 보류는 이 승인으로 해제됐다.
- 별도 읽기 전용 리뷰에서 본문·다운로드·홈·목록·CSS·JS와 원문 근거 쪽을 대조했다. 내용상 발행을 막는 문제는 없었고, README 문체 규칙에 맞춰 굵은 항목명 뒤 콜론 일곱 개를 제거했다.
- 저장소 테스트 71개 통과. 세 HTML 페이지의 중첩·고유 ID·목차·로컬 경로·자산 응답, 제목·날짜·가이드 10편, 외부 링크 속성과 원문 읽기 주소를 확인했다. 요청문 세 개와 TXT, 로컬 서버 제공 내용도 일치한다.
- 1440·768·390·320px에서 페이지 가로 넘침 없음. 밝은 화면과 다크 모드에서 표지·실습·평가표·비용 도식·팀 운영 흐름·실행 계획을 확인했다. 넓은 실습 표는 작은 화면에서 표 영역 안에서 가로로 스크롤된다.
- 복사 버튼 세 개의 완료 안내, 기대 답안 펼치기, 홈·목록·본문 이동을 확인했다. 최종 본문을 읽고 복사·펼치기 후 목록으로 돌아가 새로고침해도 잘못된 Updated 표시가 붙지 않았다. 브라우저 오류·경고 로그는 없었다.
