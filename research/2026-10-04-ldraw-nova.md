## 이미지·시각화

assets/case-studies/README.md의 사례연구 04 항목에 원본 경로와 사용 범위를 기록했다. PNG 4종은 특정 커밋의 원본 바이트를 보존한다. 대표·수정 전후·정면·창문 이미지에 출처와 날짜를 표시한다.

설명용 창문 간격은 첫 좌표 120, 간격 100~200, 3개 중심 좌표로 구성한 임의 예시다. 실제 제품 실행·LDraw 좌표 검증이나 물리 시뮬레이션으로 표시하지 않는다.

생성 과정, 모듈 구조, 검색과 사용 판단, 검사 상태는 설명용 도식이다. 전시모듈 적용 제안과 구성 전환 도식은 헬로우 휴먼의 가상 설계이며 제품 기능·실제 효과로 쓰지 않는다.

## 전시모듈 적용 제안 보완 (2026-10-04)

- 기존 할인 설정 예시를 매장 → 전시모듈 → 컴포넌트 구조에 적용하는 07~09절로 교체했다. 결론은 10절로 이동했다.
- 사용자가 제공한 동적 로딩 가이드와 프런트엔드 구현을 대조했다. 가이드의 예전 예시보다 현재 구현을 우선했다. 서비스의 공개 화면은 화면 구성 참고용으로 확인했다. 화면 관찰만으로 내부 구성 방식이나 AI 기능을 입증하지 않는다.
- 공개 파일에는 회사·시스템명, 소스 경로, 내부 모듈 식별자, API 경로, 실제 코드·상품 데이터·화면 캡처를 옮기지 않았다. 아래 내용은 재사용 가능한 구조로 일반화했다.

| 관찰한 구조 | 글에 반영한 설계 판단 | 확인 범위·한계 |
| --- | --- | --- |
| 모듈 식별자로 등록된 구현을 조회하고, 콘텐츠 묶음을 모듈 입력으로 변환해 렌더링한다. | 기존 모듈 선택·순서·콘텐츠 계획을 첫 단계로 삼는다. | 임의의 컴포넌트 트리를 해석하는 범용 실행기가 이미 있다는 의미는 아니다. |
| 매장별 화면은 공통 모듈 영역과 전용 영역을 함께 구성한다. | 템플릿별 고정 영역·허용 위치를 조합 규칙에 포함한다. | 고정 영역의 위치나 구성이 모든 매장에서 같다고 일반화하지 않는다. |
| 살펴본 모듈은 배너·상품 목록·탭을 코드로 조합하며 입력, 상태, 행동을 연결한다. | 새 모듈 코드 제작과 설정 기반 동적 조합을 별도 단계로 구분한다. | 모든 화면 컴포넌트가 독립적으로 재사용 가능하다고 주장하지 않는다. |
| 일부 모듈은 탭·배너·상품의 부모 자식 연결, 찜 상태, 화면 문맥과 측정 정보를 사용한다. | 데이터뿐 아니라 상태·행동·측정의 연결 조건을 부품 설명서에 넣는다. | 화면이 렌더링됐다는 사실로 기능의 정상 동작을 보증하지 않는다. |
| 빈 콘텐츠·일부 연결 오류를 걸러내거나 렌더링을 생략하는 경로가 있다. | 미리보기에서 숨겨진 모듈·데이터 부족의 이유도 확인하도록 제안한다. | 기존 검사가 모든 모듈 계약·콘텐츠 조건을 검증한다는 뜻은 아니다. |
| 미리보기와 조회 문맥을 전달하는 프런트엔드 경로를 확인했다. | 기준 시점·문맥을 맞춘 미리보기와 재현 가능한 검토를 제안한다. | 백엔드 콘텐츠 선정, 운영 설정의 저장·승인·예약·복구는 확인하지 않았다. |

### 가상 예시의 경계

- 비교 도식은 미리 작성한 두 계획(브랜드 신상품 소개, 키즈 주말 기획전)을 전환한다. AI를 호출하거나 실제 상품·재고 API를 실행하지 않는다.
- 브랜드 예시는 3개 중 1개가 품절이면 2개로 축소한다. 기획전 예시는 동일 범위의 유효한 예비 상품이 있다고 가정해 1개를 충원한다. 이는 실제 운영 정책이 아니다.
- 본문 JSON은 새로운 조합 설계를 설명하는 의사 설정이다. 현행 입력 형식이나 즉시 사용할 수 있는 구현으로 표시하지 않는다.
- 콘텐츠 정책 등록·실행, 조합 실행기, 설정 초안 저장·승인·반영·복구는 필요한 개발·통합 과제다. 프런트엔드 소스만으로 준비 여부를 단정하지 않는다.
- 첫 실험의 기존 모듈 5개 안팎·새 조합 1개는 권장 범위이며 측정 결과가 아니다. 매출 효과는 별도 비교 실험이 필요하다.

## 로컬 결과 검증

- 기존 Node 테스트 7개 통과. 새 전용 스크립트의 구문 검사와 git diff 공백 검사 통과.
- 홈·목록·본문의 로컬 파일 링크, 내부 앵커, 중복 ID 검사 통과.
- PNG 4종의 Git blob SHA-1이 원본 저장소 트리와 일치. 모두 1000×800.
- 브라우저에서 1280px 데스크톱, 390px·320px 모바일 폭 확인. 가로 넘침 없음.
- 라이트·다크 모드 확인. 원본 이미지 5개 표시 위치 모두 로드 확인.
- 간격 100과 200에서 중심 좌표가 각각 120·220·320, 120·320·520으로 갱신됨. SVG 배치·출력·접근성 설명 일치.
- JSON 펼치기 동작 확인. 도식 조작 후 목록 이동·새로고침 시 해당 글에 잘못된 Updated 표시가 붙지 않음.
- 홈의 최신 사례연구 링크, 사례연구 목록의 04 편수와 새 글 연결 확인.

### 전시모듈 제안 보완 후 확인

- 기존 Node 테스트 7개, 전용 스크립트 구문 검사, 공백 검사 통과.
- 홈·목록·본문의 로컬 링크, 내부 앵커, 중복 ID, noindex, 01~10 절 번호 확인.
- 데스크톱과 390px·320px 폭에서 새 도식의 가로 넘침 없음. 라이트·다크 모드 배치 확인.
- 브랜드형에서 품절 시 3개→2개로 축소, 기획전형에서 같은 조건의 예비 상품 1개 표시, 체크 해제 시 정상 예시로 복귀 확인.
- 새 설정 예시 펼치기와 닫기 지원. 화면 구성 전환은 실제 API 없이 설명용 데이터만 변경한다.
- 도식 조작 뒤 목록으로 돌아가 새로고침해도 해당 글에 잘못된 Updated 표시가 생기지 않음을 확인했다.
- 제품 소스·운영 데이터·백엔드는 수정하거나 실행하지 않았다. 제안의 운영 성과와 제품 통합은 검증 범위에 포함되지 않는다.
