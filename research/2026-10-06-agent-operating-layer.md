## 해석·설계와 원문 사실의 경계

- 모델 경쟁에 운영 계층 경쟁이 겹친다는 것은 헬로우 휴먼의 종합 해석이다.
- 문맥 메모리와 업무 완료 상태, 알림과 실행 중단, 도구 호출 횟수와 금액 예산을 구분했다.
- 초안의 일렬 구조 대신 실행 환경이 모델 응답과 도구 실행을 조율하는 설명용 개념도를 썼다. 특정 공급사 내부 아키텍처로 표시하지 않았다.
- API·DB 예시는 일반화했다. 사내 자료·이름·실제 코드·개인 대화는 사용하지 않았다.
- 20개 작업 비교는 미실행 제안이다. 동일 초기 상태·완료 기준·재시도 조건을 고정하고, 전체 작업당 비용과 성공 작업당 비용의 분모를 구분했다. 성공 0건도 처리했다.
- 실제 제품 화면을 복제하거나 가상 UI를 실제 화면으로 표시하지 않았다. 원본 예시는 Reflection 공식 데모 페이지로 연결했다.
- 저장소 지침에 따라 README와 파일 구성 문서에 개별 기사 항목을 추가하지 않았다. 뉴스 목록·홈에서 새 글을 관리한다.

## 확인 범위의 한계

- 열어 본 공식 자료만으로 Together의 현재 라우팅 동작 불일치를 해소하지 못했다. 문서에 기재된 Anthropic 경로도 Claude 계열 세션에 한정했다.
- 검색에 v0.90.4라는 제3자 알림이 있었지만 해당 GitHub 페이지에서 릴리스 본문을 확인하지 못했다. 최신 버전이라는 표현을 쓰지 않고 고정된 v0.90.3과 10월 5일 주간 정리만 근거로 사용했다.
- 독립 성능 평가·실제 비용 실험을 했다고 주장하지 않는다. 발표의 사실성과 제품의 성능 보장은 다르다.

## 결과물 검증

- `node --test` 7개 통과, `git diff --check` 통과.
- 기사·뉴스 목록·홈의 로컬 파일과 앵커 연결, 중복 ID, 새 기사 중복 등록, ISSUE 08·10월 6일·noindex를 검사했다.
- 정적 목록과 브라우저 필터 모두 총 13편, 일반뉴스 8편, 단신 5편이다.
- 브라우저에서 데스크톱과 좁은 모바일 화면, 라이트·다크 테마, 도식 배치, 목차 이동, 상세 설명의 키보드 펼치기를 확인했다. 검사한 화면에 가로 넘침은 없었다.
- 기사 상세 설명 조작 후 목록으로 돌아가고 새로고침해도 읽은 기사에 New/Updated 표시가 생기지 않았다. 필터의 방향키 이동과 홈 최신 기사 링크도 확인했다.
- 새 JS·외부 패키지를 추가하지 않았다. 인쇄와 실제 터치 기기, 공급사 제품 실행은 별도로 시험하지 않았다.
