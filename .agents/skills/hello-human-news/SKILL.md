# 헬로우 휴먼 일반뉴스

동호회 멤버가 AI 소식을 편하게 읽고 자신의 업무와 연결할 수 있는 일반뉴스를 만든다. 여러 소식의 맥락을 설명하되, 사실·발표사 주장·우리의 해석을 구분한다. 사용자가 원고만 요청하면 원고만, 사이트 반영을 요청하면 이 프로젝트의 정적 HTML까지 완성한다.

## 시작하기

- 프로젝트 루트의 `README.md`, 적용되는 `AGENTS.md`, `git status --short`를 확인한다. 이 문서의 저장소 경로는 모두 프로젝트 루트 기준이다.
- `news/index.html`, `index.html`의 `#ai-news`, 최근 일반뉴스를 읽어 현재 구조와 문체를 따른다. 호수·편수·날짜·자산 버전은 예전 작업에서 기억한 값을 쓰지 않는다.
- 사용자가 제공한 초안·첨부·링크와 수정 요청을 함께 읽는다. 주제와 의도가 충분하면 진행하고, 자료가 없고 주제도 정해지지 않았다면 범위나 관심사를 짧게 확인한다.
- 기존 기사 수정은 해당 문단과 연결된 요약·도식·출처를 중심으로 한다. 요청 없이 새 호를 만들거나 발행일·호수를 바꾸지 않는다.

## 조사에서 기사까지

1. **최신 근거 확보.** 원문 발표, 공식 제품 문서, 릴리스 기록을 실제로 열어 확인한다. 후속 수정·반박·출시 여부도 찾는다. 제공된 초안과 검색 결과 요약만으로 사실을 확정하지 않는다. 발표일·사건 발생일·통계 기준일·확인일을 구분한다.
2. **주장별 검증 기록.** `research/YYYY-MM-DD-slug.md`에 핵심 주장, 주체·대상·단위·시점, 근거 URL, 확인 상태, 기사에 쓸 표현과 한계를 남긴다. 유효한 공식 한국어 원문을 우선하되 최신 세부 내용이 영문에만 있으면 영문을 근거로 쓴다. 확인하지 못한 내용은 범위를 밝히거나 제외하고, 조사하지 않았는데 최신화했다고 쓰지 않는다.
3. **읽기 쉬운 구성.** 제목·부제, 짧은 요약, 주제별 본문, 모임 관점, 읽은 자료의 흐름을 기본으로 삼되 소재에 맞게 줄이거나 바꾼다. 주제마다 ‘무슨 소식인가 → 실제로 무엇을 하나 → 왜 중요한가 → 어디까지 확인됐나’를 풀어 쓴다. 소식을 억지로 하나의 기술이나 결론으로 묶지 않는다.
4. **독자의 이해를 돕는 화면.** 수량은 그래프, 순서는 흐름도, 시점은 타임라인, 제품 사용 모습은 원본 화면·동영상으로 설명한다. 장식보다 이해에 도움이 되는 시각화를 고른다. 작성 전에 [편집·미디어 기준](references/editorial.md)을 읽는다.
5. **사이트 반영과 확인.** HTML을 만드는 경우 [저장소 반영 절차](references/site-workflow.md)를 따라 기사·목록·홈·출처 기록을 함께 맞추고 브라우저에서 확인한다.

## 편집에서 지킬 구분

- 기업의 일반 업무에 AI 모델을 연결한 사례와 개발자의 코딩 도구 도입을 구분한다. 같은 발표에 있어도 제품, 사용자, 업무, 운영 상태가 다르면 문단과 수치를 나눈다. 코딩 가이드 연결은 해당 맥락에만 둔다.
- 현재 운영 실적과 미래 목표는 제목·그래프 라벨·캡션에서 구분한다. 이용량은 생산성 향상률이 아니며, 요청 분류는 업무 완결 처리가 아니다.
- 기존의 유용한 그래프는 수정 시 먼저 살릴 방법을 찾는다. 맥락이 다르면 옮기고 라벨·설명을 바로잡는다. 근거가 잘못된 시각화는 수정하거나 대체하며, 의미 있는 수치가 없으면 그래프를 억지로 만들지 않는다.
- 공급사의 선정 데모, 직접 체험, 설명용 도식, 모임의 실험 제안은 서로 다르게 표시한다. 하지 않은 실험이나 성능 측정을 했다고 쓰지 않는다.
- 전문용어는 첫 등장에 쉬운 설명을 붙인다. 한국어 존댓말과 짧은 문단을 쓰고, 독자가 개발자라고 가정하지 않는다. 일반뉴스를 설치 튜토리얼로 바꾸지 않는다.
- 공개 저장소이므로 실제 사내 데이터·내부 URL·개인정보 대신 가상 사례를 쓴다. `noindex`는 접근 통제가 아니다.

## 완료와 권한

기본 완료 지점은 검토 가능한 로컬 결과물이다. 커밋·푸시·배포는 각각 사용자가 명시적으로 요청한 범위에서만 수행한다. ‘커밋해줘’는 푸시 허가가 아니며, 기사 작성 요청도 원격 게시 허가가 아니다.

마지막에는 결과 파일 또는 확인된 미리보기 링크, 주요 수정, 실제 수행한 검증과 남은 확인 사항을 짧게 알린다. 브라우저 검증을 못 했다면 그 사실을 밝힌다.
