# 편집·시각화·원본 미디어

## 근거를 읽는 기준

조사 노트에는 확인일과 다음 항목을 남긴다. 정해진 소식 수나 출처 개수를 채우기보다 기사 핵심 주장의 근거를 확보한다.

| 항목 | 기록할 내용 |
| --- | --- |
| 주장 | 원고에 넣을 기능·수치·사건 |
| 범위 | 발표 주체, 제품, 사용자·업무, 현재 운영·실험·예정 여부 |
| 기준 | 날짜, 단위, 분모, 평가 조건 |
| 근거 | 직접 확인한 원문 URL, 관련 문단·릴리스·업데이트 |
| 상태 | 확인된 발표, 공급사 주장, 독립 검증, 미확인 |
| 편집 판단 | 사용할 표현, 빠뜨리면 오해하는 조건, 제외 이유 |

- 공식 발표는 ‘그 회사가 이렇게 발표했다’는 근거다. 공급사 수치를 독립 검증으로 바꾸지 않는다. 같은 보도자료를 재인용한 기사 여러 개도 독립 측정이 아니다.
- 모델 계열 발표와 개별 기능 출시, 공개 예정과 실제 제공, 오픈 가중치와 오픈소스 라이선스를 구분한다. 요금·라이선스·접근 범위는 필요할 때 최신 공식 문서를 확인한다.
- 사고 기사에서는 의혹·접근 시도·통보·확정된 침해를 구분한다. 조사한 데이터의 양을 유출량으로 쓰지 않는다. 확인되지 않은 피해를 부정하거나 확정하지 않는다.
- 논쟁 중인 사실은 당사자 설명과 확인 가능한 독립 자료를 함께 살핀다. 접근 제한이나 번역 지연으로 확인 범위가 좁다면 그 한계를 기록한다.
- 주요 근거 링크는 관련 문장 가까이에 두고 마지막 출처 목록에도 정리한다. 내부 검색 도구의 참조 ID는 최종 HTML에 넣지 않는다.

## 기사 흐름

소식에 공통 변화가 있으면 제목에서 구체적으로 요약한다. 공통점이 약하면 주요 소식을 제목으로 삼고, 부제에 나머지 제품·업무를 알린다. 짧은 요약 다음에는 각 소식을 사실, 쉬운 업무 예시, 의미, 한계 순으로 설명한다. 기술 세부 설명은 필요한 곳에서만 별도 문단이나 `details`로 둔다.

‘헬로우 휴먼의 해석’이나 ‘모임에서 해볼 실험’은 원문 사실과 구분한다. 업무 연결이 자연스러울 때 가상 자료로 시도할 작은 실험을 제안하고, 실제 사내 업무를 이미 시험한 것처럼 표현하지 않는다. 모든 뉴스에 코딩 실습이나 커머스 예시를 강제로 붙이지 않는다.

엠대시를 쓰지 않는다. 굵기·서체로 이미 구분된 항목명 뒤에는 불필요한 콜론을 붙이지 않는다. 장문의 경고만 반복하지 말고 핵심 조건을 해당 주장 바로 옆에 둔다.

## 시각화 선택

| 이해할 대상 | 적절한 표현 | 반드시 드러낼 것 |
| --- | --- | --- |
| 비율·규모 | 막대·수치 묶음 | 단위·분모·시점·발표 주체 |
| 향후 도입 계획 | 목표 막대·목표선 | 대상 집단, 목표 시점, 현재 실적 아님 |
| 업무 처리 | 입력 → AI 처리 → 사람 확인 → 결과 | 실제 발표 범위와 설명용 보완 구분 |
| 사건 전개 | 날짜가 있는 타임라인 | 발생·발표·업데이트의 차이 |
| 제품 편집 기능 | 공식 편집 전후 비교 | 같은 데모의 입력·출력, 공급사 선정 사례 |
| 동작 원리 | 설명용 개념도 | 실제 UI·내부 설계도·성능 실험이 아님 |

수치의 단위나 대상이 다르면 같은 축에 올리지 않는다. 실제 측정값 없이 성능 비교 막대를 만들지 않는다. 목표를 달성률처럼 보이게 하는 라벨은 제목과 접근성 설명까지 함께 고친다.

예를 들어 은행의 이메일 분류·지식 검색과 개발자의 코딩 도구 계획이 함께 발표됐다면, 일반 업무를 본문 중심에 둔다. 개발자 목표 그래프는 별도 계획 영역으로 분리하고 ‘연말 개발자 도입 목표, 현재 사용률 아님’이라고 표시한다. 사용자가 좋아한 그래프를 단순히 없애는 것으로 내용 혼선을 해결하지 않는다.

화면 구조는 기존 기사 스타일을 따른다. 도식의 텍스트를 읽을 수 있게 하고, 색상만으로 의미를 전달하지 않는다. 모바일에서 순서가 유지되도록 재배치하며 가로 넘침과 겹침을 확인한다. 라이트·다크 모드에서 축·범례·보조 설명의 대비를 확인한다.

## 원본 이미지와 동영상

- 공식 제품 페이지·문서·저장소·공식 채널에서 실제 기능을 보여주는 원본을 고른다. 로고나 분위기 사진보다 조작 화면, 편집 전후, 실제 결과물이 낫다.
- 원본 화면은 내용을 먼저 확인한다. 구버전 화면이면 버전과 설명 범위를 캡션에 밝히고, 최신 기능의 시연으로 둔갑시키지 않는다. AI 생성 이미지는 제품의 실제 화면이나 성능 증거로 사용하지 않는다.
- 이미지 내용은 원본을 유지한다. 도식과 주석이 필요하면 원본과 분리한다. 캡션에 제공자·원문 링크·자료 성격을 적는다. 출처 표기가 자유 이용 허락을 뜻하지는 않는다.
- 사용 권한과 도구 정책이 허용하는 경우 원본을 `assets/news/`에 저장한다. 다운로드·임베드가 제한되면 우회하지 말고 공식 페이지의 해당 데모 링크로 대체하고 한계를 알린다.
- 동영상은 공식 임베드가 가능할 때 제목과 반응형 비율을 갖춰 넣고 자동 재생하지 않는다. 임베드가 불가능하면 공식 재생 페이지로 연결한다. 실제 재생을 확인하지 못했다면 재생 확인을 완료했다고 쓰지 않는다.
- `<img>`에는 내용 중심 `alt`, 원본 비율을 반영한 `width`·`height`를 넣는다. 큰 원본을 확인할 링크를 제공하고 화면을 과도하게 잘라 기능을 숨기지 않는다.
- 비교 슬라이더는 키보드 조작, 읽을 수 있는 라벨·상태, 안정적인 크기를 제공한다. JS가 없거나 인쇄할 때도 양쪽 이미지를 볼 수 있게 한다. 반복 사용하는 검증된 코드를 먼저 살펴본다.

저장한 미디어마다 `assets/news/<slug>-media.md` 또는 기존의 적절한 출처 기록에 다음을 남긴다.

| 기록 | 내용 |
| --- | --- |
| 파일·원본 | 로컬 경로, 공식 소개 페이지, 원본 파일 또는 공식 영상 URL |
| 제공자·확인일 | 원작자·기관, 실제 확인 날짜 |
| 용도·상태 | 무엇을 보여주는지, 버전, 데모·직접 캡처 여부 |
| 가공·이용 조건 | 크기·변경 여부, 확인한 이용 조건 또는 미확인 상태 |

조사 노트와 미디어 기록도 공개될 수 있다. 인증 토큰, 로그인 전용 URL, 내부 경로·실제 고객 자료를 남기지 않는다.
