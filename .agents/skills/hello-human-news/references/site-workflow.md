# 저장소 반영과 검증

사이트에 일반뉴스를 추가하거나 수정할 때 읽는다. 이 문서와 `README.md`의 구조 설명이 실제 코드와 다르면 현재 코드의 목록·컴포넌트 구조를 따른다. `README.md`의 공개 범위와 편집 원칙은 계속 지킨다. 이 문서의 경로는 프로젝트 루트 기준이다.

## 살펴볼 파일

| 경로 | 확인 목적 |
| --- | --- |
| `README.md` | 공개 범위, 문체, 발행·자산·갱신 표시 규칙 |
| `news/index.html` | 일반뉴스 번호·편수, 전체 순서, 목록 링크 |
| `index.html`의 `#ai-news` | 일반뉴스 카드와 별도의 속보·단신 띠 |
| 가장 최근 일반뉴스 HTML | 메타데이터·헤더·목차·본문·스크립트 구조 |
| `assets/news.css`, `assets/style.css` | 공통 디자인과 테마 변수 |
| `assets/news-index.js` | 단일 목록의 필터·날짜 정렬·편수 계산 |
| `assets/content-updates.js`, `assets/content-update-state.js` | 변경 감지 시점과 `New`/`Updated` 판정 |

`news/2026-10-03-durable-ai-workflows.html`은 원본 이미지·복구 도식·편집 전후 비교·업무와 개발자 계획 분리의 참고 사례다. `assets/news-workflows.js`에는 비교 슬라이더 예시가 있다. 이 파일들의 과거 수치·제품·날짜·호수는 새 기사의 근거가 아니며 그대로 복제하지 않는다.

## 새 기사 추가

1. 현재 일반뉴스의 최대 `ISSUE` 번호를 확인하고 다음 번호를 쓴다. `BRIEF` 번호는 별도이며 전체 편수로 호수를 정하지 않는다. 사용자 지정 발행일이 없으면 사용자의 현재 날짜를 기준으로 하고 실제 조사일은 별도로 명시한다.
2. `news/YYYY-MM-DD-slug.html`을 만들고 제목, 설명 메타, H1, 부제, 날짜, 호수, 목차와 본문 `id`를 맞춘다. 기본 골격은 기존 일반뉴스를 따르되 이전 주제의 본문·수치·이미지·자산 참조를 남기지 않는다.
3. `<meta name="robots" content="noindex, nofollow, noarchive">`를 유지한다. `theme.js`는 공통 CSS 앞에 두고, 공통 내비게이션·`article-toc.js`·분석·콘텐츠 갱신 스크립트는 현재 페이지의 실제 버전과 순서를 따른다.
4. 기사 전용 시각화는 필요한 만큼 `assets/news-<slug>.css`와 JS에 분리하고 페이지 범위로 제한한다. 공통 스타일 변경이 필요하면 영향 범위를 검토하고 해당 자산을 불러오는 페이지들의 `?v=`도 갱신한다. 외부 의존성과 빌드 도구를 불필요하게 추가하지 않는다.
5. `news/index.html`의 `#news-feed .news-issues`에 `<li data-news-kind="regular-news">`로 한 번만 등록한다. 날짜 내림차순, 같은 날짜는 속보·단신 먼저라는 현재 순서를 유지한다. 필터별로 글을 복제하지 않는다.
6. 정적 HTML의 `[data-news-total]`과 `[data-news-count]`도 실제 목록 수에 맞춘다. 새 일반뉴스이면 전체·일반뉴스 수가 늘고 속보·단신 수는 그대로다. JS가 계산하더라도 JS 없는 화면의 숫자까지 맞춘다.
7. 새 글이 날짜상 최신 일반뉴스라면 홈 `#ai-news .news-home-feature`의 링크·제목·설명·날짜·호수를 함께 갱신한다. `.news-home-flash`의 속보·단신은 건드리지 않는다. 다른 섹션의 같은 클래스도 수정하지 않는다.
8. 조사 노트·미디어 출처를 저장하고 `README.md`의 파일 목록에는 실제로 새로 추가한 주요 파일을 반영한다.

GitHub Pages의 프로젝트 경로 아래에서도 링크가 동작하도록 기존 상대 경로 방식을 따른다. 루트 절대 URL이나 로컬 PC 경로를 공개 HTML의 자산 경로로 넣지 않는다.

## 기존 기사 수정

- 원래 호수·발행일·URL과 목록 편수는 유지한다. 최신 확인 날짜가 필요한 수정이면 본문이나 조사 기록에 갱신 기준을 명시한다.
- 수정한 사실이 요약, 제목, 도식, 접근성 라벨, 출처, 목록·홈 소개에도 있으면 함께 맞춘다. 관련 없는 섹션과 디자인은 유지한다.
- 기존 그래프의 근거와 역할을 검토한 뒤 위치·표현을 고친다. 삭제가 필요한 경우에는 잘못된 근거나 대체 표현을 분명히 한다.
- 같은 파일명의 이미지를 바꾸면 HTML 이미지 URL에 버전을 붙여 내용 변경이 감지되게 한다.
- 인터랙션이 본문을 바꾸면 현재 패턴처럼 `DOMContentLoaded`에서 초기화한다. 페이지 로드 중 기준 스냅샷보다 먼저 바뀌어 `Updated`가 반복 표시되는 일을 방지한다.

## 검증

변경 범위에 맞게 수행하고, 실행하지 못한 항목은 마지막에 밝힌다.

- `node --test`와 `git diff --check`를 실행한다. 새로 추가하거나 수정한 JS는 `node --check <파일>`로 구문을 확인한다. 기존 테스트 통과를 기사 사실 검증이나 브라우저 확인의 대체로 쓰지 않는다.
- 기사·목록·홈의 제목·번호·날짜·링크 일치, 중복 없는 `id`, 목차 대상, 상대 링크·이미지 경로의 존재, 필터별 편수를 확인한다.
- 사용할 수 있는 브라우저 도구의 지침을 읽고 기존 미리보기부터 찾는다. 정적 파일로 확인 가능하면 별도 서버를 만들지 않는다. 모듈이나 `fetch` 때문에 HTTP가 필요하면 저장소의 서버 방식을 쓰고, 없다면 승인된 로컬 정적 서버를 loopback에 한정해 실행한다. 포트 충돌은 다른 포트로 피하고 `.git`·`.agents` 등 비공개 개발 파일을 노출하지 않는다.
- 데스크톱과 좁은 모바일 화면에서 스크린샷을 확인한다. 가로 넘침, 한글 줄바꿈, 표·도식 겹침, 라이트·다크 대비, 목차와 탭 이동, 원본 이미지 로딩을 점검한다.
- 인터랙션이 있으면 키보드·터치, 최소·중간·최대 상태, JS 없는 대체 화면을 확인한다. 변경한 경우 인쇄 화면과 동영상 재생도 확인한다.
- 일반뉴스·속보 필터를 오가도 글이 중복되지 않는지, 글 열기 → 인터랙션 조작 → 목록 복귀 → 새로고침에서 `Updated`가 잘못 다시 붙지 않는지 확인한다.
- 최종 diff에서 요청과 관련 없는 수정, 이전 기사의 잔재, 비밀값·실제 사내 정보가 없는지 확인한다.

검토용 로컬 결과물과 미리보기 링크를 전달하고 멈춘다. 사용자가 명시적으로 요청한 경우에만 커밋하며, 푸시·배포는 별도 요청을 확인한다.
