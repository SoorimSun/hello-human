# 심화 실습 · 인분별 재료량 계산기

## 목표

입문에서 만든 헬로우 키친의 갈비찜 페이지에 1~6인분을 입력하면 일곱 재료의 양이 바뀌는 기능을 추가합니다. Wayfinder와 Superpowers를 사용해 결정 이유가 설계·구현·검증으로 이어지는 개발 과정을 경험합니다.

## 이번 학습의 진행 방식

- 입문 공개 저장소를 복제한 hello-kitchen-process 폴더의 codex/servings-calculator 브랜치에서 진행합니다.
- Wayfinder로 고정 조건과 미결정 질문을 구분합니다. 입력 즉시 갱신과 적용 버튼을 비교하고, 이유와 범위 밖 기능을 기록합니다.
- 작은 작업이라 결정 지도가 불필요하면 그 이유와 결정 요약을 docs/decisions.md에 남깁니다. 지도가 생겼다면 실제 경로를 요약에 연결합니다.
- Superpowers brainstorming으로 동작 설계를 만들고, 사용자가 확인한 뒤 writing-plans로 구현 계획을 만듭니다.
- 학습을 위해 설계와 계획을 짧은 로컬 문서로 남깁니다. 실제 생성 경로를 알려주고 구현 전에 사용자의 검토를 받습니다.
- 승인된 계획은 executing-plans로 현재 채팅에서 순서대로 구현하며 test-driven-development의 실패 확인 → 최소 구현 → 통과 확인을 따릅니다.
- 전체 변경에 대한 리뷰를 확인합니다. 이미 리뷰를 마쳤다면 결과를 재사용하고, 새 변경이나 미확인 문제에 필요한 검토만 합니다.
- 최종 자동 테스트와 화면 점검은 verification-before-completion으로 실제 결과를 확인합니다.
- 작업 위치·로컬 커밋 허용 범위는 사용자의 명시 요청을 따릅니다. 이 자료만으로 커밋·push·병합·공개 배포를 허용한 것으로 해석하지 않습니다.
- Wayfinder 트래커와 학습 문서는 로컬 파일로 유지합니다. GitHub 이슈는 만들지 않습니다.

## 고정 조건

- 기준 자료는 recipe.md의 2인분 재료입니다.
- 소갈비 600g, 무 200g, 당근 100g, 간장 60mL, 설탕 20g, 다진 마늘 15g, 참기름 5mL입니다.
- 계산식은 기준량 × 요청 인분 ÷ 2입니다.
- 입력은 1~6의 정수만 허용합니다. 기본값은 2입니다.
- 빈 값, 0, 음수, 7 이상, 소수, 숫자가 아닌 입력은 유효하지 않습니다.
- 잘못 입력하면 이유를 표시하고, 재료량은 마지막으로 확인된 유효한 값으로 유지합니다.
- 처음부터 입력이 잘못되면 기본값인 2인분 재료량을 유지합니다.
- 합의한 적용 방식으로 유효한 값을 적용하면 오류가 사라지고 재료량이 다시 계산됩니다.
- 초기화 버튼을 누르면 입력·재료량이 2인분으로 돌아가고 오류가 사라집니다.
- 변경 때마다 원래 2인분 자료에서 계산합니다. 직전 화면의 값을 다시 곱하지 않습니다.
- 소수는 필요할 때 최대 한 자리로 표시합니다. 7.5는 7.5, 15는 15로 표시합니다.
- 새로고침하면 2인분으로 돌아옵니다. 로컬 저장소나 서버에는 값을 저장하지 않습니다.
- 재료의 단위를 유지합니다. 갈비를 데치거나 조리는 시간·조리 온도·물의 양은 계산하지 않습니다.
- 칼로리·영양·의학적 정보는 생성하지 않습니다.

## 설계할 때 정할 내용

- 숫자 입력과 적용 버튼을 둘지, 입력 즉시 갱신할지 결정하고 이유를 적습니다.
- 가이드의 후속 예시는 적용 버튼 또는 Enter로 갱신합니다. 이 방식을 고르면 입력 중에는 마지막 결과를 유지하고, 적용할 때 검증·오류 해제·수량 갱신을 수행합니다.
- 마지막 유효 인분과 현재 입력 문자열을 어떻게 구분할지 설명합니다.
- 입력 검증·계산·숫자 표시·화면 갱신의 역할을 구분합니다.
- 입력의 접근 가능한 이름, 오류 안내와 결과 알림, 키보드 조작을 설계합니다.

## 파일과 도구

- 공개 파일: index.html, servings.mjs, 비어 있는 .nojekyll
- servings.mjs는 실제 페이지와 Node.js 테스트가 함께 사용하는 계산·검증 모듈입니다.
- 로컬 파일: tests/servings.test.mjs, tools/serve.mjs, docs/의 결정·설계·계획·리뷰·확인 기록, 설치한 .agents/skills/ 등 스킬 자료
- Node.js LTS와 내장 node:test를 사용합니다. 테스트 명령은 node --test입니다.
- tools/serve.mjs는 Node.js 내장 기능만 써서 실습 폴더의 정적 파일을 127.0.0.1:4173에서 제공합니다.
- 계산기에는 외부 npm 패키지, 빌드 도구, 서버 데이터 저장 기능을 추가하지 않습니다. 학습 도구인 스킬 설치는 별도 준비 작업입니다.
- ES 모듈은 파일 더블클릭 대신 로컬 HTTP 주소에서 확인합니다.

## 검증

- 자동 테스트: 1·2·3·6인분, 잘못된 입력, 기준 데이터 불변, 2→6→1→2 반복 변경에 필요한 계산 결과
- 브라우저 확인: 수량·단위, 잘못된 입력과 복구, 초기화, 새로고침, 키보드만으로 조작, 폭 390px 화면
- 자동 계산 테스트와 실제 화면 점검을 따로 기록합니다.
- 오류가 있으면 재현 조건을 적고 원인을 확인한 뒤 수정합니다.
- 통과했다고 보고하기 전에 실제 명령과 브라우저 결과를 확인합니다.

## 남길 학습 기록

- docs/decisions.md: 선택·이유·범위 밖 기능·결정 지도 경로(있는 경우)
- 설계 문서: 입력과 상태, 오류 처리, 파일별 역할, 접근성, 완료 기준
- 구현 계획: 작업별 변경 파일·기대 동작·실패시킬 테스트·검증 명령
- 진행 기록: 실제 실행 명령·실패 이유·통과 결과·설계나 계획이 바뀐 이유
- docs/review.md: 리뷰 지적, 재현 여부, 수정·보류·해당 없음의 이유
- docs/verification.md: 자동 테스트·직접 화면 점검·미확인 항목, 결정과 검증 항목의 연결

Superpowers 문서와 진행 기록의 위치는 설치 버전·설정에 따라 달라질 수 있습니다. 실제 생성된 경로를 안내합니다. 실행하거나 확인하지 않은 결과를 성공으로 기록하지 않습니다.

## 배포

계산기 구현 요청만으로 배포하지 않습니다. 별도 공개 요청 후 index.html, servings.mjs, .nojekyll만 기존 GitHub 저장소 루트에 올립니다. 공개 주소에서도 수량 변경과 새로고침을 확인합니다.
