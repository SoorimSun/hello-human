# 내 업무 실험 기록지

헬로우 휴먼 AI Guide 10 · 2026. 10. 23

이 기록지는 전종홍의 『지능을 전기처럼 쓰는 시대: AI 네이티브 핸드북 2026』의 관점을 업무에 적용하도록 헬로우 휴먼이 별도로 만든 실습 양식입니다. 원문의 양식이나 저자의 실증 사례가 아닙니다. 상품과 규칙은 가상이며 실제 상품 사양이나 모델 성능 기록이 아닙니다. 회사에서 허용한 도구와 자료로만 사용하고, 기록은 허용된 위치에 보관하세요.

개념의 바탕: 원문은 AI가 만드는 가치와 개선 과정, 업무 전체의 결과와 비용, 사람이 검증하고 책임지는 습관을 강조합니다. 이 기록지의 업무 카드·연습 사례·평가표는 그 관점을 연습하기 위한 헬로우 휴먼의 구성입니다. [원문 바로 읽기](https://drive.google.com/file/d/1Kve5XiR8kMN260Uc0BW6eeoQi4cJzptA/view).

처음에는 가이드 본문의 상품 검수 한 건만 따라 해보세요. 이 기록지는 그다음에 내 업무를 정하거나 여러 사례를 비교할 때 사용합니다. 모든 칸을 한 번에 채울 필요는 없습니다. MD 파일은 메모장 같은 텍스트 편집기로도 열 수 있습니다.

## 2. 상품 검수 추가 연습 5건

1. `product-check.txt`를 메모장이나 편집기에서 엽니다.
2. `[공급사 명세서]`부터 `[내부 검수 기준]` 바로 앞까지를 지우고, 아래 사례 하나의 코드 블록 내용으로 바꿉니다. 앞쪽 요청문과 뒤쪽 내부 검수 기준은 유지합니다.
3. 완성한 전체 텍스트를 AI의 새 대화에 붙여 넣고 전송합니다. 사례 제목과 아래 기대 결과는 함께 넣지 않습니다.
4. AI의 결과를 아래 기대 결과와 비교해 3절의 평가표에 기록합니다.

각 사례는 별도의 새 대화에서 실행합니다. A~C로 요청문을 다듬고 D~E는 수정 과정에 쓰지 않은 확인 사례로 남겨 볼 수 있습니다. 기대 결과는 실행 전에 담당자가 확인하되 AI에 입력하지 않습니다.

연습 5건은 운영 품질을 입증하는 표본이 아닙니다. 중요한 오류가 발견되면 요청문만 고치지 말고 자료와 업무 기준도 함께 점검하세요.

### 기대 결과 · AI 입력에서 제외

| 사례 | 기대 판정 | 잘못된 판정의 예 |
| --- | --- | --- |
| A | 제공 자료와 실습 규칙 범위에서 발견한 문제 없음. 최종 승인은 사람에게 남김 | 판매 구성 2개를 임의로 1개로 수정 |
| B | 용량 불일치 한 문제로 묶고, 상품명·속성 두 곳의 수정안 제시 | 상품명만 고치거나 용량 오류를 두 문제로 중복 계산 |
| C | 세척 방법 확인 필요. 공급사에 문의 | 일반적인 텀블러 세척법으로 빈칸 채우기 |
| D | 24시간 주장 증빙 요청 또는 문구 보류 | 증빙이 없다는 이유로 보온 불가라고 단정 |
| E | 명세서끼리 충돌하므로 기준 문서 확인 요청. 용량 수정과 게시 보류 | B가 뒤에 나왔다는 이유로 최신판이라고 판단 |

B·C·E는 성능 주장이 없으므로, 보온 자료가 없다는 사실만으로 실습 규칙 위반으로 세지 않습니다. 보온 성능 자체를 필수 항목으로 정한 실제 업무라면 해당 규칙을 먼저 추가해야 합니다.

## 3. 실행과 평가 기록

### 실행 조건

- 도구와 모델:
- 모델 설정(알 수 있는 범위):
- 요청문 버전:
- 입력 자료 버전:
- 실행 날짜:
- 평가 담당자:
- 용도: 요청문 개선 / 별도 확인

| 사례·실행 번호 | 기대 결과 | 실제 결과 | 놓친 오류 | 잘못된 지적 | 근거 오류·정보 날조 | 사람의 수정 | 완료 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

완료 상태는 완료 / 보류 / 수정 후 완료로 적습니다. 여기서 완료는 ‘정한 기준에 맞는 검수표 작성 완료’이며 상품 게시 완료가 아닙니다. 자료 부족을 정확히 짚고 확인 질문으로 남겼다면 검수표는 완료일 수 있지만, 상품 게시 여부는 사람이 별도로 결정합니다.

평가 항목을 하나의 점수로 합쳐 중요한 오류를 가리지 마세요. 같은 사례를 반복 실행했다면 각각 기록해 흔들림을 확인합니다. 예를 들어 세척법을 지어낸 답을 고쳤다면 ‘실제 결과: 임의 세척법 제안 / 사람의 수정: 공급사 확인 요청으로 변경 / 완료 상태: 수정 후 완료’로 남길 수 있습니다.

### 업무 전체의 효과

| 방식 | 업무 종류·난이도 | 준비 | 생성·처리 | 검토 | 수정 | 전체 시간 | 사용료 | 완료 업무 수 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 기존 방식 | | | | | | | | |
| AI 사용 | | | | | | | | |

동일한 완료 기준에서 비교합니다. 재시도와 실패에 든 비용도 합산하고, 같은 업무를 여러 번 시도했더라도 완료 건수는 중복해서 세지 않습니다. 완료가 0건이면 건당 비용을 계산하지 말고 총투입과 실패 원인을 남깁니다. 초기 구축비는 별도로 기록합니다.

## 5. 멤버들과 공유할 짧은 기록

```text
이번에 바꿔 본 업무:
AI에 맡긴 범위와 사람이 결정한 부분:
비교한 사례 수와 완료 기준:
찾아낸 오류 / 놓친 오류 / 잘못된 지적:
전체 업무 시간이 달라진 정도와 비교 조건:
효과가 있었던 요청문 또는 기준:
다음에는 유지하거나 바꿀 점:
```

공유할 때는 회사명, 내부 시스템·URL, 실제 고객정보·로그·코드를 제거하고 가상 예시로 설명하세요. 결과가 좋았던 사례뿐 아니라 보류하거나 중단한 이유도 남기면 다음 멤버에게 도움이 됩니다.
