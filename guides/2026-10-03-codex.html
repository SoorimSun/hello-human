“2인분 레시피로 페이지를 만들어줘.” 이 한 문장에서 시작해, 직접 확인할 수 있는 작은 앱까지 만들어봅니다.

코드 문법을 몰라도 따라갈 수 있습니다. 입문에서는 읽기 좋은 요리 페이지를 만들고 공개합니다. 심화에서는 Wayfinder와 Superpowers로 인분 계산기를 결정·설계·구현·리뷰·검증합니다. 각 단계에는 복사할 요청, 남길 기록, 사람이 확인할 기준이 있습니다.

앱이나 CLI 중 하나로 시작하세요. Claude Code 가이드를 먼저 읽었다면 흐름은 익숙하지만, 지침 파일과 설정 명령은 Codex 방식으로 바뀝니다. 입문은 6장까지, 심화는 7~8장입니다. 9장부터는 필요할 때 찾아보세요.

제품 설명은 2026년 10월 3일 확인한 공식 문서를 기준으로 합니다. 앱 명칭·메뉴·모델은 버전과 계정에 따라 다를 수 있습니다. 요리 자료와 도식은 이 학습을 위해 구성한 예시입니다.

COURSE 01 · 입문레시피 한 장 만들기 →자료 읽기 → 페이지 → 수정 → 공개완료하면 github.io 주소가 남습니다. COURSE 02 · 심화개발 과정 경험하기 →Wayfinder → Superpowers → 인분 계산기결정 이유·변경 내역·검증 기록이 남습니다.

1. Codex가 일할 작업대를 준비합니다

Codex는 요청을 받아 프로젝트 파일을 읽고, 코드를 만들거나 수정하고, 명령을 실행해 결과를 확인하는 도구입니다. “어떻게 만들까요?”라는 대화에서 실제 파일을 다루는 작업으로 이어집니다. 모델은 다음 행동을 판단하고, Codex는 파일과 도구를 연결합니다. 공식 문서 · Codex의 작업 방식 ↗

이번에 만드는 것은 음식을 조리하는 AI가 아니라 레시피를 보여주고 재료량을 계산하는 웹페이지입니다. 입문부터 로그인·사진 생성·영양 분석을 한꺼번에 넣지 않습니다. 작은 결과를 완성한 뒤 기능 하나를 늘립니다.

2. 처음이라면 앱에서 폴더를 여세요

현재 공식 시작 안내는 ChatGPT 데스크톱 앱 안에서 Codex를 선택하는 구조입니다. 기존 버전에서는 Codex 앱으로 보일 수 있습니다. 이 가이드의 “앱”은 로컬 폴더를 열어 Codex로 작업하는 화면을 뜻합니다.

  1. 공식 시작 페이지 ↗에서 내 운영체제용 앱을 설치하고 ChatGPT 계정으로 로그인합니다. macOS·Windows·Linux용 안내가 있습니다.
  2. 탐색기나 Finder에서 빈 hello-kitchen 폴더를 만듭니다. 예를 들어 문서 폴더 안에 두면 찾기 쉽습니다.
  3. 아래 두 파일을 그 폴더에 저장합니다. 이름이 recipe.md.txt처럼 바뀌지 않았는지 파일 확장자도 확인하세요.
  4. 앱에서 폴더를 열거나 프로젝트로 추가한 뒤, Codex → New chat으로 시작합니다. 작업 위치는 내 컴퓨터의 방금 만든 폴더를 고릅니다.
  5. 입력창 아래 권한에서 Ask for approval을 고르고, 첫 요청은 계획부터 확인합니다.
요리 자료 recipe.md ↓ 작업 지침 AGENTS.md ↓

앱을 시작하기 위해 CLI 설치 명령까지 실행할 필요는 없습니다. 입문은 정적 HTML만 만들며, Node.js는 심화의 자동 테스트 단계에서 준비합니다. 앱 설치와 프로젝트의 실행 도구 준비는 서로 다른 일입니다.

계정과 사용량

ChatGPT 로그인과 API 키 이용은 인증·과금 경로가 다릅니다. 현재 플랜에서 Codex 사용이 가능한지, 조직 계정의 허용 범위가 무엇인지 확인하세요. 이 실습은 ChatGPT 로그인을 기준으로 하며 API 키를 만들거나 대화에 붙일 필요가 없습니다. 공식 이용 범위 ↗

3. CLI는 같은 작업을 터미널에서 합니다

앱으로 시작했다면 설치 부분은 건너뛰어도 됩니다. CLI는 글자를 입력하는 터미널에서 Codex를 사용하는 방법입니다. 명령을 재현하거나 반복 작업과 연결할 때 편리합니다.

CLI를 사용할 멤버 · 설치와 첫 실행

공식 CLI 설치 페이지 ↗에서 운영체제 탭을 고릅니다. 아래는 공식 독립 실행형 설치 스크립트를 내려받아 실행하는 명령입니다. 내 운영체제의 명령 하나만 사용하세요.

Windows · PowerShell에 입력 
irm https://chatgpt.com/codex/install.ps1 | iex
macOS / Linux · 터미널에 입력 
curl -fsSL https://chatgpt.com/codex/install.sh | sh

설치 후 터미널을 새로 열고 codex --version으로 확인합니다. 이미 npm이나 Homebrew로 설치했다면 기존 설치 방식의 업데이트 안내를 따르세요. 여러 방식으로 중복 설치할 필요는 없습니다.

탐색기·Finder에서 만든 hello-kitchen 폴더의 실제 경로로 이동합니다. 아래 경로는 예시이므로 내 폴더에 맞게 바꿉니다. cd는 작업 위치를 바꾸는 명령입니다.

터미널 · Windows 경로 예시 
cd "C:\Users\MY_NAME\Documents\hello-kitchen"
codex --sandbox workspace-write --ask-for-approval on-request
터미널 · macOS / Linux 경로 예시 
cd ~/Documents/hello-kitchen
codex --sandbox workspace-write --ask-for-approval on-request

첫 실행에서 Sign in with ChatGPT를 선택하고 브라우저 인증을 마칩니다. 작업 폴더 확인이 나오면 직접 만든 폴더가 맞는지 확인하세요. 화면에 입력창이 나타나면 준비가 된 것입니다.

실행 중인 Codex 입력창 · 현재 상태 확인 
/status

설치 명령·cd·codex는 바깥 터미널에, 자연어 요청·/model·/plan은 실행 중인 Codex에 입력합니다. /quit으로 종료하면 터미널로 돌아옵니다.

4. 권한과 생각의 깊이를 따로 고릅니다

권한은 Ask for approval로 시작하세요

Ask for approval은 현재 작업 공간의 파일 편집과 일반적인 로컬 명령을 허용하고, 네트워크나 작업 공간 밖 접근 등에는 확인을 요청하는 방식입니다. 파일을 고칠 때마다 묻는 설정은 아닙니다. 먼저 계획만 보고 싶으면 /plan과 “지금은 수정하지 마”를 함께 사용하세요.

Approve for me는 추가 권한 요청의 검토를 자동화합니다. 같은 작업 공간 경계를 두더라도 검토 주체가 달라집니다. Full access는 훨씬 넓은 접근을 허용하므로 이번 실습의 출발 설정으로 사용할 이유가 없습니다. 허용 요청이 나오면 대상 폴더와 실행 목적을 읽고 판단합니다. 공식 문서 · 권한 모드 ↗

모델은 사용 가능한 GPT-6.1 Sol, effort는 medium부터

이 가이드의 시작 제안은 GPT-6.1 Sol + medium입니다. 해당 모델이 계정에 없다면 현재 제공되는 기본 모델로 같은 실습을 진행해도 됩니다. 공식 안내도 모델·추론 설정을 같은 작업에서 비교해 고르도록 권합니다. 앱은 모델·추론 메뉴, CLI는 /model에서 선택하세요.

Effort는 모델이 추론에 들이는 노력의 수준입니다. 높이면 복잡한 판단에 도움이 될 수 있지만 시간과 사용량도 늘 수 있습니다. 코드의 정확성이나 테스트 통과를 보장하는 설정은 아닙니다. 제공되는 단계는 모델과 클라이언트에 따라 다르므로, 아래 값이 보이는 경우에 사용하세요.

5. 입문 · 레시피 페이지 한 장을 만듭니다

목표는 2인분 갈비찜을 소개하는 페이지 한 장입니다. 파일은 index.html 하나로 만들고 스타일도 그 안에 넣습니다. 사진이나 외부 서비스를 연결하지 않아도 완성할 수 있습니다.

01 · 자료와 작업 위치 확인

hello-kitchen 폴더 안에 recipe.md와 AGENTS.md가 있어야 합니다. 앱에서 이 폴더를 열거나, CLI에서 이 폴더로 이동해 실행합니다.

Codex 입력창 · 앱·CLI 공통 
현재 작업 폴더와 적용되는 AGENTS.md를 확인해줘.
recipe.md를 읽고, 만들 페이지의 내용과 완료 기준을 짧게 정리해줘.
아직 파일은 수정하지 마.

답변에 2인분, 일곱 가지 재료, 정확한 수량이 나오는지 확인합니다. 다른 폴더가 보이면 다음 단계로 가지 말고 작업 위치를 바로잡으세요.

02 · 계획을 보고 범위 확인

/plan으로 계획 모드를 켠 다음 아래 요청을 보냅니다. 권장 effort는 medium입니다.

recipe.md를 기준으로 헬로우 키친의 갈비찜 페이지를 만들 계획을 세워줘.
입문 실습이라 index.html 한 장에 CSS를 포함할 거야.
외부 패키지·이미지·폰트와 JavaScript 기능은 쓰지 마.
한국어, 모바일에서 읽기 쉬운 화면, 재료 수량·단위 일치를 우선해줘.
자료에 없는 시간·영양 정보는 추가하지 마.
바꿀 파일과 내가 확인할 항목을 알려줘. 아직 구현하지 마.

계획에 데이터베이스·로그인·복잡한 프레임워크가 들어가면 “이번에는 HTML 한 장만”이라고 범위를 줄입니다. 기본 HTML은 웹페이지의 내용, CSS는 모양을 정하는 코드입니다.

03 · 구현하고 실제 파일 열기

계획이 맞으면 화면의 구현 전환 동작을 선택하거나 /plan으로 일반 실행 모드로 돌아온 뒤 보냅니다.

확인한 계획대로 index.html을 만들어줘.
완성한 페이지를 열어 확인할 수 있게 안내해줘.
앱의 Browser 패널을 사용할 수 있으면 거기에서 열어줘.
바뀐 파일과 확인한 내용, 직접 확인하지 못한 내용을 알려줘.
커밋·push·배포는 아직 하지 마.

CLI를 쓴다면 탐색기·Finder에서 index.html을 더블클릭해 브라우저로 엽니다. 앱에서 미리보기가 안 되더라도 같은 방법을 쓸 수 있습니다. 이 단계는 외부 파일을 불러오지 않는 정적 HTML이므로 가능합니다.

04 · 읽고 비교한 뒤, 한 가지만 수정

  • 2인분, 소갈비 600g·무 200g·당근 100g·간장 60mL·설탕 20g·다진 마늘 15g·참기름 5mL가 자료와 같은가?
  • 조리 순서 네 단계가 빠짐없이 보이는가?
  • 브라우저 창을 좁혔을 때 글자가 겹치거나 가로로 넘치지 않는가?
  • 추가하지 말라고 한 기능이나 만들어낸 정보가 들어가지는 않았는가?

effort를 low로 바꿔 작은 수정도 해봅니다.

페이지 상단의 이름을 "헬로우 키친 · 오늘의 한 접시"로 바꿔줘.
요리 이름, 2인분 표시, 재료량과 조리 순서는 그대로 유지해줘.
수정된 부분을 알려줘.

브라우저를 새로고침해 반영을 확인하세요. “완료했다”는 답변과 실제 파일·화면이 일치하는지 보는 습관이 핵심입니다.

입문 제작 완료

자료를 주고, 계획을 읽고, 파일을 만들고, 한 부분을 수정했습니다. 이제 6장에서 다른 멤버도 열 수 있는 주소로 공개합니다.

6. GitHub Pages로 요리 페이지를 공개합니다

이 단계에서는 개인 GitHub의 Public 저장소에 실습 파일을 올립니다. 저장소는 파일과 변경 기록을 보관하는 곳이고, GitHub Pages는 그 파일로 웹사이트를 제공하는 기능입니다. 저장소 주소와 실제 웹사이트 주소는 다릅니다.

심화에서 새로 쓰는 도구와 파일

Node.js 공식 다운로드 ↗에서 현재 LTS를 설치하고 터미널을 새로 엽니다. Node.js는 자동 테스트·로컬 미리보기에, 함께 설치되는 npx는 스킬 설치 명령에 사용합니다. 계산기 자체에는 외부 npm 패키지를 추가하지 않습니다.

터미널 · 설치 확인 
node --version
npx --version
index.html사용자가 보는 화면과 입력 동작
servings.mjs실제 페이지와 테스트가 함께 사용하는 계산·검증 코드
tests/예상 결과와 실제 계산 결과를 비교하는 자동 테스트
tools/ · docs/로컬 미리보기 서버, 계획·설계·확인 기록

.mjs는 JavaScript 모듈 파일입니다. 심화에서는 계산 코드를 분리해 실제 사용되는 로직을 테스트합니다. 브라우저용 외부 패키지나 빌드 과정은 추가하지 않습니다.

공개한 버전을 새 Git 작업 폴더로 가져옵니다

Git은 파일의 변경 기록을 남기는 도구입니다. GitHub 웹에 업로드했다고 내 폴더가 Git 저장소로 바뀌지는 않습니다. Git을 설치 ↗하고 터미널을 새로 연 뒤 git --version을 확인하세요. 이 과정에서는 공개한 입문 버전을 새 폴더에 복제해 출발점을 맞춥니다.

터미널 · 새 폴더를 둘 위치에서 실행, YOUR_USERNAME은 내 GitHub 계정명 
git clone https://github.com/YOUR_USERNAME/hello-kitchen.git hello-kitchen-process
cd hello-kitchen-process
git switch -c codex/servings-calculator

hello-kitchen-process가 이미 있으면 다른 새 폴더 이름을 사용하세요. clone은 공개 저장소를 내 컴퓨터로 복제하고, switch -c는 계산기 변경을 기록할 새 브랜치를 만듭니다. 기존 hello-kitchen에서 recipe.md·AGENTS.md를 복사하고, 내려받은 advanced-brief.md도 새 폴더에 넣습니다.

이제 앱에서는 hello-kitchen-process를 새 프로젝트로 열고, CLI에서는 그 폴더에서 codex를 실행합니다. 아래 심화의 파일·테스트·서버 명령은 모두 이 새 작업 폴더를 기준으로 합니다. clone ↗ · switch ↗

8. 스킬을 따라 개발 과정을 경험합니다

Wayfinder는 Matt Pocock의 스킬로, 목표 앞에 남은 질문과 결정을 정리합니다. Superpowers는 설계·작업 분해·구현·리뷰·검증을 돕는 개발 스킬 모음입니다. 이번에는 두 도구를 이어 쓰며 단계의 결과를 읽고 다음 단계로 넘기는 역할을 연습합니다.

작은 기능으로 긴 과정의 핵심만 배웁니다

Wayfinder는 원래 여러 세션에 걸친 큰 목표를 다룹니다. 이 계산기처럼 범위가 명확하면 큰 결정 지도를 생략할 수도 있습니다. 그 경우에는 선택 이유를 짧게 남기고 넘어갑니다. Superpowers의 문서도 이번 학습에 필요한 분량으로 유지합니다.

준비 · Codex에서 스킬을 설치하고 확인하기

Wayfinder는 아래 명령을 hello-kitchen-process의 터미널에서 실행해 설치합니다. 공식 설치 명령에 Codex·필요 스킬·파일 복사 옵션을 지정한 예시입니다. Wayfinder와 초기 설정, 내부에서 참조하는 스킬을 함께 설치합니다. 외부 설치 도구 실행 안내와 설치 목록을 읽고 진행하며, 이미 설치했다면 중복 설치하지 않습니다.

터미널 · 프로젝트에 필요한 스킬을 설치, 화면에서 줄이 접혀도 한 명령 
npx skills@latest add mattpocock/skills --agent codex --skill wayfinder setup-matt-pocock-skills grilling domain-modeling research prototype --copy

프로젝트 범위가 기본이며 --copy는 스킬 파일을 복사합니다. 설치 화면이 나오면 Codex와 이 프로젝트 범위인지 확인하세요. 설치 도구의 공식 옵션 ↗

Superpowers는 앱의 Plugins → Coding → Superpowers → +로 설치합니다. CLI에서는 실행 중인 Codex에 /plugins를 입력하고 superpowers를 검색해 Install Plugin을 선택합니다. Wayfinder 설치 안내 ↗ · Superpowers의 Codex 설치 안내 ↗

설치 후 새 채팅을 열거나 CLI를 재시작합니다. 입력창에서 $를 입력해 wayfinder·setup-matt-pocock-skills와 Superpowers 스킬이 보이는지 확인하세요. 설치 경로에 따라 이름에 접두사가 붙을 수 있으므로 선택 목록의 실제 이름을 사용합니다. 아래의 자연어 요청에서도 사용할 스킬 이름을 명시합니다.

길게 쓰는 것보다 목표·입력·범위·완료 기준이 드러나는 것이 중요합니다. “예쁘게 고쳐줘”보다 어디가 불편하고 어떤 상태가 되면 좋은지 알려주세요.

목표휴대폰에서 재료량을 쉽게 읽고 싶다.
입력현재 index.html과 recipe.md를 기준으로 한다.
범위재료 목록의 간격·정렬만 바꾼다.
완료 기준390px에서 수량이 읽히고 계산 결과는 유지된다.
화면 수정 요청 · 권장 effort low 
휴대폰에서 재료 이름과 수량의 간격이 너무 넓어.
index.html의 재료 목록 배치만 조정해줘.
390px에서 이름과 수량을 한눈에 읽을 수 있게 해줘.
recipe.md의 내용과 servings.mjs 계산 로직은 바꾸지 마.
수정 전후 차이와 실제 확인한 화면을 알려줘.
오류 전달 · 원인이 어려울 때 effort high 검토 
인분을 2→6→2로 바꾸면 소갈비가 600g으로 돌아오지 않아.
기대 결과는 600g이고, 현재 보이는 값은 [실제 수량]이야.
이 순서로 재현한 뒤 원인을 설명해줘.
직전 화면의 양을 다시 곱하고 있는지 확인해줘.
재발을 잡는 테스트를 추가하고 최소 범위로 수정해줘.
실행 결과와 아직 확인하지 못한 항목을 알려줘.

[실제 수량]은 화면에 보인 값으로 바꾸세요. 에러가 있다면 첫 오류 메시지와 실행한 명령도 함께 줍니다. 원인을 모를 때는 추측으로 여러 파일을 한꺼번에 바꾸기보다 재현부터 요청하는 편이 판단하기 쉽습니다.

12. 대화를 이어가고, 변경을 검토합니다

같은 기능을 고치는 동안은 같은 채팅에서 이어가세요. 목표가 바뀌거나 긴 대화에서 필요한 조건을 놓치기 시작하면 현재 상태를 파일로 남긴 뒤 새 채팅을 시작합니다. 같은 폴더를 열었다고 이전 대화의 모든 맥락이 자동으로 이어지는 것은 아닙니다.

현재 채팅 · 다음 작업 준비 
다음에 이어서 할 수 있게 docs/next-step.md를 작성해줘.
목표, 현재 파일 구성, 합의한 계산 규칙, 실행한 테스트 결과,
남은 문제와 다음 작업 하나, 로컬 미리보기 명령을 적어줘.
지금은 코드를 더 수정하지 마.
새 채팅 · 같은 폴더에서 재개 
AGENTS.md와 docs/next-step.md를 읽고 현재 상태를 확인해줘.
파일이 기록과 일치하는지 살펴보고, 다음 작업 하나부터 이어가자.

앱은 사이드바에서 기존 채팅을 다시 엽니다. CLI는 종료한 뒤 같은 폴더에서 아래 명령으로 선택하거나 최근 대화를 재개할 수 있습니다. /compact는 현재 대화의 컨텍스트를 요약하는 기능이며 파일 변경을 되돌리는 명령은 아닙니다.

터미널 · 이전 CLI 대화 계속

codex resume --last

파일 저장, 커밋, push, 배포는 다른 단계

13. 막힐 때 꺼내 보는 작은 안내서

증상먼저 확인할 것
Codex가 recipe.md를 못 찾는다선택한 작업 폴더와 파일명·확장자를 확인합니다. Cloud가 아닌 내 로컬 폴더인지도 봅니다.
codex 명령을 찾을 수 없다터미널을 새로 열고 설치한 방식을 확인합니다. CLI 설치 명령을 Codex 대화창에 입력한 것은 아닌지도 봅니다.
계획만 나오고 파일이 안 생긴다Plan이 켜졌는지 확인하고 계획을 검토한 후 일반 실행 모드에서 구현을 요청합니다.
메뉴·슬래시 명령이 다르다앱과 CLI를 구분합니다. 현재 입력창에서 /로 가능한 명령을 확인합니다.
테스트가 안 돈다node --version, 현재 폴더, tests/servings.test.mjs 존재를 확인합니다. “테스트 0개”는 기능 검증 성공이 아닙니다.
심화 계산 버튼이 동작하지 않는다파일 더블클릭 대신 로컬 HTTP 주소인지, 모듈 파일과 연결 경로가 맞는지 확인하고 브라우저 오류를 전달합니다.
4173 포트가 이미 사용 중이다이미 실행 중인 실습 서버를 확인합니다. 다른 프로그램을 임의 종료하지 말고 Codex에게 사용할 포트와 안내 주소를 함께 바꾸도록 요청합니다.
Pages가 404 또는 이전 화면이다브랜치·루트·파일명 index.html, Actions 배포 결과, github.io 주소를 확인합니다. 심화는 servings.mjs도 올려야 합니다.
Wayfinder·Superpowers가 보이지 않는다Codex에 설치했는지, 현재 프로젝트가 hello-kitchen-process인지 확인합니다. 새 채팅·세션의 $ 목록에서 실제 이름을 고릅니다. Superpowers는 Plugins의 활성 상태도 봅니다.
스킬이 문서 없이 바로 구현하려 한다학습을 위해 결정 요약·설계·계획을 파일로 남기고 확인한 뒤 구현하겠다고 다시 지정합니다. 작은 작업에는 문서를 줄이는 스킬도 있습니다.
로컬 커밋에서 작성자 오류가 난다Git의 이름·이메일 설정을 확인합니다. 본인이 사용할 값을 프로젝트에 설정한 뒤 다시 시도합니다. 로컬 커밋만 허용한 상태에서 push까지 요청하지 않습니다.
사용량 한도가 걸렸다앱 사용량 표시 또는 /status를 확인합니다. 계정 플랜·모델에 따른 한도와 재개 시점을 확인합니다.
