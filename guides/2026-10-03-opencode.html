새 모델이 나왔습니다. 설명은 근사한데, 내가 맡길 일도 잘할까요?

OpenCode는 한 작업 환경에서 여러 제공사의 모델을 연결해 쓸 수 있는 코딩 에이전트입니다. 이번에는 가상의 야간 아트 페스티벌 페이지를 같은 조건으로 만들어봅니다. 큰 글자와 빛나는 그래픽을 어떻게 배치하는지, 버튼은 정말 작동하는지, 작은 수정이 기존 화면을 망가뜨리지 않는지 확인합니다.

완성물은 모델별 HTML, 첫 결과와 수정본, 비교 기록입니다. 무료 모델 하나로 먼저 끝내고, 궁금한 새 모델이나 로컬 모델을 같은 과제에 투입하세요. 특정 모델의 우승을 미리 정해 둔 실험은 아닙니다.

FIRST RUN무료 모델로 한 번 완성하기 →설치 → 모델 선택 → 제작 → 화면 확인 MODEL LAB이미 쓰고 있다면 비교부터 →같은 입력 → 새 폴더 → 두 라운드 → 기록

1. OpenCode는 작업대, 모델은 교체할 수 있습니다

OpenCode는 프로젝트를 읽고, 파일을 편집하고, 명령을 실행하는 환경을 제공합니다. 모델이 다음 행동과 코드를 판단하고, 제공사(provider)가 그 모델을 실행하는 API를 제공합니다. 로컬 서버도 제공사처럼 연결할 수 있습니다. 터미널·데스크톱·IDE에서 쓸 수 있으며, 이 글은 명령과 선택 과정을 맞추기 쉬운 터미널 화면(TUI)을 기준으로 합니다. OpenCode 소개 ↗

PRICE무료 모델

현재 이용 요금이 무료인 모델입니다. 제공 기간·사용 한도·데이터 이용 조건은 따로 봅니다.

IDENTITY스텔스 모델

정체나 세부 정보가 공개되지 않은 상태로 제공되는 모델입니다. 익명 별칭을 그대로 기록합니다.

MODEL FAMILY중국계 모델

Qwen·DeepSeek·GLM·Kimi·MiniMax 등도 비교 대상입니다. 개발사와 실제 API 제공 경로를 함께 봅니다.

WHERE IT RUNS로컬 모델

내 컴퓨터의 추론 서버에서 실행합니다. 모델 크기뿐 아니라 메모리·양자화·컨텍스트도 결과에 영향을 줍니다.

네 가지는 서로 겹칠 수 있습니다. 무료 스텔스 모델도 있고, 중국에서 개발한 공개 가중치 모델을 로컬에서 실행할 수도 있습니다. 스텔스라는 이름 자체가 보안이나 데이터 비수집을 뜻하지는 않습니다.

2. 설치하고 작업할 폴더를 엽니다

Windows는 PowerShell, macOS는 터미널을 엽니다. 아래는 공식 문서에 있는 npm 설치 경로입니다. node나 npm이 없다면 Node.js LTS를 설치한 뒤 터미널을 새로 여세요.

터미널에 입력 · 설치와 버전 확인 
node --version
npm --version
npm install -g opencode-ai
opencode --version

이미 설치되어 있다면 버전을 기록하고 다음 단계로 갑니다. 공식 문서는 Windows에서 WSL을 권장하며, Windows 자체의 npm 설치도 안내합니다. 이 실습은 PowerShell로 시작할 수 있습니다. WSL을 쓰면 로컬 추론 서버도 같은 환경에 두는 편이 연결을 이해하기 쉽습니다. 공식 설치 안내 ↗ · Windows·WSL ↗

macOS에서 Homebrew를 사용한다면

npm 설치와 아래 방법 중 하나만 선택하면 됩니다.

brew install anomalyco/tap/opencode
opencode --version

기존 프로젝트 바깥에 새 실험 폴더를 만듭니다. 아래 이름이 이미 있다면 다른 이름을 쓰세요.

터미널에 입력 · 첫 모델의 작업 폴더

opencode 실행 뒤에는 대화 화면이 열립니다. 설치 명령은 터미널에, /models 같은 명령은 OpenCode 입력창에 입력합니다. 폴더 이름이나 위치가 맞는지도 확인하세요.

어떤 권한으로 작업하는지 읽어보세요

Plan은 계획을 검토할 때, Build는 파일 작업을 진행할 때 사용합니다. 기본 키 설정에서는 Tab으로 전환합니다. 실제 편집·명령 실행 허용 범위는 권한 설정에 따라 달라집니다. 이번 실습은 새 폴더에서 index.html을 만드는 Build 작업입니다. 에이전트 ↗ · 권한 ↗

3. 무료 모델 하나로 시작합니다

OpenCode 도구 사용료와 연결한 모델의 이용료는 구분합니다. 현재 내장 무료 모델은 API 키를 등록하지 않아도 목록에 로드되는 경로가 있습니다. 처음부터 카드 등록이나 유료 구독을 할 필요는 없습니다. 아래 명령으로 실제 내 환경의 목록을 확인하세요. 공식 소스 · 무료 모델 로딩 ↗

무료 모델의 조건도 모델별로 다릅니다

Zen은 Big Pickle의 무료 기간 데이터가 모델 개선에 쓰일 수 있다고 안내합니다. Space Bunny에는 다른 데이터 정책이 명시되어 있습니다. 이 실습처럼 가상의 공개용 자료로 시작하고, 실제 이용 조건은 선택한 모델의 최신 안내에서 확인하세요. Zen 데이터 정책 ↗

인증이나 유료 모델을 선택했다는 안내가 나오면 현재 제공사·모델·요금을 다시 확인합니다. 외부 API를 연결할 때의 /connect는 9장에서 다룹니다.

4. 모델마다 같은 출발선을 준비합니다

비교를 시작할 때는 같은 자료, 같은 작업 지침, 결과 HTML이 없는 폴더, 새 세션을 맞춥니다. 아래 두 파일을 내려받아 첫 작업 폴더인 run-a에 넣으세요. 기록지는 작업 폴더 밖에서 사람이 작성합니다.

공통 요구사항 brief.md ↓ 공통 작업 지침 AGENTS.md ↓ 비교 기록지 scorecard.md ↓

AGENTS.md는 OpenCode가 읽는 프로젝트 작업 지침입니다. 일반 프로젝트에서는 /init으로 만들 수 있지만, 여기서는 같은 파일을 복사해 사용합니다. 모델마다 새로 생성하면 비교 조건이 바뀝니다. 개인·상위 폴더의 지침과 전역 플러그인도 영향을 줄 수 있으니 동일한 환경을 유지하세요. 작업 지침과 적용 범위 ↗

OpenCode 입력창 · 자료를 넣은 뒤 새 대화 시작 
/new

/new는 대화를 새로 시작할 뿐, 만든 파일을 지우거나 되돌리지 않습니다. 다른 모델은 run-b처럼 새 폴더에서 실행해야 이전 결과를 이어 고치는 일이 생기지 않습니다. TUI 세션 명령 ↗

5. 첫 과제는 눈길을 끄는 HTML 한 장입니다

주제는 NEON ATLAS 야간 아트 페스티벌입니다. 밤의 전시 포스터처럼 과감하게 구성하되, 행사 정보와 프로그램을 읽고 고를 수 있어야 합니다. 이미지를 잘 고르는 능력에 결과가 좌우되지 않도록 외부 리소스 없이 CSS·인라인 SVG로 시각 요소를 만들게 합니다.

첫 결과가 나올 때까지 디자인 힌트를 추가하지 않습니다. 선택을 되묻는다면 “자료에 있는 범위 안에서 스스로 정해서 진행해줘”라고 동일하게 답하고 기록합니다. 비교를 위한 이번 과제는 Build로 바로 실행하며, 계획 대화를 먼저 나눈 결과는 별도 실험으로 남깁니다.

6. 완성 보고를 읽고, 브라우저에서 직접 확인합니다

파일 탐색기나 Finder에서 run-a/index.html을 브라우저로 엽니다. 첫 결과를 고치기 전에 HTML을 작업 폴더 바깥에 run-a-round-1.html로 복사하고, 데스크톱·모바일 화면을 캡처해 둡니다.

  1. 첫 화면에서 행사 이름·일시·장소가 읽히는지 봅니다. 그래픽이 멋져도 글씨가 묻히면 기록합니다.
  2. 프로그램 보기를 눌러 일정으로 이동합니다. 전체는 6개, 빛·소리·퍼포먼스는 각각 2개인지 확인합니다.
  3. 전체 필터로 돌아온 뒤 빛의 문과 잔향 수집을 담습니다. 관심 개수는 2여야 합니다.
  4. 빛 필터로 바꿉니다. 빛 프로그램 2개가 보이고 전체 관심 개수는 계속 2여야 합니다.
  5. 비우기를 누릅니다. 관심은 0, 빛 필터와 빛 프로그램 2개는 유지되어야 합니다.
  6. 새로고침합니다. 전체 프로그램 6개, 관심 0개로 시작해야 합니다.
  7. 1440px와 390px에서 확인합니다. 브라우저 개발자 도구의 기기 화면으로 너비를 맞추고, 가로 잘림·겹침·버튼 크기를 봅니다.
  8. Tab과 Enter·Space로 조작합니다. 포커스가 보이고 필터·담기가 작동하는지 확인합니다.
  9. 동작 줄이기를 켜고 새로고침합니다. OS의 접근성 설정을 이용해 장식 애니메이션이 줄거나 멈추는지 확인합니다.

첫 결과가 실패해도 그대로 기록합니다. 인증·한도·서버 연결 문제로 모델이 실행되지 않았다면 미실행으로 구분합니다. “디자인이 약했다”와 “API에 연결되지 않았다”는 다른 관찰입니다.

7. 한 번 더 요청해 수정 능력을 봅니다

이번에는 같은 모델·같은 세션에서 작은 정보 수정과 상태가 얽히는 기능 추가를 요청합니다. 각 모델은 자신이 만든 첫 결과를 고칩니다. 화면을 예쁘게 만드는 능력과 기존 구성을 유지하면서 정확히 바꾸는 능력을 함께 볼 수 있습니다.

ROUND 2시간 변경과 관심 필터를 추가합니다

OpenCode에 입력 · 모든 모델에 같은 수정 요청 
현재 index.html에서 아래 두 가지를 수정해줘.

1. '빛의 정원' 시작 시간을 19:00에서 19:30으로 바꿔줘.

8. 모델을 바꾸고, 결과를 나란히 봅니다

첫 실험을 마쳤다면 새 터미널에서 opencode-lab 폴더로 이동해 run-b를 만듭니다. 원본 brief.md와 AGENTS.md만 복사하고 OpenCode를 실행합니다. /models에서 다음 모델을 선택한 뒤 5~7장을 그대로 반복합니다.

같은 대화에서 모델만 바꾸면 무엇이 달라질까요?

이전 대화와 파일을 이어받는 협업 실험이 됩니다. 처음부터 만드는 능력을 비교하려면 폴더와 세션을 함께 새로 준비하세요. Round 2는 각 모델의 첫 결과에 이어서 진행하므로, 그 모델이 자기 작업을 수정하는 능력을 봅니다.

시작 전에 맞추고 기록할 조건

  • 환경은 같은 OpenCode 버전·Build 에이전트·지침·도구·권한·브라우저 크기로 맞춥니다. 추가 스킬이나 브라우저 도구를 한 모델에만 붙이지 않습니다.
  • 제공사와 정확한 모델 ID, 실행 날짜, variant·추론 옵션을 적습니다. 같은 “high”라는 이름이 모델마다 같은 계산량을 뜻하지는 않습니다.
  • 요청 횟수와 시간 한도를 미리 정합니다. 예를 들어 각 라운드 공통 요청 1회, 최대 15분으로 정했다면 모두에게 동일하게 적용합니다. 중단한 결과도 남깁니다.
  • 소요 시간은 요청 전송부터 파일 작업과 마지막 보고가 끝날 때까지 잽니다. 설치·모델 다운로드·서버 로딩 시간은 따로 기록합니다.
  • 비용·토큰은 표시되거나 확인 가능한 값만 씁니다. 모르면 미확인으로 남깁니다. 로컬 속도에는 내 장비와 양자화 설정도 함께 적습니다.

OpenCode 모델 ID는 provider/model 형태입니다. variants는 모델별 옵션 묶음이며 지원 여부가 다릅니다. 기본값으로 시작하되 실제 선택값을 기록하고, 추론량을 높여 재시도한 결과는 별도 회차로 남기세요. 모델 ID와 variants ↗

0·1·2점과 관찰 한 문장으로 남깁니다

0은 미충족, 1은 일부 충족, 2는 대체로 충족입니다. 점수 옆에 실제 화면이나 재현 가능한 동작을 한 문장 적습니다. 가능하면 모델 이름을 가린 화면을 먼저 비교하세요.

결과가 흥미롭다면 같은 모델을 새 폴더에서 2~3회 반복해 편차를 봅니다. 가장 예쁜 한 장만 골라 비교하지 않습니다. 작은 HTML 과제로는 대규모 코드 이해, 서버 개발, 긴 작업의 안정성까지 판단할 수 없습니다.

“어느 모델이 최고?”보다 구체적인 기록이 남습니다

“A는 첫 화면이 좋았고, B는 두 필터의 교집합을 정확히 처리했다. C는 내 노트북에서 느렸지만 수정 범위를 잘 지켰다.” 이런 관찰이면 다음에 무엇을 맡길지 고르는 데 도움이 됩니다. 이 문장은 기록 방식의 예시이며 실측 결과가 아닙니다.

다른 주제로 확장하고 싶다면 회원의 모델별 웹 제작 실험도 참고하세요. 주제와 조건이 바뀌면 결과도 달라질 수 있습니다.

10. 로컬 모델은 서버부터 준비합니다

로컬 모델은 추론 서버가 먼저 모델을 실행하고, OpenCode가 그 서버에 요청하는 구조입니다. 다운로드할 수 있는 모델이라도 내 메모리에 맞는지, 도구 호출을 지원하는지, 긴 입력을 처리할 수 있는지 확인해야 합니다. 대화 답변과 파일 편집 도구를 쓰는 작업은 요구 조건이 다릅니다.

LM Studio로 연결하기

  1. LM Studio에서 내 장비에 맞고 도구 사용을 지원하는 모델을 내려받아 로드합니다. 다운로드와 로딩을 먼저 마칩니다.
  2. Developer → Start server로 로컬 서버를 켭니다. 서버 주소와 제공하는 정확한 모델 ID를 확인합니다. 기본 예시 주소는 http://127.0.0.1:1234/v1입니다.
  3. 아래 예제 파일을 실험 폴더의 opencode.json으로 저장합니다. 기존 설정이 있다면 덮어쓰기 전에 내용을 확인합니다.
  4. MODEL_ID_FROM_SERVER 세 곳을 실제 서버 모델 ID로 바꿉니다. 표시 이름과 API ID가 다를 수 있습니다. limit.context와 limit.output도 서버에 실제 설정한 값과 모델의 지원 한도에 맞춥니다.
  5. 그 폴더에서 OpenCode를 새로 실행하고 /models에서 로컬 모델을 확인합니다. 이어서 같은 HTML 과제를 실행합니다.

11. 막힌 지점을 구분하면 다시 시도하기 쉽습니다

상황먼저 확인할 것
opencode를 찾지 못함설치 결과와 새 터미널, PATH를 확인합니다. npm 설치 명령을 OpenCode 대화창에 넣지 않았는지도 봅니다.
무료·스텔스 모델이 목록에 없음현재 버전과 공식 제공 목록을 확인합니다. 제공 종료·접근 제한일 수 있으므로 가능한 다른 무료 모델을 고릅니다.
401·403 오류선택한 제공사와 키, 계정 접근 권한을 확인합니다. 지역·상품별 endpoint도 확인합니다.
429·한도 오류요금제·쿼터·재시도 안내를 확인합니다. 코드 생성 품질 점수와 분리해 기록합니다.
말만 하고 파일을 만들지 않음Build 표시, 편집 권한, 현재 폴더, 모델의 도구 호출 지원을 확인합니다. 대화의 코드 블록을 결과 파일로 간주하지 않습니다.
로컬 서버 연결 거부서버가 켜져 있는지, 주소·포트와 실제 모델 ID가 맞는지 확인합니다. WSL과 Windows의 localhost는 같은 환경이라고 가정하지 않습니다.
도구 호출 오류·출력 중단모델과 서버의 도구 호출 형식, 실제 컨텍스트·출력 한도, 메모리 부족 여부를 봅니다.
모델을 바꿨는데 이전 화면을 계속 고침새 폴더에 이전 index.html을 복사하지 않았는지 확인합니다. /new만으로 파일은 초기화되지 않습니다.
페이지는 예쁜데 버튼이 안 됨처음 상태·누른 순서·기대 결과·실제 결과를 기록합니다. 공통 비교를 마친 뒤 별도의 수정 요청으로 해결합니다.
